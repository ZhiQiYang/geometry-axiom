# 測試可信度審查 — 2026-09-28

## 結論與範圍

本輪將測試本身當成被審查對象，對照使用者已核准的公理、工程規格、空間建模、平面投影與框選第一版需求。檢查本次新增／修改測試及共同執行器，另查核沿用的原生場景、閱讀器、見證與原型測試能證明的範圍。

確認存在假通過風險，也有版本文字過期造成的假失敗。不是只重新跑原測試：以 TEMP 壞版本、錯誤回覆或故障注入比較舊測試與新測試。正常控制組必須通過，故障組必須被需求對應的斷言拒絕。環境失敗不當成抓到產品 bug。

先前「1027 通過」是舊執行器記錄的混合層級判定，不能解讀成 1027 個完整使用流程。已證實它的文字計數機制可能受日誌符號污染，但沒有找到該次紀錄實際被灌數的證據，也不能說 1027 全是假的。新的 runner 明列範圍、略過、環境失敗與斷言結果。最終瀏覽器回歸結果另列於下方，不沿用舊數字。

## 需求對照與證據分類

- 工程規格：固定材料／做法版本、來源、面與物件覆寫、指定面升級、整批拒絕、單步復原、實際保存重開；不把原型 62 個純函式測試當成正式畫布證據。
- 空間：圖面 z=2500 與牆底／牆高分開；高度 3000、厚度 100 向外；孔洞／凹形位置、底面共面的角材及來源快照。材料厚度型錄不等於已建面材實體。
- 框選：此輪稽核當時的第一版文件規則為兩方向「完全包含」，不是 SketchUp 方向交叉選取。測試符合當時規則，但不能拿第一版綠燈當作「向右完整包含、向左相交也選取」的證據。使用者隨後明示要求實作，由 GEO-212 另行修改行為及測試；現行規則與新增證據見 [畫布選取](CANVAS-SELECTION.md)，下方原稽核數據保留歷史範圍。
- 閱讀器：24 個同步／內容／結構測試是資料證據，不能代替真瀏覽器批註操作、手機觸控或視覺可讀性。
- Windows GDI：真資源 API 加故障注入；極小版面以模擬 client 呼叫函式，並非真視窗互動驗收。
- 正式保存流程測下載與檔案輸入；原生 Windows 另存視窗、真手機多指觸控仍未實測。

## GEO-212 接續驗證：短暫提示及非同步載入

方向框選的完整回歸另找到三類測試問題：P38 的自動回報可能晚於原六秒期限，且規則拒絕負例落在自動回報的二十秒節流期間；工程入口以非 inert 誤認載入完成，讀到前次批次選取；多處 toast 在等待畫面穩定後才讀取，等待最長五秒，卻超過成功／錯誤提示的二秒／三點六秒生命。任意 `.toast.ok` 或最後一則文字也可能誤用舊提示而假通過。

對應修補：先在無節流影響時觀察規則拒絕，再等待故意注入的自動回報完整寫入；工程入口等待實際「已讀取目前工程」狀態，之後立即核對精確目標；短暫提示只接受本次操作新加入、在動畫幀中實際可見的 DOM，版面案例於同幀記錄位置。保留原幾何、欄位、拒絕及復原斷言，不修改產品的提示時效或載入行為。執行範圍、失敗輪次與最終結果見 [方向框選驗證](CANVAS-SELECTION.md)。

另修正 P8 的需求錯配：點擊畫布座標不代表角材以該座標放置，定位來自明確的面邊引用。舊測試把右下角點擊稱為越界，且任意非空提示即可通過；現改明確重試已占用的 e0 定位，要求本次「占滿」錯誤與世界完全不變，不再聲稱它驗證足跡越界。
