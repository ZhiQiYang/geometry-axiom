本文件對應 issue #461 R4，取代 issue #43 設計留言 7169458157 的 E1 敘述；基底為 `b3c4b981bb96b118c1c05b7a1bd98062d710c8b2`。行為依 `公理層.md` D51a–c、I63a–c、R58a–b、D63；本文件沒有新增或改寫條文。v1 尚未套用，不提供把 v1 未發布 schema 當成正式舊格式的隱式相容。

機讀 oracle 是 `tests/oracles/r13_e1_contract.json`。`decimalCases`、`derivationBasisCases`、`stateCases`、`hostRows`、`uiRows` 的預期在測試前明列，由數值、保存、UI 與空間入口的測試讀取並逐值核對，不從產品輸出或測量結果學回 expected。`r13_height_oracle.py` 另以 Fraction 建構、檢查及掃描有限關係；它不匯入 JS 產品。

中性十進位與三純量有限關係位於 `geometry-core/reconstruction-values.js`；房間欄位、來源、版本及核對規則仍在 H 層 `geometry-web/reconstruction-data.js`。瀏覽器沿現有 `runtime_version.application_assets` 精確路由 `/kernel/reconstruction-values.js` 載入，不擴張任意路徑服務。移除所有宿主與模板後，原架構裁判仍可只從 `geometry-core` 掃描全部 K 來源；不得以修改該斷言容納放錯位置的核心檔案。

## 範圍與普通入口

E1 只提供 `room-height` 與人工來源。四欄固定為 bottom、top、height、wallThickness；欄位、來源、確認、推導、收據的未知鍵一律拒絕。沒有 RC 模板、圖頁／證據引用、任意公式、批量房間選取、座標框架轉換或新幾何 producer。

入口是面內「底圖」的「來源與補資料」群組。一般面原有「來源紀錄與待補資訊」仍可編輯；D13 共用房間原有「原頁歷史紀錄與核對」仍唯讀。兩者都由 `app.js::feUnderlayPaneHTML` 與 `feBindUnderlayPane` 的共同外層接 R13 編輯器，不把 D13 原頁紀錄改成可寫，也不需要另改 `room-collection-workspace.js`。

紀錄是**專案全域清單**，不因從哪個面進入而自動加上面、房間或圖頁關聯。D51a 的關聯可省略；E1 明確省略。換面不篩掉紀錄、不改紀錄 bytes、不宣稱物件延續。帶入 3D 時另外明選紀錄與當下已定位的承載面；這是本次候選的選取，不是可跨刪除重建沿用的持續身分證明。刪面不刪人工原始紀錄；目前沒有合法面時不能形成採用候選。模型仍保存建立當時的來源快照。

## 輸入文法、單位與精確值

| 項目 | E1 明確行為 |
|---|---|
| 新欄位 | `raw=""`、`unit=null`、`confirmation=null`；位置 basis=unknown，距離 basis=distance。 |
| 可保存的原文 | 空白、未完成小數、全形、備註等均保留原字串；不 trim、不轉全形、不填零、不補單位。仍受 Unicode scalar 與 byte 容量限制。 |
| 可確認的文法 | ASCII 十進位：可有一個前置 `+`／`-`、可有前導零；接受 `.1`、`-.1`、`+00012.0`；小數點後必有數字。 |
| 文法拒絕 | `1.`、單獨符號、前後空白、換行、全形數字、Unicode 負號、指數、分數、千分位、十六進位及算式都不得確認。這不限制 D31 原本的正式算式。 |
| 單位 | 必須使用者明選 mm 或 cm；mm 乘 1、cm 精確乘 10。未知單位的 raw 可以保存，不能確認或採用。 |
| 精確值 | canonical 值為整數 mm，絕對值不超過 100000000。不得浮點容差、截斷或捨入。`250.1 cm=2501 mm`；`250.01 cm` 必拒絕。 |
| 正負與零 | 底高、頂高允許零與負；高度、牆厚須嚴格大於零。`-0` 的精確值是 0，原字串仍是 `-0`。 |

## 確認、位置基準與有限推導

確認與幾何採用是兩個階段。直接確認記錄原字串、單位、basis、人工來源及當下版本，證明它們對應該精確觀察值。位置 basis 尚為 unknown 時，可以先確認這個觀察值；這不證明它是 World Z，因此仍不得採用或參與位置推導。

明選 `world-z` 是本片的位置基準宣告。`note` 供保存補充說明，可空白；程式不判斷文字是否「可辨識」，也不因填了「完成地坪」而自行產生座標轉換。改 basis 或 note 都取消該欄有效確認及相依推導，須重新核對。E1 不提供其他框架轉換。

房間有限關係只有 `bottom + height = top`。另外兩欄必須是目前有效的**直接**確認，唯一目標的 raw 必須恰為空字串，不覆寫已有輸入、不串接推導。三種方向的基準需求為：

| 唯一缺欄 | 計算 | 必須明選 World Z 的欄位 |
|---|---|---|
| bottom | top − height | top 與目標 bottom |
| height | top − bottom | top 與 bottom |
| top | bottom ＋ height | bottom 與目標 top |

推導目標也須先明選 mm／cm，結果仍以整數 mm 保存。候選可顯示，但另按「確認推導」才新增確認。輸入版本、兩個直接確認、唯一目標、精確值與完整依據皆重驗。三個已填、可比較的值相矛盾時，保留原值、列出欄位／人工來源／關係與精確差額，阻擋相關採用；不自選真值。未知基準的頂高不能拿來與 World Z 相減，它須明列為待複核資料。

RC 樑的 `樑底 + 樑深 = 樑頂` 同樣是 D51c 已採納關係，排入 E3；E1 的房間子集不能被寫成 C／D 全案只有一條關係。

## 原字串何時記錄、保存與組字

| 事件 | 原字串、歷史與資格 |
|---|---|
| 成功且有變化的 input／change | 在既有專案歷史記一筆變更，同步完整原文；受改欄位及紀錄取得新修訂，相關確認失效。名稱變更可記歷史，但不推進核對輸入修訂。 |
| 同值事件或 save flush | no-op，不新增歷史或耗號。若 DOM 比已保存紀錄新且漏了最後 input event，保存前 flush 先記這筆實際變化。 |
| IME 組字中保存 | 同步目前 DOM 的未完成原字串；保持原輸入控制與組字狀態，不等待、不改成組字前文字；不觸發確認或採用。 |
| 組字結束 | 同步最後原文；只有實際內容變化才新增歷史。確認與採用仍須另按。 |
| flush／容量／owner 驗證失敗 | 該次保存明示未完成，保留可見未保存文字；不以舊值寫檔後稱成功。復原資料保持先前 bytes，恢復狀態標 unavailable 並說明原因。 |
| 選檔等待期間又改字 | 保存 stamp／owner 不再相符，該次保存拒絕，原文保留。 |
| 關閉／換頁 | 已記錄 raw 留在專案；未成功同步的編輯原文留在原 context。只用明示重新讀取捨棄未保存文字。 |

每個成功輸入事件一筆歷史是本片明確的工程選擇，沿用既有 32 步歷史上限，不擴大、不另外建立文字歷史。長字串逐鍵輸入可能淘汰較舊步驟；不能因此丟失目前紀錄。Node 測試只驗合成 composition 與 DOM seams，實體輸入法仍待真機。

## 身分、水位、刪除與保存範圍

紀錄使用專案內 `rd-N` 身分及單調修訂水位，不是 World id 或 D59 記號。失敗、取消與 no-op 不耗號；同 context 復原內容會回到當時版本，但水位不倒退。新增 A→undo 到零筆→新增 B，不得重用 A 的身分或修訂。

第一次建立前的舊專案不製造本附件、不升格式。使用後即使 undo／delete 到零筆，仍保留已使用水位的空附件，因此以 `/21` 保存。新 context 從讀入檔案水位初始化，不繼承另一專案水位。

刪除紀錄與所有既有 review 中該紀錄的 `missing=true` 在同一步歷史完成，模型原件不改。已觀察的 missing 不因同號／同內容出現而自行消失；整步 undo 可還原刪除前狀態。刪除模型則同一步刪除其 review。

`.gcanvas`、方案快照與既有恢復資料保留附件；場景、dump、D25 交換及 D55 定義匯入不因此攜帶它。附件不含執行期 context、history frame 或操作 token。完整開啟先在隔離候選重驗數學、型別、資料水位、容量、模型來源／完整輸入／完整結果及確認 pins，再發布。

## 明選範圍、供值與部分建模

E1 一次明選**恰一筆完整的四欄房間紀錄**，不另提供欄位範圍縮小器。bottom、height 是 plan 必要供值；選用牆厚只在有直接有效確認時供 `wall_thickness`，空白保持 null、不建立材料牆。top 不存在對應的 plan input slot，只記 `purpose=human-review`，不把它冒稱供值。

| 房間紀錄狀態 | 是否可準備候選／核對狀態 |
|---|---|
| bottom 或 height 未確認、位置基準未知 | 不可準備。原文可保存；不從畫布位置、圖面 z 或手動草稿補值。 |
| 有填寫但非法的尺寸／已知矛盾 | 不可準備。保留原文，須明示修正或撤回。 |
| 牆厚有填卻未確認 | 不可準備；不能偷偷排除已填牆厚。 |
| bottom、height 有效；top 空／未確認／基準未知，或 wall 空 | `defined-subset`，逐欄列 missing-value 或 needs-review 及細節；須明選「只建立已定資料」才能預覽與建立。 |
| 四欄全有效、位置可比較且關係成立 | `selected-scope-reviewed`；只證明這一筆明選範圍，不證明全圖、未選 RC 或施工完整。 |

選用牆厚不是所有 plan 的必要輸入；但在本片的四欄資料範圍中，空欄仍是缺值，不能因未供材料牆便把資料紀錄冒稱全部核對。頂高僅供人工核對時也不得聲稱數值直接進入模型。

進 D07 時底面與頂面初始均「尚未指定」。使用者必須分別明選邊界／計算封口／不建立；無論是否有高度都不自設用途。孔洞、邊、投影用途及朝向仍走既有核對。缺值不借獨立手動 D07 的 3000／100 或其他手動草稿；手動入口保留原義。

供值欄在 R13 模式唯讀；要改數值須回原紀錄修改與確認，或離開本模式改走手動建模。這是防止表單改值後仍宣稱採用舊確認的介面選擇，不宣稱公理強制所有表單都唯讀。只有高度、沒有底高基準的資料不能建立 plan，但仍可保存並繼續二維編輯。

模型沿既有 `space_modeling.py` producer、model-base 驗證及完整 replay 形成；`/model/space-preview` 是宿主 HTTP 模型端點，不是 World 的原生歷史交易。預覽、prepare 與 commit 都核 owner／版本／完整輸入；部分建立的明選在提交前也再次檢查。取消、容量失敗、過期或驗證失敗均零模型／review／歷史寫入。

模型與 review 同一候選、同一步 `changeModels`。所有新增、改設定、F1b 整筆更新及刪除 writer 都通過該收口；已帶 review 的變更若不能保留原核對，須在本次操作明選解除。hash 必先算完及驗證，不能先寫模型再補附件。review 的 completeness、uses、checks、omitted 都依確認快照重算，不能靠改 hash、刪 omitted 或把 top 偽稱 setting 取得資格。

## 封閉格式與容量

新增宿主能力與附件 `reconstruction-data/1`，使用 `geometry-canvas/21`。原 `/1`–`/20` 能力清單逐值保留，只加唯一新尾項；未知格式負控改為 `/22`，凍結 b3 讀取器仍拒絕 `/21`。兩個依格式判斷原文定位的 K1／R06 突變同步保留原撤回意義。新能力不是原生 scene 能力。

| I63c 容量 | E1 範圍與驗證 |
|---|---|
| 紀錄 256 筆、每筆 16 KiB | 專屬有界 admission；第 257 筆或任何單筆超限拒絕。 |
| raw 64 Unicode scalar；basis note 256 scalar | 補充平面字元算一個，孤立 surrogate 拒絕；不使用 UTF-16 `.length` 代替。 |
| 名稱 96 UTF-8 bytes | 24 個四 byte 字元可用，25 個拒絕。 |
| 每尺寸欄最多 8 個來源引用 | E1 只人工來源，外部引用數為零；未宣告已完成 E2 引用能力。 |
| 64 review、每模型一份、每份 64 KiB | 模型 id 不重複、完整 pins 重算；缺模型或模型與用途不符拒絕開啟。 |
| scope 1–256 筆、無重複 | E1 採恰一筆的有限子集；未知／重複／額外 scope 拒絕。 |
| 整份 1 MiB 與專案總容量 | 以保存 UTF-8 JSON bytes 驗；其他附件仍保留原 128 KiB／節點／陣列限制，不共用放寬。 |
| 缺失標記預留 | 每筆 scope 建立時已有 boolean missing；false 的 JSON bytes 多於 true，改為 true 無需增容。 |

工作包 D 的 D2 尚未分配 `.gcanvas` 號碼，不能據其自有 `geometry-source-reassociation/1` 推定它也取得 `/21`。本片先明示 `/21` 僅為 reconstruction 的格式層；若另一片先落地，須按新 main 做具名格式遷移、精確清單聯集與相容負控，不讓兩份不同 policy 共用同一版本號。共享檔交集為 C 的 reference-workspace/project-store、F 的 space-workspace，以及 D 後續的 model writer／保存政策；不能聲稱任意套用順序零衝突。

## 後續切片與驗證交接

E2 才接外部來源。main 的 R10 現況只收 PDF、目標必填且限 parameter-field／boundary／timber、觀測只有 drawing-label／field-measurement；沒有獨立版本欄位或 estimate。原設計稱可直接沿用圖片／估測／版本不正確。要增加這些形狀或新目標，是封閉格式的另片擴充，必須寫清 schema、版本與負控，不能靠 R13 本片偷放寬。

E3 補 RC 柱／樑模板、兩組有限關係、明選既有正式來源與 D5 槽高的當次取值；複製觀察不是建立新活引用。沿原 D13/D14 的奇數寬、軸、歸屬與完整幾何驗證；不能用 L 形外接盒代替足跡。需求帳 R19 的柱投影與公理 R19 不同，投影規則在 R7–R9；游離柱不一定投到 D5 成員面，沒有投影不證明沒有柱。

E4 才擴大多筆核對與部分重建；待補 RC 不能當零尺寸或當不存在。既有 COMPLETE／EMPTY／INCOMPLETE 不改，必要包 INVALID／UNSUPPORTED 不能改稱部分成功；數值角色不混加。E2–E4 等首片套用結果再交。

本片的四個 Node 套件各有直接命令、先紅位置及具名撤回。`P4313` 覆兩種底圖普通入口與 390／1400 寬；新增的獨立 space harness 群組驗真正 D07 路徑，保留全部舊群組的順序及計數。上述瀏覽器程式碼在本環境只能靜態與 Node 契約檢查，真 Chromium、實體 IME、OS 選檔器與正式 CI 都待雲端，不以此文聲稱產品 L4。
