日期：2026-09-27。原型本輪驗收結果見 `../prototypes/engineering-spec/design-qa.md`。

狀態（2026-09-28 核對）：**早期選定第 2 張「畫布內套用」後，使用者於 2026-09-27 改選第 1 張「畫布旁直接編輯面材」。工程規格公理擴充已於 2026-09-28 經使用者核准，正式 Canvas 已有工作區、核心來源與保存串接；整體驗收及最後補驗仍分開記錄。** 本文件保留規劃與原型沿革；正式採納範圍以 `geometry-core/ENGINEERING-SPEC-PROPOSAL.md` 及 SSOT 為準，不能把原型操作等同正式核心驗收。正式操作見 [ENGINEERING-SPEC-USE.md](ENGINEERING-SPEC-USE.md)，測試結果及未驗項見 [PROJECT-AUDIT-20260928.md](PROJECT-AUDIT-20260928.md)。原型 `AGENTS.md`／`design-qa.md` 只作選稿與原型驗證依據。

正式入口是 Canvas 的「檔案 → 工程規格 · 面材與角材」，或已放置面的「構件 → 網格 → 套用工程規格」；視窗標示「工程規格版 2026.09.28」。啟動位址依 [正式應用 README](../README.md)。`http://127.0.0.1:8810/` 仍是獨立原型，不是正式工程入口。

使用者確認的工作預設為 **915 × 1830 × 6 mm（寬 × 長 × 厚）**，常用替代尺寸為 **910 × 1820 mm**，厚度另有 **9 mm** 選項；尺寸均可自訂。天花幾乎使用 6 mm、牆面約 95% 使用 6 mm、約 15% 案件使用 910 × 1820 mm，是使用者實務經驗，不能當作獨立的台灣市場統計。型錄與規格資料不構成施工組合或承載驗證。

## 1. 要解決的問題

讓面材、構件與網格使用可追溯的規格來源。使用者建立一份工程做法後，可在選定的面套用；更換材料或配置時，先看到完整影響，再決定是否更新。

三個資料層級：

| 層級 | 保存什麼 | 例子 |
|---|---|---|
| 材料規格 | 穩定 ID、不可變版本、類型、名稱、型號、材料資料、具單位的尺寸、來源備註 | 面材的長／寬／厚、角材 A／B 截面 |
| 工程做法 | 引用哪些材料版本、各角色的材料預設、排板及支撐配置參數 | 「木作天花 A」引用面材、邊界材、主支與副支規格 |
| 面的套用設定 | 引用做法版本、目標面、軸向對應、起算點、欄位覆寫及既有物件的綁定 | 「客廳天花」沿用做法，局部覆寫縫寬 |

材料尺寸、排板位置、支撐配置、實際構件分別建模。材料規格的版本固定不等於幾何固定；幾何仍由專案內定義及引用推導。

## 2. 已有能力與擴充邊界

正式應用現在已有：具名整數 mm 規格、參考線引用面材尺寸／縫寬／角材截面、面材排法主網格、單格子網格、構件角色及優先級、影響預覽、專案保存與復原重做。

本輪新增正式材料版本、工程做法、網格／角材尺寸來源、本面及物件覆寫、整包候選預覽與確認，以及 `.gcanvas/5`／正式做法包。核心協定見 `geometry-core/ENGINEERING-SPEC-API.md`；原型的瀏覽器資料與 JSON 不自動移入正式工程。原型獨有的廠商快速帶入、自訂型錄欄位仍不是正式工程能力。

依據：公理 D1、D6a／D6b、D7、D9、D10／D10a、D15／D17、D19、I8／I8a、I10、I23／I25，以及 2026-09-28 經逐條差異核准採納的 D26–D28／I34–I36／R31。原有直接数值定義仍合法，工程來源擴充依 `ENGINEERING-SPEC-PROPOSAL.md` 的核准紀錄實作與驗收。

## 3. 分階段功能範圍

### 第一階段：完成面材與角材的規格引用及套用

| 編號 | 功能 | 必須做到 |
|---|---|---|
| F01 | 材料規格庫 | 建立、搜尋、複製、編輯草稿、發布版本、封存；第一階段提供面材與角材兩種可套用類型 |
| F02 | 具型別的欄位 | 長度使用 mm；等分數為無單位整數；方向為列舉。不可混用、不可把幾何不支援的小數尺寸靜默取整 |
| F03 | 工程做法編輯 | 選用面材及各角色角材版本，設定縫寬、板材長寬對應面軸與主支方向預設；起排方式由面套用明設；來源明確的支撐限制作為備註 |
| F04 | 尺寸保持引用 | 主格 panel／gap、角材 A／B 保存來源欄位引用；展開數值是唯讀結果。截面引用與構件角色分離 |
| F05 | 選面套用 | 套用到目前面或明確勾選的多個面；批次選取具名目標，逐面確認方向與起算點；不把「全工程」當成暗中擴大的作用範圍 |
| F06 | 處理既有內容 | 區分建立新主格、更新既有主格、綁定指定既有角材，以及無既有套用／来源時僅提供後續新建預設；已有套用時明示更新做法會重算原引用；既有角材預設不自動綁定、不換角色 |
| F07 | 來源與局部覆寫 | 每個可覆寫欄位顯示來源及目前生效值；「改成本面設定」產生有身分的覆寫；可「恢復沿用」並預覽影響 |
| F08 | 完整影響預覽 | 顯示選定面及引用鏈另外影響的物件、變更前後數值／格線／截面、保留覆寫、阻擋原因與定位入口 |
| F09 | 整批套用與復原 | 所有目標及依賴通過才一次提交；任何阻擋整批保留原狀；一次復原／重做對應整批交易；過期預覽必須重算 |
| F10 | 版本升級 | 已發布版本不可改寫；另存新版本後，選擇要升級的使用位置；原有局部覆寫預設保留，外部新版不自動改專案 |
| F11 | 保存與跨專案攜帶 | .gcanvas 內含全部已發布材料／做法版本（含未套用）、必要依賴、套用與來源；未發布草稿另存。離線重開不需外部規格庫。可匯入／匯出做法包，檢查同 ID／版本異內容衝突 |
| F12 | 引用保護與舊專案相容 | 使用中版本可封存、不可使引用懸空；舊的純數值來源標為「既有直接輸入」，經明確操作才轉成規格引用 |

面材厚度第一階段作為規格資料記錄，可記錄正小數，不參與現行二維網格座標。面材長寬用於排板網格，尚不因此生成面材實體或裁切清單。

依本次核准 D27，支撐限制只作帶來源的備註，可記錄中心距／淨距、適用構件及規則來源。**本期沒有支撐間距幾何檢核，不作力學合格聲明，不自動尋找等分數，不批次放置骨架。** 早期規劃曾描述「配置間距／尚無可檢核支撐」與幾何檢核介面，這部分未进入本次核准資料結構及 API，不能當作本輪已實作功能；若後續納入，需另訂可機器判讀的規則及驗收。

### 第二階段：擴充構件類型與配置效率

- RC 柱、RC 樑等現有構件類型加入對應規格欄位及引用套用；截面與深度可參數化，但位置、高程及跨距仍遵守各自定義，不能共用一個「尺寸」欄位代替。
- 明確選取父格後的多格子網格配置，及依間距限制計算等分策略；需另定不整除、容量與既有子格的處理。
- 在面與格線配置已確認後，另設「生成構件」操作，依角色次序、實際擋面及碰撞限制產生候選；不可把格線存在當成構件已存在。
- 面材實例、裁切清單、用量及扣孔計算，依另行定案的面材物件規則擴充。

相位／交丁、巢狀子格、採購價格／庫存、雲端協作與結構承載計算不納入這次第一階段。

## 4. 第一階段已核准的行為（2026-09-28）

1. **身分與版本**：材料及工程做法採穩定 ID＋版本＋內容指紋；名稱只供辨識。同名不同 ID 可並存，同 ID／版本異內容拒絕匯入。
2. **有效值順序**：明示的物件覆寫 → 明示的面覆寫 → 已套用工程做法的指定版本 → 做法引用的材料版本。沒有來源即顯示未設定，不使用隱藏的全域預設。
3. **覆寫的範圍**：第一階段只開放已明定的尺寸及排板欄位；構件角色維持明示宣告及現有規則，不由材料切換追改。
4. **起算點**：介面可選面邊作為建立時起點，但第一階段沿用 D10a：套用當下具體化；之後改輪廓不自行重新置中或重排索引。若要持續跟隨邊界，另案修改條文。
5. **子格保護**：有子格時，父主格增減線數仍阻擋；同線數變更亦須檢查格子範圍與整數等分。不可暗中刪子格、改等分數、重綁附近格子。
6. **容量**：16 組主／子網格及每軸 64 條線仍以完整 World 檢查；批次目標各自合法也不能繞過總量限制。
7. **角材**：材料只提供截面與選材資料；長度仍從實際環境推導。套用工程做法不覆寫既有角色，後續放材的預設仍接受 D17 等檢查。
8. **數值精度**：參與現行幾何的尺寸限整數 mm。面材厚度作為規格資料可保存正小數，其他型錄資料可記錄小數描述；都不得混同有效幾何值或因此宣稱小數幾何可套用。輸入不支援的幾何尺寸時明確指出。
9. **更新範圍**：升級材料先形成新的工程做法版本，再明確選擇升級使用位置。預覽若發現選取範圍外的依賴，一併列出並納入整批確認。
10. **舊場景**：讀取舊場景結果不變；新的工程引用須定義版本化的核心保存協定，不能只在 UI 加來源文字、背後仍存散落數字。

## 5. 主要使用流程

### A. 建立一套做法

工程規格 → 新增材料規格 → 輸入名稱、類型及尺寸 → 儲存材料版本 → 建立工程做法 → 指定面材／邊界材／主支／副支 → 設定排板規則及新建預設 → 檢查缺漏 → 發布做法版本。

### B. 套用到面

目前面「工程規格」入口，或工程規格工作區「套用至面」→ 選做法版本 → 勾選目標面 → 逐面確認軸向、起點及既有物件處理 → 預覽變更 → 全部通過後套用 → 畫布及檢查器顯示來源。

### C. 更換材料

建立新材料版本 → 做法編輯器選用新版 → 發布新做法版本 → 查看哪些面仍使用舊版 → 選擇升級位置 → 保留局部覆寫 → 顯示新舊差異與子格／角材影響 → 確認整批更新。

### D. 衝突修正

預覽列出核心實際回傳的阻擋原因 → 有結構化物件 ID 時點選定位；核心未提供單一問題物件位置時，只提供清楚命名的「查看本次目標面」入口 → 返回設定修改或明確移除目標面 → 重新預覽。不得從自由錯誤文字猜物件 ID，也不可提供自動忽略錯誤的套用動作。定位補驗狀態見第 2.1 節。

## 6. 必須設計的畫面與狀態

| 畫面 | 主動作 | 必要狀態 |
|---|---|---|
| 材料規格清單與編輯 | 發布材料版本 | 空清單、草稿缺值、有效版本、已封存、使用中、尺寸不支援 |
| 工程做法編輯 | 儲存／發布做法版本 | 材料未選、來源版本已固定、規則未設定；既有版本可查看，也能從編輯入口另存新版本 |
| 面的規格設定 | 預覽套用 | 未套用、沿用來源、本面覆寫、既有直接輸入、混合選取 |
| 套用目標與方向 | 檢查變更 | 單面／多面、既有主格、既有角材是否明確綁定、缺少前置條件 |
| 影響預覽 | 套用至 N 個面 | 通過、阻擋、範圍外依賴、預覽過期、處理中、無變更 |
| 版本更新與引用位置 | 預覽升級 | 有新版、仍用舊版、保留覆寫、來源衝突、封存但可解析 |

介面用語：使用者入口稱「工程規格」，內容中的可重用組合稱「工程做法」；材料選擇與做法選擇分開。來源文字例：「沿用 木作天花 A · v1」「本面覆寫」「恢復沿用」。

## 7. 三種介面探索方向

三稿使用相同功能範圍及既有視覺系統，變化集中於操作結構。它們是替代方向，不是三套同時實作的產品。

- **規格工作台**：以工程做法編輯為主，材料引用呈現為清楚的表格列，旁邊保留小型排板預覽及目標摘要。適合先建立可跨面重用的完整做法。
- **畫布內套用**：延續現有面內工作區，右欄選做法與處理覆寫，畫布維持最大可見範圍。適合邊看幾何邊調整一個面。
- **步驟式確認**：將選做法、選面／方向、預覽確認串成清楚步驟；主要畫面聚焦差異與阻擋處理。適合第一次使用及批次套用。

桌機探索稿以 **1440×1024** 為目標；字級以 14–16 px 為基準。延續白色面板、淺灰畫布、藍紫主動作、青綠面輪廓。主支／副支線型延續既有圖例，衝突除顏色外必須有文字。

手機 390×844 使用單欄設定與可返回的畫布預覽；長表單不擠成三欄。主動作固定於底部、內容可捲動且不被遮住；觸控目標至少 44 px。材料庫與版本資訊為獨立全頁，保留返回位置。

三張初步稿聚焦各方向的主要畫面；選定方向後再完成上述所有狀態與手機稿，才進入互動原型與公理修訂審核。

這些初步圖片由內建 Image Gen 產生，已附上現有桌機與手機子網格介面作為視覺參照。圖片中的格線位置及材料縮圖均是示意，不能作為座標公式或實際支撐範圍的驗收證據；後續介面必須使用核心推導的真實線段，包含子格範圍與孔洞裁切。

初輪已顯示的稿件順序：第 1 張為規格工作台、第 2 張為畫布內套用、第 3 張為步驟式確認；使用者當時以「2」選定第二張。後續於 2026-09-27 改選新一輪的第 1 張「畫布旁直接編輯面材」，以 `design/reference-inline-selected.png` 取代舊 `design/reference-selected.png` 作為目前視覺依據；這兩輪的「第 1 張」不是同一稿件。

### 7.1 選定方向的互動原型（保留設計沿革）

位置：`geometry-web/prototypes/engineering-spec/`；本機原型預覽入口：`http://127.0.0.1:8810/`。保留大畫布、左側圖層與右側規格設定，面材寬、長、厚與常用尺寸可直接在右欄編輯；手機切換設定／畫布，底部保留主要動作。選定圖片與瀏覽器對照保存在原型的 `design/`。此入口不讀寫正式 Canvas 的工程；原型備份 JSON 不能當作正式 `.gcanvas` 開啟。

## 8. 驗收條件

| 編號 | 操作／情境 | 通過條件 |
|---|---|---|
| A01 | 建立面材與角材材料 | 名稱、類型、單位及必要尺寸清楚；非法值指向欄位；不可發布缺漏來源 |
| A02 | 建立工程做法 | 各材料有明確 ID／版本引用；排板參數與構件角色預設分開；預覽不宣稱構件已建立 |
| A03 | 套用到新面 | 預覽明確指出要建立的網格與來源；套用後引用真實參與推導 |
| A04 | 更新既有面 | 明確選定更新哪個主格及綁定哪些角材；未選物件的材料來源、截面宣告與角色不被改寫；因既有引用連動的位置與長度變更必須納入影響預覽 |
| A05 | 局部覆寫與恢復 | 看得到來源／生效值／覆寫狀態；恢復沿用先重新驗證，成功後移除覆寫 |
| A06 | 更換材料版本 | 原有工程不自動變；選擇升級後預覽完整影響，局部覆寫預設保留 |
| A07 | 父格仍有子格 | 線數變更、不可整除或引用失效指出物件與原因；套用停用且世界不變 |
| A08 | 新方向與既有角色不同 | 既有角材角色不被追改；實際方向違規清楚呈現；使用者可返回調整 |
| A09 | 三面批次其中一面失敗 | 三面皆未改；不可呈現部分成功；修正後一次套用，一次復原整批撤回 |
| A10 | 預覽後世界再變 | 舊預覽無法提交，要求重新計算；沒有過期資料覆寫新內容 |
| A11 | 超出容量或缺少來源 | 整批拒絕，不截斷、不跳過、不建立懸空引用 |
| A12 | 保存、關閉、重開 | 無外部規格庫仍可還原相同版本、覆寫、引用及推導結果 |
| A13 | 跨專案匯入 | 同名不同 ID 不串錯；同 ID／版本異內容拒絕；缺少依賴拒絕且不覆寫原資料 |
| A14 | 舊專案讀取 | 原幾何不變，來源標為既有直接輸入；不經確認不自動遷移 |
| A15 | 桌機與手機操作 | 表單標籤可辨識、鍵盤順序合理、錯誤可定位；390 px 無水平溢出、底部動作不蓋住欄位 |
| A16 | 小數幾何尺寸 | 明確告知目前精度限制；不取近似值、不當作已具備完整支援 |

以上是驗收條件，不是逐項通過聲明。正式測試及尚未驗證部分以專案檢查紀錄為準。初步圖片只能審查資訊層級與視覺，不替代互動或幾何驗證。

## 9. 實作順序與規格關卡

1. 核定本功能範圍與介面方向，補齊關鍵狀態。
2. 提交逐條公理差異：材料／工程做法／套用身分、具型別參數、尺寸引用、版本與遷移、跨面交易及保存。取得明示核准。
3. 先完成核心來源定義、求值、交易、序列化及契約測試，再提供給介面使用；來源不可只存在前端標籤。
4. 實作材料庫與做法編輯、面內入口、影響預覽及整批套用。
5. 驗證 A01–A16、既有場景與子格相容性，並同步唯一正典閱讀器及見證。

2026-09-27 的規劃／原型階段不修改公理及正式應用。2026-09-28 使用者核准逐條提案後，正式實作進入上述核心、介面及保存驗收流程；採納紀錄見 `geometry-core/ENGINEERING-SPEC-PROPOSAL.md`。原型 `design-qa.md` 仍只記錄原型，不作 A01–A16 的正式驗收證據。
