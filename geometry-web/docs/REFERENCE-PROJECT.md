# GEO-198：PDF 參考與可攜專案

2026-09-26；使用者核准第一批範圍：PDF 描面、來源紀錄與保存。尚未接入 3D 建模。

## 使用方式

1. 左欄「從 PDF／圖片描面」，或「檔案 → 匯入參考資料」。原有直接建立入口保留。
2. 選擇頁碼，預設完整顯示整頁，可放大、框選取景。「清除取景框」恢復整頁。選既有面，或明確建立描繪用面；取消不建面。
3. 右欄先顯示校準：點兩點並填圖上已知距離（mm／cm）。手機取點時收起右欄，選好後回到距離输入。只有套用後才標「已校準」；自動適合畫面的比例不算校準。
4. 沿用外環、尺寸及構件工具。更換圖頁各自保留對位與校準。「從此來源選其他頁」可查閱完整 PDF。
5. 在來源紀錄中保存已知數值及基準；留空表示待補。紀錄不建立任何幾何或 RC 構件。
6. 在固定頂列點「保存專案」，面內或物件畫布都能使用。未完成的外環須先套用或放棄草稿；校準取點也須先套用或取消。支援檔案選擇器時完成寫入才顯示已保存；下載模式只說已產生下載。
7. 「開啟 .gcanvas 專案」還原完整來源與幾何。原有 `.scene` 入口只存取幾何。

對位、旋轉、透明度與鎖定集中在「對位與顯示」；來源頁及紀錄可分別展開。
需要 3D 位置或構件時，可展開「放置與空間（選用）」進入原放置表單，2D 描面不要求先設定高度。

## 格式與責任

`.gcanvas` 是 ZIP：`manifest.json`、`world.scene`、`sources/<sha256>`。
清單 `format` 固定為 `geometry-canvas/1`，未知版本拒絕。來源整份保存，依 SHA-256 去重。

- `projectId / name / sceneHash`：專案身份、展示名稱、場景完整性。
- `sources[]`：id、hash、name、type、size、path；原始位元組不改寫。
- `faces[]`：bid、activePageId、pages。
- 圖頁：id、sourceId、page（從 1 起算）、imgW/H、crop `[x,y,w,h]`、mmPerPx、x/y、rot、opacity、locked、calibration、reviewRequired、records。
- 校準：points、distanceMm、inputValue、inputUnit；未知校準為 `null`。
- 紀錄：id、label、location、value（未知為 `null`）、unit、datum；來源頁由所屬圖頁決定。

圖片座標為原始像素；PDF 座標為套用原頁旋轉後的 `getViewport({scale:1})` 頁面座標，左上原點、Y 向下。
PDF 預覽解析度、取景及縮放不改頁面座標。`mmPerPx` 沿用既有欄位名，PDF 時表示每頁面座標單位的 mm。
對位仍為未旋轉的左上角，旋轉繞原始整頁中心，沿用 GEO-190 語意；改比例保持 x/y 不動。
來源調整不修改已建立幾何，會標需核對；已校準面的輪廓改動也要求重新核對。

`project-store.js` 負責格式、雜湊、封裝與中繼資料歷史；`reference-workspace.js` 負責來源選頁、界面及場景接合。
瀏覽器只保存來源／關聯資料，幾何由核心的 dump、objects、boundary 提供。
原始來源檔不送服務端；只有 `world.scene` 使用既有 `/upload`。
服務端新增兩個 JS 靜態路由與 vendor 精確檔案白名單，不開放任意路徑讀取。
提交前審查另在既有 `/api` 加入可選的操作結果查詢，修正回應遺失造成的來源歷史錯位；幾何指令及核心不變。

## 失敗及歷史

- 載入先驗證版本、數值、來源雜湊、頁數、頁面尺寸及作用中頁的可算繪性；再交易式載入核心。
- 按「加入參考頁」即鎖定當下圖頁、取景及目標面；建面／進面期間對話框不可再操作，完成或失敗後解除。
- 保存／開啟期間阻擋畫布與選單的點擊、鍵盤及表單事件，避免已保存內容與目前畫面不一致。
- 核心拒絕時不替換目前來源。傳輸無法確認時顯示錯誤並暫停編輯，不報成功。
- `/api` 修改請求帶一次性識別及服務工作階段；回應遺失時只查詢已記錄結果，不重送修改。重新連線先同步該結果，再刷新物件及來源歷史。
  群組已提交時保留一步復原；尚未提交則在確認結果後中止群組。查詢先於原請求抵達時，該識別會標為未送達，晚到的請求也不執行。
  已收到結果由下一次請求確認回收；最多保留 256 筆未確認結果，滿額時拒絕新增操作。服務重啟後拒絕套用舊工作階段的結果。
- 載入回應遺失時，重試先比對核心目前 dump 與載入前／預期結果，恢復可證實的來源。兩份幾何相同而無法判定時重試原載入；核心較早歷史仍可操作，但無法證實的來源歷史會明示不可恢復，不按面編號猜接。
- 專案最多 256 MB；單一來源最多 128 MB；解壓縮總量最多 512 MB。只接受清單、場景及已列出的來源路徑。
- 中繼資料歷史對應核心的成功命令與 history 群組。只保存專案上下文及面實例識別，不保存幾何快照。
- 容量跟隨現有核心 `HISTORY_MAX=32`；`canvas-pos`、preview、cancel-preview 不新增歷史；群組失敗整組還原。
- 同一面實例的來源修改不新增幾何復原步驟。復原／重做可恢復原實例的來源；分支上重用編號是另一實例。
- 開啟專案本身沿用核心的一步復原；新瀏覽器工作階段之前的來源歷史無法恢復。專案包不攜帶復原堆疊。

## 驗證

- `node --test tests/test_project_store.js`：封裝、完整性、數值檢查、場景與實例隔離；含群組內刪除後立即重建同編號面。
- `python -m unittest tests.test_serve tests.test_feedback_store`：服務路由、既有來源限制與回報功能。
- 完整 `geometry-web/cdp_test.js`；新增 P57–P61 涵蓋圖片／PDF、cm 校準、正交輪廓、保存重開、取消、讀取與寫檔失敗、手機版。
- `GEOMETRY_REFERENCE_ONLY=1` 可只跑新增段；不能取代完整回歸。
- 私人案例留本機；`tests/reference_pdf_fixture.js` 生成自製雙頁矩形／L 形 PDF。
- 已知矩形／L 形座標使用獨立預期值核對四種直角旋轉，不只驗證轉換函式互為反函式。
- CDP 測試在既有固定等待後檢查請求及畫面更新是否安定，保留原驗收條件，避免讀到核心提交與檢視器更新之間的過渡狀態。

PDF.js 6.3.289 與 fflate 0.8.3 固定在 `vendor/`，包含 LICENSE 及來源版本記錄。執行時不依賴 CDN 或 npm 安裝。
