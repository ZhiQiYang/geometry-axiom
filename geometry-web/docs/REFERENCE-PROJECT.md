# GEO-198：PDF 參考與可攜專案

2026-09-26 初版：PDF 描面、來源紀錄與保存。2026-09-27 增加空間建模保存；見 [第一版操作說明](SPACE-MODELING.md)。

## 使用方式

1. 「檔案 → 匯入參考資料」，或畫布空狀態的描圖入口。原有直接建立入口保留。
2. 選擇頁碼，預設完整顯示整頁，可放大、框選取景。「清除取景框」恢復整頁。選既有面，或明確建立描繪用面；取消不建面。
3. 右欄先顯示校準：點兩點並填圖上已知距離（mm／cm）。手機取點時收起右欄，選好後回到距離输入。只有套用後才標「已校準」；自動適合畫面的比例不算校準。
4. 沿用外環、尺寸及構件工具。更換圖頁各自保留對位與校準。「從此來源選其他頁」可查閱完整 PDF。
5. 在來源紀錄中保存已知數值及基準；留空表示待補。紀錄不建立任何幾何或 RC 構件。
6. 在固定頂列點「保存專案」，面內或物件畫布都能使用。未完成的外環須先套用或放棄草稿；校準取點也須先套用或取消。支援檔案選擇器時完成寫入才顯示已保存；下載模式只說已產生下載。
7. 「開啟 .gcanvas 專案」還原完整來源與幾何。原有 `.scene` 入口只存取幾何。

對位、旋轉、透明度與鎖定集中在「對位與顯示」；來源頁及紀錄可分別展開。
需要 3D 位置或構件時，可展開「放置與空間（選用）」進入原放置表單，2D 描面不要求先設定高度。

## 格式與責任

`.gcanvas` 是 ZIP：`manifest.json`、`world.scene`、`sources/<sha256>`。
清單 `format` 為 `geometry-canvas/1`，含空間模型時使用 `/2` 並增加 `models`；含面投影定義或模型來源投影快照時使用 `/3`，增加 `faceProjections`；含角材結構模型時使用 `/4`。四版均可讀取，未知版本拒絕；舊程式拒絕不支援的新版，避免遺失新欄位。來源整份保存，依 SHA-256 去重。

- `projectId / name / sceneHash`：專案身份、展示名稱、場景完整性。
- `sources[]`：id、hash、name、type、size、path；原始位元組不改寫。
- `faces[]`：bid、activePageId、pages。
- 圖頁：id、sourceId、page（從 1 起算）、imgW/H、crop `[x,y,w,h]`、mmPerPx、x/y、rot、opacity、locked、calibration、reviewRequired、records。
- 校準：points、distanceMm、inputValue、inputUnit；未知校準為 `null`。
- 紀錄：id、label、location、value（未知為 `null`）、unit、datum；來源頁由所屬圖頁決定。
- 面投影定義：`faceProjections: [{bid, placement_id, projection}]`，不要求存在 PDF／圖片。每份定義綁定面實例與放置面；投影用途、觀看方向、淨空輪廓與外側牆厚的精確欄位及生命週期見 `FACE-PROJECTION.md`。圖面 z 由放置資料取得，不另存副本。
- 平面模型的 `source.projection` 保存建立時的投影定義；依模型原始 `input.base_scene` 與 `source.placement_id` 驗證，不要求現有畫布仍保留來源面。舊模型缺此欄位仍可開啟及修改牆高，介面明示未保存投影定義。
- 角材模型以 `input.timbers` 精確列出所选放置面的根物件，`result.timbers` 保存從原始來源推導的獨立交換包；來源雜湊不能誤用生成牆面後的場景。匯入核對根、放置、完整實體、支數、材料量與重建結果，角材不自動成為淨空障礙。修改牆高保留角材位置及來源快照；詳見 `TIMBER-IN-SPACE.md`。
- 空間模型：id、name、created_at、source、input、result；保存明確建模輸入及經驗證的空間／體積／淨空／材料牆套件。新平面模型預設牆高 3000 mm，牆底須明填；舊模型高度不變。模型使用建立當時的幾何定義，不隨來源變更自動更新。「修改牆高」只更新平面模型保存的 `input.settings.height` 及重新驗證的結果，保留 ID、建立時間、來源與其他設定；取消或預覽失敗不改原紀錄。組合既有面模式仍以各面位置決定幾何。清單最多 8 MB、模型最多 64 個。

圖片座標為原始像素；PDF 座標為套用原頁旋轉後的 `getViewport({scale:1})` 頁面座標，左上原點、Y 向下。
PDF 預覽解析度、取景及縮放不改頁面座標。`mmPerPx` 沿用既有欄位名，PDF 時表示每頁面座標單位的 mm。
對位仍為未旋轉的左上角，旋轉繞原始整頁中心，沿用 GEO-190 語意；改比例保持 x/y 不動。
來源調整不修改已建立幾何，會標需核對；已校準面的輪廓改動也要求重新核對。

`project-store.js` 負責格式、雜湊、封裝與中繼資料歷史；`reference-workspace.js` 負責來源選頁、界面及場景接合。
來源／關聯資料保存在瀏覽器專案上下文，原有幾何由核心的 dump、objects、boundary 提供；複合空間幾何由既有建模執行器推導並验证。
原始來源檔不送服務端；`world.scene` 使用既有 `/upload`，模型的幾何定義與套件經 `/model/space-preview` 及 `/model/verify` 驗證。
服務端新增兩個 JS 靜態路由與 vendor 精確檔案白名單，不開放任意路徑讀取。
提交前審查另在既有 `/api` 加入可選的操作結果查詢，修正回應遺失造成的來源歷史錯位；幾何指令及核心不變。

## 失敗及歷史

- 載入先驗證版本、數值、來源雜湊、頁數、頁面尺寸及作用中頁的可算繪性；再交易式載入核心。
- 含空間模型時，先逐包驗證、依保存輸入重建並核對摘要及幾何，全部成功才載入核心。模型驗證失败不替換目前專案。
- 按「加入參考頁」即鎖定當下圖頁、取景及目標面；建面／進面期間對話框不可再操作，完成或失敗後解除。
- 保存／開啟期間阻擋畫布與選單的點擊、鍵盤及表單事件，避免已保存內容與目前畫面不一致。
- 核心拒絕時不替換目前來源。傳輸無法確認時顯示錯誤並暫停編輯，不報成功。
- `/api` 修改請求帶一次性識別及服務工作階段；回應遺失時只查詢已記錄結果，不重送修改。重新連線先同步該結果，再刷新物件及來源歷史。
  群組已提交時保留一步復原；尚未提交則在確認結果後中止群組。查詢先於原請求抵達時，該識別會標為未送達，晚到的請求也不執行。
  已收到結果由下一次請求確認回收；最多保留 256 筆未確認結果，滿額時拒絕新增操作。服務重啟後拒絕套用舊工作階段的結果。
- 載入回應遺失時，重試先比對核心目前 dump 與載入前／預期結果，恢復可證實的來源。兩份幾何相同而無法判定時重試原載入；核心較早歷史仍可操作，但無法證實的來源歷史會明示不可恢復，不按面編號猜接。
- 專案最多 256 MB；單一來源最多 128 MB；解壓縮總量最多 512 MB。只接受清單、場景及已列出的來源路徑。
- 中繼資料歷史對應核心的成功命令與 history 群組。只保存專案上下文及面實例識別，不保存幾何快照。
- 容量跟隨現有核心 `HISTORY_MAX=32`；`canvas-pos`、preview、cancel-preview 不新增歷史；群組失敗整組還原。
- 同一面實例的來源修改不新增幾何復原步驟。復原／重做可恢復原實例的來源；分支上重用編號是另一實例。
- 模型增刪改新增本機歷史步驟，與核心歷史按實際操作順序交錯；本機復原不多送一次核心 undo，分支會封鎖舊核心 redo。刪除最後一個模型仍標記未保存。
- 開啟專案本身沿用核心的一步復原；新瀏覽器工作階段之前的來源歷史無法恢復。專案包不攜帶復原堆疊。
- 手動開檔與試用工程專案從讀取、驗證到畫布／工程規格可用全程顯示目前階段並阻擋 UI 重入；載入前若原工程被其他非同步操作改動，拒絕替換。復原／重做訊息保留「開啟專案」及專案名稱。
- 完整檔案專案保持已保存；內建範例明示「範例已載入 · 尚未另存」，不代表使用者已有自己的檔案。缺畫布位置的舊包會自動配置並保存展示資料，狀態明示「畫布已自動排版 · 尚未保存」，不把這次新增的展示資料隱藏成已保存；現成工程範例預先保存卡片位置。
- 工程規格視窗的初始表單、分頁瀏覽與關閉不新增專案草稿；表單內容實際修改時才保存草稿並標示未保存。已有草稿仍可保存進專案及重開接續。

- `python -m unittest tests.test_serve tests.test_feedback_store`：服務路由、既有來源限制與回報功能。
- 完整 `geometry-web/cdp_test.js`；新增 P57–P61 涵蓋圖片／PDF、cm 校準、正交輪廓、保存重開、取消、讀取與寫檔失敗、手機版。
- `GEOMETRY_REFERENCE_ONLY=1` 可只跑新增段；不能取代完整回歸。
- 私人案例留本機；`tests/reference_pdf_fixture.js` 生成自製雙頁矩形／L 形 PDF。
- 已知矩形／L 形座標使用獨立預期值核對四種直角旋轉，不只驗證轉換函式互為反函式。
- CDP 測試在既有固定等待後檢查請求及畫面更新是否安定，保留原驗收條件，避免讀到核心提交與檢視器更新之間的過渡狀態。

PDF.js 6.3.289 與 fflate 0.8.3 固定在 `vendor/`，包含 LICENSE 及來源版本記錄。執行時不依賴 CDN 或 npm 安裝。

## GEO-218：專案資訊與接續工作（2026-09-29）

「目前工作內容」是畫布上正在編輯的內容；「場景」是由服務保留的幾何、構件及引用；「專案」把場景、來源附件、空間模型與已記錄的工程草稿一起保存為 `.gcanvas`。`.scene` 只保存場景，不含完整專案。頂列資訊鈕依實際事件顯示來源、最近確認寫入、下載產生時間及下一次復原；不從範例清單推測來源，也不把開啟檔案的時間當成保存時間。

- 新專案清除內容並建立新的身份與名稱。清空專案內容保留身份及名稱，清除場景、附件、模型與草稿；兩者均先確認且各可一步復原。開啟專案仍可一步復原。
- 工程規格、網格與空間建模使用同一份頂列保存控制；視窗主動作是預覽、建立或套用。網格未套用設定、外環與校準草稿仍阻擋保存；工程規格的已記錄表單草稿可隨專案保存。
- 完成操作後，本分頁可將完整專案包暫存至瀏覽器 IndexedDB。重新整理時先核對服務工作階段與場景指紋，再驗證整包資料；全部相符才恢復附件、專案身份、模型、已記錄工程草稿及原本保存狀態。恢復不向服務上傳場景，也不恢復未套用的工具草稿或較早的完整復原歷史。
- 不符時保留目前場景及舊暫存，不把舊附件接到新場景；介面說明需開啟正確檔案。瀏覽器空間不可用或寫入失敗會如實顯示。本機暫存不等於已保存檔案；關閉分頁後不保證能接續。
- 同一瀏覽器儲存環境、同一網站位址與服務工作階段只允許一個編輯分頁；另一分頁唯讀。關閉原編輯分頁後，可在資訊面板按「重新連接此工作」。不同瀏覽器設定檔、`localhost` 與 `127.0.0.1` 等不同網站位址，以及外部工具不共享此瀏覽器鎖；這不是服務端的全域多客戶端交易保證。
- 收到其他分頁變更通知後暫停保存、編輯與復原；明確替換專案前隔離不可確認的舊附件歷史，避免下一次復原混用資料。

新增瀏覽器驗收由 `cdp_test.js` P74 呼叫 `ux_refinement_test.js`；`GEOMETRY_UX_REFINEMENT_ONLY=1` 僅跑該段，不能冒充完整回歸。
