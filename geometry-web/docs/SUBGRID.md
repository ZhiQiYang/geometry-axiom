# 子網格使用與驗收（GEO-204）

依據：2026-09-27 使用者批准的 `geometry-guide/SUBGRID-CLAUSE-PROPOSAL.md`；正式規範見公理 D19／I25／R23 及相關條文。子網格採用設計稿的單格雙軸等分。

## 使用方式

1. 進入一個已建立主網格的面，在網格設定按「建立子網格」。
2. 在畫布點一格，或用「父格範圍」選單選格。包含靠面邊的格子；孔及凹面以實際有效區域裁切。
3. 輸入 u、v 等分數，查看局部預覽、間距與子線座標。1 表示該軸不加內部線，至少一軸須大於 1；跨度不能整數等分時會指出欄位。
4. 按「建立子網格」。清單的子網格列可重新編輯、改等分或重新選格；變更既有子格時先確認新舊範圍及引用的影響。
5. 左欄可整組或逐線切換顯示。隱藏只影響目前面內畫布，重開專案會恢復顯示；子網格定義會隨專案保存。

兩方向子線皆預設副支 3。沿線放材時可明確覆寫角色；與實際主支同方向、或尚未建立主支方向時，介面提示不能以副支放置。角色仍由核心驗證。

## 操作限制

- 子網格只依附主網格，一組對應一格；同格不可重複建立，亦不建立子格的子格。
- 直接錨在子線的角材，其整個 footprint 必須留在父格內，兩端仍需實際擋面。虛擬格邊不提供支撐。
- 父格仍有子格時，不能增減任一軸線數，避免索引悄悄改指其他格；同條數移動會重算並預覽。
- 有子格的父格不能刪；子格仍被 guide／角材引用時不能刪。介面列出直接依賴。
- 世界共最多 16 組主／子網格，每軸最多 64 條內部子線（最多 65 等分）。
- 相位差不是子網格的欄位。父格任一軸已有相位差時，不能建立或保留子網格。依跨度條件批次等分與巢狀子格尚未納入。

## 設計稿對照

| 稿件內容／問題 | 實作 |
|---|---|
| 在畫布選一格、雙軸等分 | 可點畫布，亦有鍵盤可操作的範圍選單及 SVG 格子 |
| 子線預設副支 3 | 兩軸一致，提示與實際主支方向的衝突，可明確覆寫 |
| 固定示意值沒有真正表單 | 真正等分欄位、核心唯讀預覽、欄位錯誤、草稿重設與套用 |
| 示意子線穿進孔內 | 線段、標籤、命中及定位預示依有效區域與局部範圍裁切 |
| 父格改動、刪除及容量未定 | 依已批准條文加入追溯、影響確認、依賴保護與上限 |
| 手機設定遮住畫布 | 選格時收起設定；選完返回設定；表單控制至少 44 px |

## 驗收證據

正式驗收項目 S01–S15 在批准提案中逐項定義。證據分工：

- `tests/test_subgrid_contract.py`：核心公開協定，S01–S13，包含拆面後 guide 連鎖重算及非法預覽內容。
- `subgrid-local.scene`：局部子線依真實主支側面推導角材長度；已加入完整場景回歸。
- `geometry-web/cdp_test.js` P8v4：實際執行 app.js，畫布滑鼠選格、欄位修正、有限線段及孔裁切、顯示切換、編輯、確認／取消、undo／redo、專案保存重開、390 px 手機、鍵盤、角色提示、ID 0 與大座標選格。
- `tests/test_modeling_runtime.py`：子格來源可供既有建模執行器讀取，幾何未被展示網格改動；非法子格仍拒絕。
- `geometry-guide/witness/子網格-驗證.md`：三個新增條文的見證圖，以及九張既有主格線顯示錯位的修正證據。

最終測試數及提交紀錄記於 BACKLOG.md 的 GEO-204。

## 測試環境與限制

測試使用獨立 `http://localhost:18814/`、Chrome 桌機 1400×900 與手機尺寸 390×844，回報、設定檔與截圖置於系統暫存 `geometry-tests`。核心與橋接器使用 WSL GCC；Windows MSVC 原生版另作編譯檢查。

Browser plugin 未提供，使用專案要求的 Chrome CDP harness。此測試實際載入 app.js 並操作介面；沒有以靜態來源檢查冒充瀏覽器驗收。

真實手機觸控、Windows 原生另存視窗及 GDI 視窗仍須實機操作確認。專案保存已透過實際封裝／讀回流程驗證；原生檔案選取器採測試替身。

R6 的「between 配對短於原最大合法區間」防禦分支已靜態核對篩選順序；尚未構造合法公開 World 對此單一分支做黑箱覆蓋。可達的孔洞、多跨距、格外拒絕及明示實際擋面配對均有黑箱測試。
