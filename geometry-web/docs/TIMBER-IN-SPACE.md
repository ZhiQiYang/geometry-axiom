## 目標與操作

已在水平投影面上放好的角材，在「建立空間」時一起產生真正的 3D 材料幾何，保留每支角材的身份、尺寸、位置、方向及來源，不必在 3D 中重畫。

操作流程：

1. 在面內完成平面投影定義與角材放置。例如圖面 z=2500，角材厚度朝上，角材底面與圖面共面。
2. 按「建立空間」，在高度設定附近顯示「一併納入此面角材（N 支）」。有角材時預設勾選，可取消；零支時停用並說明如何回面內放置。
3. 展開清單可核對放置面編號、角材編號、角色、A×B、推導長度及最低／最高 z。資料由已驗證來源取得，不用 2D 線條猜構件。
4. 更新預覽。3D 有「空間邊界」「材料牆」「角材結構」三個獨立顯示開關。核對清單明示納入 N 支或未納入角材，再建立空間。
5. 保存 `.gcanvas`；重開仍能查看角材。匯出選單提供「角材結構」模型套件。

預設勾選是介面工作預設；送入建模器的仍是該次來源中精確列出的角材引用，不讓後端自行搜索附近物件。已建立模型沿用原本的來源快照；本期不加入自動同步來源或模型內直接修改角材。

## 範圍及幾何規則

- 第一版只接「由平面輪廓建立空間」的來源放置面。依 `placement_id` 選角材；同一輪廓的另一個放置、別的面或游離物件都不連帶納入。既有「組合已有的放置面」模式維持原行為。
- 角材須已通過既有放置驗證。長度由 D7／R6 推導；使用真實截面、三軸與原點，不使用外接輪廓重造假角材，不把角材厚度換成牆高。
- 世界 +Z 是向上。底面與 z=2500 共面、厚度 B=33 朝上時，最低 z=2500、最高 z=2533；朝下時為 2467～2500，是頂面共面。判斷依世界方向，不把 `+n` 永遠當朝上。
- 改變俯視／仰視只改觀看方向。改牆底、牆高或牆厚不搬移、不拉伸、不裁短原角材；即使角材超出新牆頂也保留其真實位置，核對時清楚顯示高度。
- 各角材維持獨立實體與 ID。一起展示不表示布林合併、不成為空間殼成員，也不自動列入淨空障礙。既有明示柱樑障礙仍照原設定計算。
- 「角材體積合計」為納入角材的材料量，獨立於空間體積、淨空及材料牆體積。不得將它加到空間量或偽稱布林聯集體積。
- 勾選納入後，任何指定角材無法完整建模均阻止本次建立／更新並顯示原因與角材 ID。不能少幾支仍報成功。使用者可明確取消納入，再重新預覽空間。

依據：`公理層.md` D7、D9、I1、I8／I8a、I9、I11、I13、D21–D25、R6、R26、R28–R30。這是既有角材建模能力的流程整合；不修改公理、核心放置規則或唯一正典閱讀器。

## 實作契約與順序

### 1. 先建立可執行夾具

在 `tests/test_space_modeling.py` 擴充朝上／朝下、反向法向、支撐依賴、多 placement 及 ID 0 夾具。以已有引擎輸出作為幾何來源，另用人工可算的座標及材料體積驗收，不能只讓兩份同源 JSON 自洽。

### 2. 後端：候選與角材套件

主要檔案：`geometry-web/space_modeling.py`，必要時接合 `geometry-web/serve.py` 的既有建模端點。

- 權威候選來自同一份 `input.base_scene` 經 `load_base()` 驗證後的 `solids`，限 `kind=timber` 且 `placement_id` 等於所選放置。UI 優先使用既有 `references` 回傳的 `geometry.surface` 與角材資料；取得資料前後核對 dump 與專案身份，讓候選摘要與建模輸入對應同一來源快照，不另造候選幾何。
- 平面模式增加選用欄位 `input.timbers`：非空、無重複的 `[{kind:"timber",id:整數}]`，ID 為合法非負整數，包含 0。未納入時省略欄位，保持舊請求；明寫空清單視為無效請求並說明應省略此欄位，不送空 roots，也不產出空角材包。UI 零支或取消納入時直接省略欄位。
- 有明確角材引用時產出 `geometry-space-preview/2`，增加獨立 `timbers` 交換包及摘要中的 `timber_count`、`timber_volume_mm3`。無此欄位的既有請求繼續產出舊 `/1` 形狀，不偷偷新增欄位。
- 角材包從**原始** `input.base_scene` 獨立求值，`roots` 為已驗證的角材引用，`role=geometry`、`target=solid-set`、`allow_partial=false`。不混入生成牆體的場景，不拼接不同交換包的網格冒充新包。
- 完整驗證角材包、根集合與摘要後才回成功；每個指定根必須完整存在。空間、淨空、牆體沿用原演算法及明示障礙清單。

### 3. 保存：新舊版本及原子驗證

主要檔案：`geometry-web/project-store.js`、`geometry-web/reference-workspace.js`；測試擴充既有專案與模型測試。

- 含新角材模型的專案使用 `geometry-canvas/4`。/1–/3 照原樣讀取；無新角材內容不強制升級，舊程式必須明確拒絕 /4 而不是丟失角材。
- 校驗新請求、回應、package roots、數量、材料體積、來源雜湊及保存输入的相互一致性。角材原始來源與生成殼包來源不同，不能錯用「兩包來源雜湊必相同」的條件。
- 匯入驗證與 replay 必须把 `timbers` 包納入；全部通過後才替換專案。保存紀錄及本機歷史維持不可變快照。
- 修改牆高沿用完整保存輸入，只改 `settings.height`；角材包應由同一原始來源重新驗證，保留原角材定義與幾何。

### 4. 介面：納入、檢視與核對

主要檔案：`geometry-web/space-workspace.js`、`space-workspace.css`；必要時擴充 `model-viewer.js`。若需更清楚的面內放置說明，僅局部修改 `app.js` 及相應 DOM 合約。

- 候選清單、預設勾選、空狀態及完整性提示先接到來源載入流程。組合已有面模式不提供本期角材納入控制。
- 納入選擇是建模設定，變更使預覽失效；「顯示角材」只是觀看開關，不改納入選擇、不重算幾何。
- Viewer 接收角材包中的真實 mesh，給角材層獨立色彩與圖例，保留每支 ID 於核對清單及模型資料；不讓每支角材占一個圖例名額。只作用於空間殼的頂面隱藏不能套到角材。本期不新增 3D 點選角材或修改角材操作。
- 來源、請求序號、專案身份與模型原紀錄的核對沿用現有機制，增加角材選擇及候選來源一致性。
- 模型清單與重開畫面可見已納入支數；匯出角材包使用既有匯出機制。

### 5. 整合、審查與交付

- 擴充 `tests/test_space_modeling.py`、`tests/test_space_model_store.js`、`tests/test_model_viewer.cjs`、`geometry-web/space_model_test.js`；必要時新增候選與角材存取專項，不新增鏡像實作型測試。
- 修正後跑適用的現有測試；若修改 app.js，依 AGENTS.md 跑完整 `cdp_test.js`。独立審查重點是精確 placement 歸屬、世界 z、來源依賴、schema／replay、非同步與歷史。
- 在隔離服務測試，不重置或重啟使用者 18831 世界；回報、瀏覽器設定與截圖放系統暫存。
- 更新現成 `.gcanvas` 範例及 `SPACE-MODELING.md`、`REFERENCE-PROJECT.md`、`DOM-CONTRACT.md`。提供可辨識的新版本標記與操作步驟，打開已驗證版本。
- 若服務端更新需換服務，先保存／確認可恢復目前專案，再安排交付，不能直接重啟遺失使用者幾何或歷史。

後端與儲存可在契約確定後平行實作；介面再接合兩者，最後跑完整操作驗收。全部 T01–T15 有證據後才能標記完成；規劃文件或單純畫面出現角材均不代表功能驗收通過。
