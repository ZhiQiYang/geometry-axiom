# L5 使用者驗收導覽

更新：2026-11-28（台北）  
核對基底：`48d5f3887e8cb8d222307db62dbdea287fda8442`

這份導覽讓你一次只試一件事。先試你最需要的功能；不必從頭讀完，也不必一次驗完。

**先選一張：** [下角材](#card-01) → [面材鋪排](#card-04) → [底圖描房間](#card-10)。

## 怎麼用

- 先請協助準備 App 的人備好卡上指定的專案、頁面和範例，再從第 1 步開始。每張以約一分鐘為設計目標；本稿尚未由使用者計時，準備、下載及重新開檔的等待不算在內。
- 用驗收用的副本，原本工作先另存。不同卡若沒有寫「接續」，就重新開該卡的起點；現成成品不一定能再按一次「建立」。
- 每張只確認標明的功能。遇到載入中先等畫面穩定；找不到按鈕、資料不符或仍在載入，就記「卡住」與停在哪一步，不猜下一步。
- 已知缺口仍會影響你是否接受。可以記「功能點通過，但目前不接受作為日常工具」，不必為了完成驗收勉強勾通過。
- **這是待使用者驗收的導覽，不是已通過的紀錄。** L4 表示已有 App 操作證據；只有你親自操作並確認的那張卡、那個版本與那段範圍，才有 L5 依據。相鄰卡、整個需求或未試過的裝置不會一起升級。

記錄只要一行：

```text
日期／App 版本／裝置與視窗寬度／卡號／通過・不通過・卡住・未測／卡在哪或是否符合我的工作需要
```

「通過」須同時符合卡內看見的結果與你的接受意見；「不通過」記下實際與預期的差別。可用 App「回報」留現場狀況（見回報卡），不要只回「全部可以」。


只想找一項功能，可用文末的[完整需求索引](#inventory)；幫忙開 App 的人請看[範例準備表](#preparation)。

## 一、先試下角材

本組每次挑一張；前置備妥後開始。

### 卡 01｜先看整組天花骨架，再決定要不要放下去（R03：固定範例矩形）

**前置：**請套用端備妥「3740×3301 天花，尚未生成」副本，材料、8 mm 門檻與配方已建好（前置表 A）；定位在物件畫布的這片天花。此起點需新增，不能直接用已確認的 `r03a.gcanvas`。

1. 雙擊天花，開「屬性 → 面設定… → 完成面／骨架…」，面內工作選「平釘天花骨架（政策 A 固定治具）」。
2. 明選這片天花的放置、915×1830×6 板材、8 mm 門檻，勾選表單的 RC／角材語意，按「預覽整組骨架」。
3. 應看到候選 **53 支**及排法圖；四邊有邊材，主支整支連續。按「取消本次生成」，應顯示配方與場景保持原狀的提示。
4. 重新明選來源、預覽，再按「確認骨架（一筆歷史）」。
5. 按「返回面設定」，再切頂列「三視圖」，在仰視圖點一支料，應看得到骨架並出現「角材 N」的選取結果。

**不通過：**53 支對不上、取消仍放入角材、確認後三視圖找不到骨架。**已知缺口：**物件畫布／面內仍看不到生成骨架，尺寸卡與門檻使用數也不正確；1400 px 預覽表可能把 3247 折成兩行。這些另外記為不接受或待修，不當成操作失誤。

依據：[README.md](../evidence/l4-cloud-20261122r03a/README.md)「逐步操作與結果」「第 4 點」。

這張卡只驗預覽、取消、確認及確認後三視圖。整組復原／重做的資料已有 L4 紀錄，但一般畫面在復原中途如何顯示仍未核；不把看不到中間結果的連按算成本人已驗收歷史。

### 卡 02｜試舊矩形配方，確認既有排法還在（R03：矩形第一片）

**前置：**「3740×2000 天花，尚未生成」副本（前置表 A 的第一片版本）。

1. 雙擊這片天花，開「屬性 → 面設定… → 完成面／骨架…」，選「平釘天花骨架（矩形第一片）」及備妥的舊配方。
2. 明選放置、板材、8 mm 門檻及 RC／角材語意，按「預覽整組骨架」。
3. 應看到 **33 支**；主支連續，四邊有邊材，裁片集中在對牆那邊。
4. 按「取消本次生成」；回來後配方、材料與門檻仍在，正式骨架未增加。
5. 重新明選並預覽，按「確認骨架（一筆歷史）」。
6. 應看到「骨架已整筆確認為一般正式物件」的成功提示；若沒有成功提示就停下記錄。

**不通過：**舊配方被當成另一種排法、不是 33 支、取消改動場景或配方，或確認沒有成功回應。一般畫面的顯示缺口同 卡 01；第一片的窄畫面不在既有 L4 範圍。

依據：[README.md](../evidence/l4-cloud-20261121r03/README.md)；第一片配方保持原版本另見 [README.md](../evidence/l4-cloud-20261122r03a/README.md) 第三階段。

此卡只驗第一片配方的預覽、取消及確認回應；一般畫面的幾何顯示與復原可視性不從成功提示推定通過。

依據：[README.md](../evidence/l4-cloud-20261122r03a/README.md) 第二階段。第一片成果可另開 [r03.gcanvas](../evidence/l4-cloud-20261121r03/main-3ef07683/r03.gcanvas)；其配方應仍是「矩形第一片」，不自行升級。

### 卡 04｜先排面材，取消後再決定保存（R02：完成面與正排）

**前置：**「400×300 面材試排，尚未建立完成面」副本（前置表 B）；板材與門檻已備妥；套用端另在當次「完成面與鋪排」表單填好附錄 B 的完成面框架與鋪排原點，停在未確認狀態交給使用者。這些未確認欄位不預設已隨起點檔保存。15 片只適用該固定副本，不能套到任意移動過的矩形。

1. 確認目前是這片面的「完成面與鋪排」表單；入口為「屬性 → 面設定… → 完成面／骨架…」，面內工作選「完成面與鋪排」。
2. 勾「鋪排」；選 100×200×6 面材、長邊沿 v、正排、板縫 3 mm 及備好的 8 mm 門檻。
3. 按「預覽」，應列出 **15 片**；完成面／鋪排的表格可分辨確認前與候選後。
4. 先按取消，再開同表單：沒有已建立的完成面或鋪排。
5. 請套用端恢復第 1 步相同的框架與原點，重選同樣面材數值、預覽並確認；關閉再開，應看得到剛保存的完成面與鋪排。

**不通過：**固定副本片數不符、取消留下正式鋪排、確認後定義不見，或表格看不清改了什麼。**提示：**這張卡尚未放支撐角材，出現「支撐不足（可保存）」是已知狀態；不代表完成結構或建議角材功能已可用。

依據：[README.md](../evidence/l4-cloud-20261113/README.md) R02 UI-1；可讀表的現況見 [README.md](../evidence/l4-cloud-20261123/README.md)。

<a id="card-05"></a>

### 卡 05｜從排板建立跟隨板縫的格線（R02：鋪排來源主格）

**前置：**套用端備好「已有完成面、正排與高 30 mm 宿主，尚未建立主格」副本（前置表 B）；定位在該面。「主格」就是跟著板縫算出來的格線。

1. 進「屬性 → 面設定… → 完成面／骨架… → 完成面與鋪排」。
2. 勾「建立跟隨此鋪排的主格」，主支偏好明選「沿 u」，按預覽。
3. 應有完成面、鋪排、宿主、主格四張前後比較表；主支偏好由「不存在」變「沿 u」。先取消，重開應仍沒有主格。
4. 再勾主格、明選沿 u，預覽並確認；重開應寫「來源主格 #1 已引用此鋪排」。
5. 關閉表單，復原後重開應沒有主格；再關閉、重做、重開，應回到同一個主格。

**不通過：**取消已建立格線、確認沒有留下同一份主格、無法復原／重做，或比較表難以閱讀。**已知缺口：**主格目前只在這張表單能查到，面內及物件畫布尚未畫出；這張卡不把缺少畫面呈現判成通過。

依據：[README.md](../evidence/l4-cloud-20261121a/README.md) R02 PF-4A；[README.md](../evidence/l4-cloud-20261123/README.md) PF-4A。

<a id="card-06"></a>

### 卡 06｜排板移 10 mm，格線也跟著移（R02：來源連動與可讀表）

**前置：**直接開現成 [pf4a.gcanvas](../evidence/l4-cloud-20261123/main-ea16e3f5/pf4a.gcanvas)；它已含主格、鋪排原點是 0。

1. 進原面，開「屬性 → 面設定… → 完成面／骨架… → 完成面與鋪排」。
2. 鋪排原點 u 從 0 改 10，再預覽；主格的 u 軸基準座標應由 **101 變 111**。
3. 按取消，重開表單，原點仍為 0、基準仍為 101。
4. 再改成 10、預覽並確認，重開應為 111，仍是同一個「來源主格 #1」。
5. 可再把原點暫改為 3146 並預覽；**3247** 應完整可讀，最後取消這次修改。

**不通過：**取消改掉來源、格線不跟著排板變、偷偷多出另一份主格，或四位數被拆開難以閱讀。這張表在桌面及390px已有L4；R03骨架的表是另一張，不能因此認定它也修好了。

### 卡 07｜把「面材加縫」平均分成小格（R14）

**前置**：新專案，先建網格來源：u 選「面材＋縫」，面材長 915 mm、縫寬 2 mm；v 間距 400 mm，確認正式來源。**需新增** `docs/examples/l5-panel-grid-ready.gcanvas` 保存於尚未加子規則；現成 [r14.gcanvas](../evidence/l4-cloud-20261114/r14.gcanvas) 是已有子規則的結果對照。

1. 開網格來源 →「新增子規則」，u 填 7、v 填 2，預覽。
2. 應寫每一主格分成 14 個 **131×200 mm** 小格；先取消，原網格不應新增子線。
3. 再填相同值、預覽並確認；點格子 (0,0)，應看到 7 條子線。
4. 編輯規則把 u 改成 6 再預覽：不能精確等分，確認應停用；取消回到原來的分格。

**看到什麼才通過**：按整個面材加縫的尺寸等分，不能整分時明確拒絕。**不通過**：偷偷取整、取消也改了格線，或原有子線不見。
**範圍**：只是一層、無錯縫的來源子規則；不代表已有多層或任意區域分格。
**依據：**[README.md](../evidence/l4-cloud-20261114/README.md) R14 與補核。

### 卡 08｜只改這一面的縫寬，重開要看得到（D09）

**前置：** 新專案；桌機先驗，手機另走同卡。入口有內建範例，不需另造材料檔。

1. 「檔案 → 範例 → 試用工程規格現成專案…」，進「工程規格」的「套用至面」。
2. 「本面覆寫與恢復沿用」裡，縫寬選「改成本面數值」，填 4，再「預覽套用」；應列一個面、一個網格，縫寬 3→4。
3. 「返回修改」後再預覽；勾選核對，按「確認套用」。
4. 關閉後從「檔案 → 工程規格 · 面材與角材」重開；應仍顯示「改成本面數值」4。
5. 不改內容再預覽，應顯示「0 項版本或定義變更」並保留覆寫；返回修改。
6. 返回畫布，復原後應回沿用來源，重做後應回 4。

**不通過：** 誤改其他面、重開看成沿用來源、沒改內容卻把覆寫清掉，或復原／重做不同步。**已知：** 390 px 寬度時，先在表單內捲到「本面覆寫與恢復沿用」並展開，還要再向下捲才看得到值；一開始沒看見不能斷言資料丟失，但可以判定這個操作方式不符合使用需要。

依據：[11/21c D09](../evidence/l4-cloud-20261121c/README.md)、[11/23 D09 與補核](../evidence/l4-cloud-20261123/README.md)。手機保存重開可由套用端先開上述「手機覆寫成品」。

### 卡 10｜同一張底圖接著描第二間（D13）

4. 有鍵盤時按 R 切開口，再按 V 回選取；工具列仍能操作。

**看到什麼才通過**：窄畫面能完成相同入口操作，選單沒有被遮住。**不通過**：按不到、選錯工具或進入後無法返回。
**驗收邊界**：一分鐘只抽查常用入口；10 個選項逐一點到、頂列高度、模型庫共用復原的歷史核對分開保留。實體手機鍵盤與觸控另記。
**依據：**[README.md](../evidence/l4-cloud-20261121c/README.md) R16。

### 卡 54｜遇到怪畫面，直接指出位置回報（D05）

**前置：** 驗收專案；套用端已把測試回報與正式使用者回報分開，並能讀回紀錄。這張卡的回報文字標「驗收測試」。

1. 按 F8，填「驗收測試：取消不應送出」，按「指出位置」再點「復原」，然後「取消」。
2. 按右下「回報」，填「驗收測試：請核對這個保存按鈕」，「指出位置」後點「保存」。
3. 按 Ctrl+Enter；等待「已記錄回報」及一個回報編號，請套用端讀回同一句說明與所指按鈕。
4. 按 Shift+F8；應出現「已快速標記」及另一個編號。套用端應共讀到兩筆，取消那筆不在其中。
5. 回到畫布，房間與角材應完全沒被這些回報操作改動。

**不通過：** 只有一直「記錄中…」或「寫入失敗」卻被當成功、取消仍送出、指出的按鈕錯了、套用端找不到已顯示成功的回報。回報不是場景物件，不以復原／另存判定其保存。

依據：[11/21c D05](../evidence/l4-cloud-20261121c/README.md)；成功提示已另核目前 [feedback.js](../geometry-web/feedback.js)。L4 原始收據抓到的當下提示仍是「記錄中…」，真正記錄成功由目錄與 CLI 讀回證明，不能拿該瞬間提示當成功截圖。

### 卡 55｜看條文、看圖，留一則批註（D01）

**前置：** 驗收用閱讀器分頁；保留現有批註，先記下筆數。

1. App「檔案 → 文件 · 規格與案例閱讀」，點「公理層 · 正典閱讀器」。
2. 左欄點 D2，應看到條文及右欄的見證圖；點條號連結 D6c，應開「參照條文」。
3. 點「＋ 批註這段」，寫「驗收測試」，按「稍後再寫」；已保存批註數應不增加。
4. 再寫一次並「儲存批註」；筆數應增加一，內容看得到。

**不通過：** 入口開錯文件、看不到圖／參照、取消也保存、保存後恢復不了。這張卡不驗匯出或手機版。

## 共通保存卡｜換一次開檔，成果還在嗎

**前置：**選有完整專案保存紀錄的卡，記下房間、支數、參數、底圖、草稿、模型或方案等本次成果；先處理尚未確認的預覽。**回報與閱讀器批註不隨 .gcanvas 保存，依各自卡片驗；CSV／模型匯出檔也是獨立下載。**這是另一次短驗收，不含前卡的一分鐘；不以這張卡推廣到未操作的功能。

**不通過：**保存失敗、少內容、資料變成別的值、沒有再次確認卻重複生成。冷開後的復原歷史不在這張卡的承諾範圍；請勿用「復原」猜測能回到上次關閉前的未生成起點。

## 給套用端：核對與登帳

這份文件依固定基底的需求帳與既有實機紀錄整理，未重新執行整套 App 操作。證據日期不同；舊紀錄的通過不等於本次已重測。請先確認目前 App 版本、開檔結果及各卡入口，再交給使用者。

### 範例準備原則

- 「現成」表示檔案已在固定基底內找到；「需新增」表示本次只交準備規格，尚未附上該檔，也不是 repo 已有檔。由套用端使用現行 App 備好，再把實際檔案與卡片對齊。
- 完整專案用「檔案 → 開啟專案…」開 `.gcanvas`；`.scene` 走「開啟場景檔…」；PDF／圖片走卡片指定的底圖匯入。三者用途不同。
- 需要確認前狀態的卡，須另存新的準備檔。不要假設另存的成品帶有先前復原歷史，也不要直接編輯壓縮檔內容來製造起點。
- 每個起點都要留下：基底版本、檔名、進入哪個面、已完成哪些設定、尚未按哪個確認鈕，以及預期結果。已確認與未確認檔名分開。
- 幾何推導與合法性仍依 [公理層](../公理層.md)。本導覽不新增推導規則；例中的支數、尺寸、片數只用於指定範例，不推廣成其他房型的答案。
- 手機寬度的雲端測試與實體手機不同。觸控、中文輸入法及作業系統的檔案對話框，只有使用者在其實際環境操作並確認後，才能記入相應驗收。

### 本次未確認、需在真 App 核對

1. 所有卡在目前 App 的入口與選單位置；歷史證據的按鈕可能改名。本稿已靜態核對面內現行入口是「面設定… → 完成面／骨架…」，表單才叫「完成面與鋪排」。
2. 附錄列為「需新增」的確認前檔，是否能經一般入口建立、保存並重新開啟；所有現成歷史專案在目前版本的相容性、目前面與欄位初值。
3. 使用者實際速度、閱讀負擔與一步內的點擊數。若某卡超過一分鐘，縮小操作目標或拆成兩次；不刪掉判斷是否成功所需的步驟。
4. R22 復原提示修正已合入 main，但本次未在這個基底重走三種來源流程。若仍顯示舊提示，當作回歸問題記錄。
