**凹角處的表示法(2026-10-16 P-145)**:
- 原本〈與主支平行的 RC 面一律沿線延伸到兩端牆〉,在外牆凹角處會穿過凹角。原生核心對這種排法一律拒絕:沿牆料超出它貼的外牆,報 `V_EXTENSION`;另一面的邊界材端面頂到它,報 `V_CUT_PRIORITY`。使用者的 F1 客廳(L 形)與 F2 主臥(壁柱)都受影響。探針見 #240。
- 核心 I22 接受的唯一排法(I19 的部分見下面 2026-10-18 補正):沿牆料停在牆端;凹角另一面的邊界材越過凹角延伸,停在路上第一支角材的側面;沿牆料的端面頂在這段延伸上。核心 I22 明定延伸段的端面「可以頂任何優先級的側面」,所以停在主支、沿牆料或另一支邊界材(例如壁龕口兩側的牆段端對端接起來)都合法;R19(e) 的「停在長主支側面」是其中一例,不是唯一。C8 只要求延伸段端面頂到角材或牆,而延伸段不能穿過角材(C1),所以停的必然是路上第一支。

## 引文檢查(quote_check.py)的已知限制

**quote_check 是輔助,不是保證**:它只擋得住 `quote_check.py` 檔頭與 selftest 的反例列出的寫法,擋不住有意繞過的人;使用者原話的把關最後仍靠審查看佇列與這些文件的 diff。查不到的寫法:
- 真的原話配上錯的時間或出處:只要逐字出現在決策佇列任一行使用者原話,就過,不驗是哪一天哪一題說的。
- **佇列自我引用**:比對的是受測這棵樹自己的決策佇列,同一個 PR 往佇列加一行使用者原話,就能讓引文過關。要擋得比對 merge-base 那一份,但 merge-base 取決於 remote ref,在 WSL 的乾淨 clone 裡不可靠(這正是 cd4da2fd 誤判的原因),本版不做,靠審查看佇列的 diff。
- 沒有任何標記詞、也沒有引號的轉述;標記詞離引號太遠(超過檔頭列的夾法,又不在同一行或上一行);其他語言的標記詞。
- 沒列入的括號與引號形狀(例如 ‹ ›、零寬字元夾在引號字元中間)、圖片與截圖裡的字、程式碼區塊裡的字。
- .py 檔的 ASCII 引號是程式字串,不認(只有緊接在標記詞後面時報錯)。
- 只有一段的引文至少 4 個字(不計空白):2、3 個字的詞不能用引號引,會報錯,即使它真的出現在某行原話裡(第 21 輪,#251 審查 92e64028:這種引文在好幾行原話裡都找得到,逐字比對形同虛設;反例在 `quote_check.py` 的 SAMPLES 最後三筆)。README、PROPOSAL、程式註解裡原本有 6 處把 2 字的詞當引文用(各處的〈一律〉5 處、〈副支〉1 處;兩個詞都出現在使用者原話裡),已改標〈〉,同一行上較長的真引文照舊逐字檢查。要引使用者的話請引更長的一段,要提一個詞請用〈〉(那不是使用者的話)。反過來,4 個字以上的常見片語只要出現在任一行原話裡就過,不驗上下文。
已補的繞法(反例都在 `quote_check.py` 的 SAMPLES,selftest 會跑):標記詞和引號之間夾全形空白、tab、nbsp、零寬字元、連接詞、破折號;全形雙引號;q 標籤;.py 的 \u、\U、\N{名稱}、\x 跳脫。
