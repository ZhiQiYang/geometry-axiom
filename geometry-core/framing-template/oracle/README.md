# 下角材幾何 oracle(平釘天花,第一版)

這是下角材模式(#205、#221)的**可執行幾何參考**,由 Claude 依使用者講明的物理目標推演並寫成程式。規則不再只靠文字描述:每一支角材的座標由 `framing_oracle.py` 算出。
- 實作(核心、模板、介面,不論哪個 AI 寫的)對 `rooms.json` 的房間與參數,要逐支產生與 `oracle-golden.json` 相同的角材。
- 8 種排法的「可施工/衝突」判定也要一致。

## 依據與授權

- 物理目標:使用者 2026-10-15 講明的原則,原話見 `決策佇列.md`「2026-10-12～15 使用者後續拍板」第 16 項。
- 同一處也記載使用者的要求:這類細節由協調 agent 依物理目標自行推導,不再反覆詢問使用者。
- `PROPOSAL.md` 原本列為「待使用者決定」的幾何題(窄收邊挪縫、沒有板端縫的錨點、第一條縫挪動、凹口主支),依此改為由本 oracle 推出,現行答案見 PROPOSAL §2.0「現行規則」。
- 存檔表示法等不影響幾何的題目,仍屬實作細節。

核心可表示(不是使用者的規則,是 SSOT 的限制):C8(I22、I19 boundary 端面、I19 數值比較、R6(d) 恰一個擋面、主支不頂延伸段);突變 rc_through_reflex、no_end_push、no_custom4。

## 物理目標與檢查

| 編號 | 目標 | 程式怎麼做 | 自動檢查 |
|---|---|---|---|
| G1 | 面材每條邊都有支撐 | 板縫下放主支、板端縫下放副支、RC 邊放邊界角材;短於 `min_piece` 的副支不放(R-nosliver) | C3:每條面材邊內側 X mm 的帶子都在角材上;唯一例外是板邊沿邊方向跨過 < `min_piece` 的窄縫,那一小段由縫兩邊的料承接。C10:沒有短於 `min_piece` 的副支 |
| G2 | 副支間距不超過上限 M,各格盡量一致 | 每格 n=⌈L/M⌉、m=⌈L/n⌉;從板端縫起算,餘數放最後一格;沒有板端縫時從起鋪牆起算 | C4:角材之間的空檔 ≤ M−w |
| G3 | 主支連續傳到 RC | 主支線碰到壁柱或獨立柱就分段,每段兩端接 RC(外牆與壁柱停在邊界材側面,獨立柱停在柱面);只禁止在室內中間斷開。離相鄰平行料只差幾 mm 時平移貼住(R-butt) | C5:縫線上沒有缺口,每段端面接 RC 或外牆邊界材;C11:能貼住卻沒貼住 |
| G4 | RC 邊界都有角材,端面只頂角材 | RC 邊放角材;與主支平行的柱面,角材沿線延伸到兩端牆;外牆在凹角處停在牆端,由另一面的邊界材越過凹角延伸,停在路上第一支角材的側面;端面頂到 custom 3 的副支宣告 custom 4 | C6:主支與副支的兩端都頂在角材上;C8:核心可表示(I22 非 boundary 不超出外牆、I19 boundary 端面、I19 數值比較、主支不頂延伸段) |
| G5 | 不碰撞、不入 RC | 任何正面積重疊都不允許。先調整:主支在承接容許量內平移(超過就加併料)、記號副支拿掉或整排加密、縫上副支挪到貼著 RC 角材;都放不下才判衝突並寫明原因 | C1、C2 |
| G6 | 從起鋪角整片鋪,只在對牆收邊,不置中 | 縫距 = 板寬+縫;首縫向內距離正向 P+⌊縫/2⌋、反向 P+⌈縫/2⌉(提案 FT01),所以縫在世界座標都佔 [c−⌊縫/2⌋, c+⌈縫/2⌉] | C7:縫位等於獨立推算的起鋪結果 |
| G7 | 最後一條縫太靠近對牆時往內挪 | d > D−1.5w 時挪到 ⌊D−1.5w⌋,留約 40 mm 收邊板;第一條縫也一樣 | C7 |

**檢查與建構的獨立性**:
- C7 用另寫的 `expected_seam_positions` 推算縫位,不呼叫建構用的 `seam_centers`。
- C3、C4、C5 的面材格子也用這組獨立縫位,不拿建構輸出當「期望」。
- 所以「整組錯移、但彼此自洽」的幾何會被抓到,見突變 `shift_origin`。

不處理:樑高度、交丁、角材怎麼固定(與幾何無關)。

**凹角處的表示法(2026-10-16 P-145)**:
- 原本「與主支平行的 RC 面一律沿線延伸到兩端牆」,在外牆凹角處會穿過凹角。原生核心對這種排法一律拒絕:沿牆料超出它貼的外牆,報 `V_EXTENSION`;另一面的邊界材端面頂到它,報 `V_CUT_PRIORITY`。使用者的 F1 客廳(L 形)與 F2 主臥(壁柱)都受影響。探針見 #240。
- 核心 I22 接受的唯一排法(I19 的部分見下面 2026-10-18 補正):沿牆料停在牆端;凹角另一面的邊界材越過凹角延伸,停在路上第一支角材的側面;沿牆料的端面頂在這段延伸上。核心 I22 明定延伸段的端面「可以頂任何優先級的側面」,所以停在主支、沿牆料或另一支邊界材(例如壁龕口兩側的牆段端對端接起來)都合法;R19(e) 的「停在長主支側面」是其中一例,不是唯一。C8 只要求延伸段端面頂到角材或牆,而延伸段不能穿過角材(C1),所以停的必然是路上第一支。
- 這支沿牆料在核心的角色是 `custom`、優先級 3,golden 標成 `rc_parallel:custom`。主支若跨在凹角牆線上、端面有一部分落在延伸段上,先把主支推進牆段內(超過承接容許量就加併料);推不進去才標 `CORE_LIMIT_MAIN_ON_EXTENSION`,那是核心表示法的限制,不是物理衝突。
- 兩種排法都滿足 G1–G7。核心這種用料較少:F1 那兩支約 4.0 m,舊排法約 6.5 m;F2 壁柱面從 3.5 m 縮到 0.4 m 加兩段約 0.6 m 的延伸。所以照 SSOT 對齊,不改條文。
- **2026-10-18 補正**:上面說「核心接受」時,C8 只驗了 I22 與 boundary 端面,漏了 I19 的數值比較。端面頂在這支沿牆料(或併料)上的副支是 secondary / 3,頂 custom / 3 不合 I19(3 不嚴格小於 3),原生核心以 `V_CUT_PRIORITY` 拒絕(#297 探針實跑 24 支,另 40 支被容量上限遮住)。
  - 使用者 2026-10-18 拍板(決策佇列,選項 C):這些副支改宣告 custom / 4,條文不改。golden 標 `:custom4`。
  - C8_I19_PRIORITY 補上這條比較;突變 `no_custom4` 證明它抓得到那 14 種排法。
  - custom 4 在原生核心是否真的接受,本 oracle 沒有實跑(只用純 Python,沒有用 WSL)。



## 檔案

- `framing_oracle.py`:建構與檢查。建構時遇到碰撞,就把該排法判成「衝突」並寫明原因;檢查失敗代表程式本身有錯。
- `rooms.json`:F1–F5 五個房間與參數:915×1830 板、縫 2、角材寬 27、上限 367、承接 8、最短料長 `min_piece` 27(R-nosliver;預設 = 角材寬,**終值待使用者確認**)。
- `oracle-golden.json`:凍結的標準答案,涵蓋 F1–F5 與三個額外例子(挪縫的 3700×2000、940×2000,縫寬 3 的 3700×4000)、各 8 種排法,含逐支角材的種類與矩形。
  - 由 `make_golden.py` 產生。凍結前已人工核對圖,也與 PROPOSAL §4 手算的數字對過:F3 主支 6036/6953/7870/8787、板端縫 5551、記號 4083/4450/4817/5184;F5 右上 Y 的主支平移 −8 mm 到 [1346,1373] 貼著柱料(P-147,原本判碰撞);3700 寬挪到 3659。
  - 只能在人工覆核之後重產,並在 PR 寫明改了什麼。
  - 2026-10-18 重產(R-butt、R-nosliver、副支 custom 4):24 個排法有變,全部 3093 支 → 2957 支。
    - 例 3700×2000、940×2000、縫寬 3 的 3700×4000 的右上/右下板長沿 Y,以及 F5 左下/右下板長沿 X:主支平移 1–2 mm 貼住沿牆料或沿柱料,原本縫裡 1–2 mm 長的 59 支料(含 4 支 2 mm 柱面料)不再出現。
    - F1 板長沿 Y 四種:沿柱料與主支之間 9–10 mm 的縫不放副支(53 支);F5 左上/右上板長沿 X:23 mm 的縫不放副支與柱面料(19 支)。
    - F1 左下板長沿 Y:那條 10 mm 縫原本把板端縫 2969 的副支位置連成一串、逼最後一格記號加密(n=6);縫不放料之後回到 n=5、副支置中。
    - F1 八種、F2 六種排法共 63 支副支改標 `:custom4`。#297 分析數到 64 支,少的那 1 支就是 F1 左下板長沿 Y 最後一格記號從 5 支變 4 支。
- `selftest.py`:
  1. 22 種突變(共 27 筆),各自都必須被對應的檢查抓到:拿掉挪縫、起鋪點整組錯移、格數無條件捨去、少一支副支、柱邊不放角材、主支偏 15 mm、允許主支被切斷;凹角兩個:`rc_through_reflex`(舊排法)必須被 C8 抓到,`no_boundary_extension` 必須被 C6 抓到;`no_r_butt` 必須被 C11 抓到,`allow_short_pieces` 必須被 C10 抓到,`nosliver_too_wide` 必須被 C3/C4 抓到,`no_custom4` 必須被 C8_I19_PRIORITY 抓到,而且 F1、F2 的那 14 種排法一個不多一個不少。未突變的對照組(F1、F2、F3、F5)必須全綠。
  1b. 凹角掃描:L 形、壁龕與獨立柱房 579 間 × 8 種排法;另有奇數縫寬(1、3)矩形房 1872 次,可施工的排法都要通過全部檢查(含 C8)。
  2. 標準答案逐支比對。
  3. 矩形房掃描(涵蓋範圍見檔頭說明):
     - 快速(預設):約 2.4 萬次建構,約 1–2 分鐘(2026-10-18 加了 C8_I19_PRIORITY 等檢查後單次約慢 25%;機器忙時以 nice 19 跑過 6 分半)。一維逐 mm 掃描只跑一種排法;二維取樣跑 8 種排法,集中在挪縫的臨界帶。
     - 完整(`--full`):一維也跑 8 種排法,二維取整段邊界帶。
- `render.py`:畫成 HTML,每個房間 8 種起鋪角與板長方向。

## 執行

```
python selftest.py            # 快速
python selftest.py --full     # 完整
python make_golden.py rooms.json oracle-golden.json   # 只在人工覆核後重產
python render.py rooms.json framing-oracle.html
python framing_oracle.py rooms.json > framing-oracle.json
```
