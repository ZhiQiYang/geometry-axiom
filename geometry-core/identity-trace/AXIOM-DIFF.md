### A1. 新增定義（第 542 行之後、第 544 行「## 二」之前）

```text

**D⟨K3-1⟩ 物件身分帳（IdentityLedger；identity-ledger/1）**：World 可啟用身分帳。啟用後，每個受涵蓋物件帶一個存在期記號（incarnation，下稱記號），
回答「此刻這個物件是不是當初那一個」。記號不參與任何幾何推導與驗證，也不進入 geometry-hash 或內容指紋（D⟨K3-4⟩）。
受涵蓋物件與其身分鍵（第一版）：邊界面 (boundary, id)、承載面 (placement, id)、RC 柱 (column, id)、RC 樑 (beam, id)、
角材 (timber, id)、參數卡 (parameter, id)、參數欄位 (parameter-field, parameterId, fieldId)。柱與樑雖共用數值 id 空間（R12），身分鍵含類別，互不混用。
屬於 D34 組構實例所有權對應的角材不受涵蓋：其分件身分依 instance／member（D34），不依角材 id，以角材 id 判定其存在期會與 D34 矛盾。
是否受涵蓋依各次提交後的狀態判定；角材由普通變為組構所有，視同其存在期結束，反之視同新存在期。
其他型別不帶記號，其延續一律未知（R⟨K3-2⟩），不得以同編號、同名稱或同內容推定延續。
記號寫成 `E:s`：E 為配號區段（D⟨K3-3⟩），32 位小寫十六進位；s 為十進位正整數，至多 2^64−1，無前導零。記號只做整串相等比較，大小與先後沒有意義。
一個記號終生只屬於一個身分鍵；同一 World 內任兩物件的記號不同。
記號與內容是兩條獨立的軸：定義逐位元相同不證明是同一存在期（分次刪除重建可得相同定義），記號相同也不表示內容未變。

**D⟨K3-2⟩ 存在期的開始、延續與結束**：存在期依一次提交（R⟨K3-1⟩）的結果判定。提交後的狀態都能被 World 外的紀錄觀察；同一提交裡面的中間狀態不能。
明示刪除：提交中任何操作使某受涵蓋物件不存在，即為對該物件的明示刪除，不論那一步屬於哪一種交易，也不論提交結束時同鍵是否又出現。
一次提交若明示刪除某受涵蓋物件，該鍵的舊存在期結束，舊記號離開。提交結束時同鍵仍受涵蓋的，是新存在期，配發新記號，不沿用舊記號；不依「前後鍵集合碰巧相同」例外。
例如：刪除整張參數卡片時，不論該操作出現在哪一種交易中，該卡片與其全部欄位一起結束；刪除承載面時，該承載面的存在期結束。
正式契約列出會造成明示刪除的操作名稱；新增這類操作須一併登記。
除此之外，同一提交前後都受涵蓋 → 存在期延續，記號不變；只在提交後受涵蓋 → 新存在期；只在提交前受涵蓋 → 存在期結束。
重宣告（I8：同 id 再宣告）是就地修改，不使物件不存在，不是明示刪除；它與改值、改來源、改名、移動卡片、R13 改掛、R8 拆分後保留原 id 的那一片，都是延續（該提交另有操作明示刪除該鍵者除外）。
歷史群組內的每一行各是一次提交：在群組中先刪除、後建立同鍵，是兩個存在期；分兩筆指令的刪除與建立亦同，即使定義逐位元相同。
參數欄位以 (parameterId, fieldId) 為鍵（D31）：卡片重宣告保留的 fieldId 延續，重宣告不再包含的 fieldId 結束（對該欄位是明示刪除），新出現者為新存在期。刪除整張卡片時其欄位一併結束；同一提交再以同 fieldId 建立的欄位是新存在期。
R8 拆出的新片、匯入的新卡片均為新存在期，不繼承任何既有記號，即使匯入後的卡片 id 與剛刪除的卡片相同。本層不記錄「由誰拆出／複製」的衍生關係。
復原／重做不是提交：它恢復當時的完整 World，連同當時的身分帳狀態與記號；復原一次刪除，物件以原記號回來。

**D⟨K3-3⟩ 配號區段與序號**：區段 E 由執行器的宿主以密碼學亂數產生並設定；核心不自行產生區段。
執行器行程啟動時，以及每次整體取代 World 之後，區段為未設定。
整體取代是換掉整個正式 World，不是提交。第一版包含：開新（同時清除復原歷史者）、恢復內建場景、載入場景檔、確認一筆已準備的場景匯入、恢復資料、載入方案快照。
載入場景檔與確認場景匯入可以復原；開新與恢復內建場景清除復原歷史。可以復原的整體取代，復原只還原當時的 World 與記號，不還原被清掉的區段。
互動輸入的清空指令不是整體取代：它在復原歷史中記一步，是一次提交（R⟨K3-1⟩）。提交後 World 為空，原有受涵蓋物件的存在期全部結束；身分帳的啟用狀態不變（取自該指令前的 World；已啟用者仍啟用），區段不清除。
宿主須設定一個新區段，且它不得已出現在目前 World 的任何記號中。任何宿主（含測試）不得重用區段。
序號 s 由行程內單一計數器提供，從 1 起只增不減，換區段也不重新起算；復原、重做、取消、失敗、過期與預覽都不使它倒退、回收或前進，只有成功的提交取號；
歷史群組失敗而整組還原時，群組內已取的序號不歸還。序號可有空號，空號不代表任何物件。
設定區段與 undo/redo 同為 session 層指令，不進場景檔，也不進復原歷史。
不同行程之間的記號不重複，只依賴區段為 128 位元密碼學亂數這一前提；本層不以時間、名稱或內容補強或替代。

**D⟨K3-4⟩ 身分引用（IdentityPin）與內容指紋**：World 之外的紀錄——已保存模型的來源身分紀錄、圖面證據、預覽候選、介面快取——
要宣稱「指的就是那一個物件」，須同時保存身分鍵與記號；只有 kind/id 只能宣稱同編號。
內容指紋只回答「內容是否相同」，不回答是不是同一個存在期。它分兩種，彼此獨立，也都不讀取記號：
    定義內容指紋，由該物件的定義算出；有效值內容指紋，由依定義推導出的有效值算出。
公理不規定演算法、編碼或欄位名。只有內容指紋相同，只能宣稱同內容。
World 內部的引用（ParameterRef、at-line、at-face、空間成員、配置所引用的邊界等）仍只以 id 引用，不加記號；
被引用者在 World 內不得被刪除（I7a、I23、I37、I38、I49 等）；本擴充不改這些刪除保護，也不另訂例外。
同一提交明示刪除後又以同鍵建立的物件是新存在期（D⟨K3-2⟩）；World 外的身分引用對它依 R⟨K3-2⟩ 判為 replaced，不會被當成延續。
身分帳屬於單一專案。記號不跨專案，不寫入任何交換格式，包含 D25 交換包、參數包、模型來源快照、匯出的場景文字與回報附件。
跨專案匯入不攜帶記號；匯入後新出現的身分鍵一律新配，不得沿用來源記號。不同專案之間不以記號相同宣稱同一物件。
同一份專案經複製或分支後，複製當下已存在的記號是兩邊共享的存在期；其後各自新配的記號不相同（D⟨K3-3⟩）。
```

I⟨K3-1⟩ 身分帳完整性：身分帳啟用的 World，在每次提交後與每次載入完成時必須同時成立：
    (a) 每個受涵蓋物件恰有一個記號；(b) 沒有屬於不存在或不受涵蓋物件的記號；(c) 記號兩兩不同；(d) 記號格式符合 D⟨K3-1⟩。
    任一不成立：提交整筆回滾、載入整份拒絕，World 留在原狀態；不得以補發、刪除或改寫記號使其成立。
    (e) 會寫出記號的 dump 與完整專案保存，輸出前再驗 (a)–(d)。不成立即拒絕輸出，並指出缺記號或多餘記號的身分鍵，不寫出任何重開時會被拒絕的場景或專案。
    恢復只有復原到上一個通過 (a)–(d) 的提交。不補發、不改寫、不刪除記號來通過。沒有可復原的提交時，完整保存保持拒絕。
    去身分 dump 不因 (e) 拒絕：它不含記號，載入結果是未啟用的 World，不會因缺記號被拒。輸出須另附診斷，註明身分帳不完整、此輸出不能還原記號。
    未啟用的 World 不含任何記號；其建立、驗證、dump 與一切內容指紋與本擴充前逐位元相同。
I⟨K3-2⟩ 配號與啟用守門：需要配發新記號的提交，在區段未設定時整筆拒絕（診斷指明「未設定配號區段」），World 不變；

    同一次提交配發多個記號時依固定順序取號：boundary、placement、column、beam、timber、parameter、parameter-field；
    同類依 id 遞增，欄位依 (parameterId, fieldId) 遞增。
    啟用以互動指令 `identity-ledger activate` 為之：須已設定區段、身分帳尚未啟用，且必須是單獨一筆提交，不得在歷史群組或候選交易內；
    在該提交內依上述順序為全部現存受涵蓋物件配發記號，可復原。重複啟用拒絕；本版不提供停用，復原啟用那一步即回到未啟用的 World。
    啟用雖不改任何定義，仍使所有未確認的預覽過期（I8a）。啟用時配發的記號只證明自啟用起的延續；啟用前的沿革一律未知。
    記號只能由核心配發或自場景檔載入：互動輸入的 `identity` 宣告行一律拒絕；場景檔中出現 `identity-ledger activate` 亦拒絕。
I⟨K3-3⟩ 身分帳保存與能力：新增能力 `identity-ledger/1`，依 I32 宣告。啟用的 World 在場景與完整專案中保存全部記號：
    場景以 `requires identity-ledger/1` 宣告，於全部定義與 canvas-pos 之後逐一輸出 `identity <kind> <id> [<fieldId>] <E:s>`（I9：先有物件，後有記號）。
    載入只還原記號、不配發：缺少、多出、重複、格式錯誤、有記號行而無 requires、或有 requires 而受涵蓋物件缺記號，均整份拒絕（I⟨K3-1⟩）；
    執行器不支援本能力時依 I32 拒絕，不得略過記號行當作舊格式，刪去 requires 也不能使其通過。
    完整專案重開保留原記號；參數包匯入的卡片與欄位是新存在期，於匯入提交時配發（I39）。
    去身分 dump：不含 `requires identity-ledger/1` 與任何 `identity` 行的 dump，必與同一 World 未啟用時的 dump 逐位元相同。
    凡計算內容指紋或定義摘要、保存為模型來源快照、匯出場景文字、寫入回報、或交給幾何的隔離求值（建模執行器、規則案例等），一律使用去身分 dump；
    其結果與未啟用時相同，且不得宣稱任何身分延續。只讀的來源檢查可另外讀取記號供 R⟨K3-2⟩ 比對。
    核對完整專案或其方案快照本身的程序（例如方案的隔離驗證）讀取該專案保存的完整場景，不在上列；其結果只用於核對該專案，不得寫入交換格式或模型來源快照。

### A3. 新增推演規則（第 1141 行之後、第 1143 行「## 四」之前）

```text

R⟨K3-1⟩ 提交時的身分結算：提交是成功改變既有正式 World 的一筆。包含：互動單行（含互動清空；復原、重做、純 canvas-pos、預覽與取消預覽、歷史群組的開始、結束與中止除外）、
    歷史群組內的每一行、拖曳、各類預覽確認（場景匯入的確認除外）、加入既有 World 的匯入確認、啟用。
    整體取代不是提交（D⟨K3-3⟩）。歷史群組的結束不是提交，群組失敗的整組還原也不是。每次提交在全量重驗通過後依序：
    (a) 除啟用外，提交結果的身分帳狀態（啟用與否、既有記號）取自該指令執行前的 World，不取自候選；候選世界本身不決定記號；
    (b) 取得該提交中的明示刪除（D⟨K3-2⟩），再比較前後的受涵蓋身分鍵，依 D⟨K3-2⟩ 延續、配發（I⟨K3-2⟩ 的順序）或結束。
        確認預覽而提交時，若確認不重新執行候選的操作而直接採用預覽候選，明示刪除取自產生該候選的那次預覽所執行的操作，隨候選保存；
        候選被取消、過期或取代時一併作廢；
    (c) 驗 I⟨K3-1⟩。失敗時與其他驗證失敗同一條路：不在歷史群組內，以該指令前的 World 整筆還原；
        在歷史群組內，一律依群組語意整組回到群組開始前，不是只回到該行之前。已取的序號都不歸還。
    每個指令只結算一次，結算發生在指令層級，不由個別變更步驟各自結算。一批預覽確認是一次提交，批內的步驟不是各自一次提交。
    是否「改變既有正式 World」以結算後的 World（含身分帳）判定，延續的鍵必須保留原記號：定義與身分帳都不變的確認不是提交，不記歷史、不取號；
    明示刪除後同鍵重建的確認，即使定義逐位元相同，也因記號不同而是提交。
    整體取代的身分帳狀態與記號取自取代後的內容（開新與恢復內建場景為未啟用；其餘取自該外部資料，I⟨K3-3⟩）。
    預覽不配發記號；取消、失敗與過期的預覽不改變配號器。只啟用身分帳的提交不改定義，但依 I8a 仍使未確認的預覽過期。有未確認預覽不是拒絕啟用的理由。
R⟨K3-2⟩ 身分比對：持有身分引用（D⟨K3-4⟩）者對目前 World 逐項判定，依下列順序取第一個成立者，結果唯一：
    (1) unknown：引用沒有記號（身分帳啟用前建立），或目前 World 未啟用身分帳；
    (2) conflict：引用的記號出現在目前 World 的另一個身分鍵上（違反 D⟨K3-1⟩，視同資料毀損）；
    (3) absent：該身分鍵目前不受涵蓋（已刪除、已成為組構所有，或因復原回到建立之前）；
    (4) replaced：該身分鍵受涵蓋，但記號不同（同編號的另一個存在期）；
    (5) continuous：記號相同。
    continuous 只證明身分延續；內容是否改變另以該物件的定義內容指紋與有效值內容指紋（D⟨K3-4⟩）比對，兩者分別呈現。
    其餘四態都不得自動改指任何物件，不得以同名、同編號或同內容補救，只能由使用者明選重新關聯。
    預覽或確認流程保存了身分引用時，確認前重新比對；任一項結果改變即預覽過期（I8a），不提交。
R⟨K3-3⟩ 外部觀察值的採用：World 外紀錄中的觀察值（圖面標值、現場量測）不是定義（D9）；建立關聯、勾選核對都不改 World。
    把觀察值變成模型值，只能對 R⟨K3-2⟩ 判為 continuous 的目標，以修改其定義的一般交易進行（例如 D31 欄位修改）：
    依 I8a 先預覽候選（含全部幾何依賴重算與違規），確認同一候選後提交；不得繞過預覽，不得以近似、截斷或取整通過（D1、I38）。
    觀察值須帶明確單位並可精確解析為目標欄位的值；mm 以外的長度單位依精確倍數換算。單位不明時拒絕採用，不假設為 mm（R3）。
    採用不改觀察值本身，也不在 World 外保存第二份可獨立修改的模型值。
```
