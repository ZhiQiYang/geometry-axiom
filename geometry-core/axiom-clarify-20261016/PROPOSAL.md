- **相位差(交丁、stagger)**:網格某一軸上，奇數格的線整體平移一個距離，偶數格不動；像磚牆的錯縫。
- **band**:相位差所依的「另一軸」的格子編號(帶正負號)。
- **cell**:兩軸相鄰格線圍成的一個格子。
- **候選**:一次編輯先在隔離的副本裡完整驗證，全過才一次提交；沒過就整筆不生效。
- **提交**:成功改變目前 World 的一筆編輯，例如打一行指令、拖曳、確認預覽(R56)。
- **整體取代**:整個換掉目前 World，不算提交，例如開檔、恢復內建場景、載入方案快照(D61)。
- **World**:目前專案的世界狀態。
- **版本宣告(版本章)**:存檔裡寫明「我是照哪一版規則存的」的那一行或那個欄位。
- **舊檔／新版檔**:沒有版本宣告、或宣告早於「一軸錯開」規則採納版的存檔是舊檔；宣告採納版(含)以後的是新版檔。
- **舊檔標記(貼紙)**:程式在載入舊檔時，替裡面兩軸都錯開的網格貼上的記號；寫成 `legacy-two-stagger`。
- **boundary／primary／secondary／custom**:角材的四種角色。boundary＝邊界材，貼著外輪廓(牆)的邊鋪；primary＝主支，沿主支軸鋪的主骨；secondary＝副支；custom＝自訂料，優先級由使用者寫(D15)。
- **優先級**:數字越小越優先(D15)。外輪廓邊、孔邊、柱面是 0，boundary 是 1，primary 是 2，secondary 是 3。角材的端面只能頂優先級比自己小的東西(I19)。
- **FIXED／FREE 邊**:外輪廓的邊分兩種。FIXED(預設)是固定邊；FREE 是自由邊，端面貼上去等於頂到空氣，會被拒絕(I6)。
- **延伸段**:邊界材超出它所貼那條外輪廓邊的端點、繼續進入面內的那一段(D16)。
- **coversEdge**:角材貼在外輪廓邊上，而且沿長度方向的範圍包含整條邊(R18)。
- **oracle**:照條文逐字寫的可執行小程式，用來算「條文推得出什麼」，不是產品程式。
- **探針**:拿原生核心實跑的幾個場景，看條文在實作上的反應。

## 語法草案:版本宣告與舊檔標記(給你看，看過才實作)

### 用白話講一遍

把存檔想成一張施工圖:
- 新存的每張圖，在角落蓋一個**版本章**，章上寫「這張圖已經照『一軸錯開』的規則畫」。
- **沒蓋章的圖，或章比較舊的圖，就是舊圖。** 舊圖裡如果有兩軸都錯開的網格，照舊可以開、算法不變；程式在開的時候替那份網格貼一張**「舊圖」貼紙**，存回去時貼紙跟著走。
- **蓋了新章的圖**，裡面如果有兩軸都錯開的網格，又沒有貼紙，就整張退件(不開)；你正在編輯的專案不受影響。
- 貼紙**只能在開舊圖時自動貼上**；你自己打指令不能貼。網格被你減成一軸，貼紙就撕掉。
- **已知限制:** 章和貼紙都只是檔案裡的文字。有人手寫一個新章，再手寫一張貼紙，就能放行一份新的兩軸網格。這個辦法只防「不小心」，防不了「故意偽造」。

### 三種存檔，各自的版本章

**1. 場景檔(`.scene`):第一行(註解行除外)寫 `requires scene-format/1`。**
- 這是沿用現有的 `requires` 行機制(現在已有 `requires engineering-spec/1`、`requires parameters/1` 這類)，不是新機制。
- 沒有這一行＝舊檔。以後再有新規則，版本號加一(`scene-format/2`)。
- 例，新存的檔(一軸錯開，合規):

```
requires scene-format/1
surface 1 origin 0 0 2500 u +x v +y outline 0,0 1000,0 1000,1000 0,1000
grid-system 0 name-hex 61 main-along none u repeat 0 100 v repeat 0 100 stagger 50
```

**2. 完整專案(`.gcanvas`):檔頭的 `format` 寫 `geometry-canvas/18`。**
- 目前的做法:專案檔頭有 `"format": "geometry-canvas/N"`，現在最高到 /17，而且程式是看專案內容挑「夠用的最小 N」。
- 草案:**新存的專案一律寫 /18**(不論內容)，裡面內嵌的場景文字照上面的規則以 `requires scene-format/1` 開頭。/17 以下就是舊專案。
- 例:檔頭 `{"format": "geometry-canvas/18", ...}`。
- 要連帶決定:/18 的守門規則比照 /17 另訂一組(程式裡每個格式號都有一組守門規則)。

**3. 交換包(模型交換包 `geometry-model-package/1`):不新增語法。**
- 目前的做法:包裡的 manifest 已經有 `axiom_revision` 和 `axiom_sha256`，記錄「這包是哪一版公理產生的」；程式只認得一張已知版本清單(現行版加上歷代舊版)。
- 草案:採納後，新的那一組版本對就是「新版」，採納前的現行那一組併入舊版清單——程式本來就是這樣管歷代版本的。舊包＝舊檔，新包＝新版檔。包裡的 `base_scene` 是場景文字，依上面場景檔的規則判斷。
- 例:manifest 裡 `"axiom_revision": "<採納後的提交>", "axiom_sha256": "<採納後的雜湊>"`。

### 逐網格系統的「舊圖貼紙」

**寫法:在 `grid-system` 那一行的最後多一個關鍵字 `legacy-two-stagger`。**

例，一份舊檔(沒蓋章，u、v 兩軸都錯開 50)原本長這樣:

```
surface 1 origin 0 0 2500 u +x v +y outline 0,0 1000,0 1000,1000 0,1000
grid-system 0 name-hex 61 main-along none u repeat 0 100 stagger 50 v repeat 0 100 stagger 50
```

程式開它、再存回去，會變成:

```
requires scene-format/1
surface 1 origin 0 0 2500 u +x v +y outline 0,0 1000,0 1000,1000 0,1000
grid-system 0 name-hex 61 main-along none u repeat 0 100 stagger 50 v repeat 0 100 stagger 50 legacy-two-stagger
```

規則:
- 貼紙只能貼在**兩軸都有相位差**的網格系統上；貼在別的系統上，整個檔拒絕。
- 貼紙只由「載入舊檔」自動產生。在新版檔裡手寫貼紙，會被放行(上面說的偽造限制)。
- 在指令列(提交)打 `legacy-two-stagger`，拒絕；提交不得新增貼紙。
- 帶貼紙的網格被提交減成一軸，貼紙隨之消失；之後再加第二軸，會被拒絕。
- 復原回到兩軸，貼紙跟著回來(復原恢復當時完整的 World)。
- 程式區分「載入檔案」和「打指令」的辦法本來就有:場景載入有一個標記變數(`g_parsing_scene_file`)。

例，新版檔裡有兩軸、沒貼紙，**整個檔退件**(訊息為草案):

```
requires scene-format/1
surface 1 origin 0 0 2500 u +x v +y outline 0,0 1000,0 1000,1000 0,1000
grid-system 0 name-hex 61 main-along none u repeat 0 100 stagger 50 v repeat 0 100 stagger 50
```

→ 「D10b／I24:grid-system 0 兩軸都有相位差，但這份檔宣告了 scene-format/1 而該系統沒有 legacy-two-stagger 標記；整個檔未載入，目前專案不變」。
