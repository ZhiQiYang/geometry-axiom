## 1. 要交付的結果

幾何核心可以在完全沒有木工模板的安裝／編譯環境中，獨立處理精確座標、輪廓、框架、格線、參數、來源關係、幾何求值與原子候選交易。木工模板使用這些能力，承接目前全部木工政策、配方、規格與相容轉接。應用在唯一裝配入口明確載入第一個且預設的木工模板，維持現有畫面、操作、接受／拒絕條件與保存結果。

完成不是把 `Timber` 改叫 `Member`，也不是把原引擎整包移到模板、只留下少數算術函式。驗收必須證明模板使用同一個實際產品所用的核心：移除模板後仍能跑幾何、來源與交易測試；另一個極小模板也能只用該 API。

本次不新增模板選擇器、可下載外掛、可編輯政策或另一種場景格式。新模板範例是程式級見證，不是擴充產品介面的授權。既有尚未實作的能力不因本次搬移變成已實作；例如基準 main 的 K1 裁切設定只有規格與測試夾具，不能在本次解耦中順帶新做整套加工功能。

## 2. 規範與程式分成三層

| 層 | 責任 | 可以依賴 | 不能做 |
|---|---|---|---|
| K：通用核心 | 精確算術、具型別幾何與來源、圖、候選求值、範圍／拓撲判式 | 標準庫與同層 API | 認得木工角色、材料名稱、規格常數、木工模組或舊木工語法 |
| W：木工模板 | 角色／支撐政策、材料和做法、有限生成、板背／鋪排、加工、木工資料與呈現字典 | K；宿主提供的中性服務介面 | 重做另一套幾何、繞過候選、先提交後 Undo 假裝原子 |
| H：應用與相容裝配 | 裝配 K/W、既有命令及檔案轉接、完整專案、執行器能力、歷史、工作區與回執 | K 與明示的 W provider | 讓 K 反向 import W、把模板資料藏成未入版本／新鮮度的全域預設 |

規範盤點使用四個標記：K、W、H，以及 M（同一條必須實質拆開）。M 不是第四個 runtime 層，也不能只貼標籤；逐條提案須寫出核心定義、模板契約與相容責任。`公理層.md` 仍是一份整體驗收 SSOT，保留條號；白話與唯一正典閱讀器在批准採納時同步。

核心中的「合法幾何」與模板中的「允許建立某類木工物件」分開。例如兩個矩形正面積交集是核心判式；在哪個物件集合中禁止交集是模板或已定義幾何型別的約束。核心不能自行推定全世界物件互不相交，也不能從 `boundary` 字樣推定可固定。

## 4. 核心必須承擔的實際能力

### 4.1 C 的最小完整邊界

核心公開的是具型別資料與操作，不是讓模板直接操作核心私有陣列。至少涵蓋：

1. D1／I33 所需的整數及精確有理運算、溢位與容量拒絕；框架與可逆座標轉換。
2. 正交輪廓、孔、矩形包含、正面積／正體積相交、線裁切、接觸與區間操作；真正產品中的同一實作。
3. 有限／無限格線、週期中心、奇偶位移、signed 索引、cell、精確子格與來源規則；幾何不讀主副支角色。
4. 具型別定義、來源欄位身分、參數精確求值、依賴閉包、循環／失聯診斷、名稱與身分分開。
5. 通用候選狀態、定義修訂、新鮮度、全量依賴求值、原子提交與回滾；預覽、取消、失敗不消耗正式配號。
6. 中性特徵引用與幾何來源追溯。模板可提供一項「來源量」，核心依型別與固定鍵求值，不能以模板種類字串決定演算法。

模板可實作核心宣告的中性 provider 介面。由 H 註冊並傳入，K 不做名稱查找載入、不含模板 header、不查 `timber`／`primary` 等值。provider 必須在同一候選上求值，不能回頭讀正式 World 或藏有第二套可變狀態。

**程式依賴與定義資料的依賴不是同一件事。** 前者只准 W→K；後者依正式引用圖，可有通用參考線引用模板物件的尺寸／側面，再有模板物件引用該線。只要實際欄位圖無環且同面／同軸等條件成立，這是合法既有行為。K 藉中性的 typed source 介面取得來源量，W 負責發布該量及其完整依賴；不能因架構分層而拒絕這種舊檔，也不能展平成常數。

`reference_rebuild` 現在會依放置序清掉並重建構件，而 guide 又能引用已放構件側面；因此來源量必須帶完整有向依賴與求值順序，不能把 guide 留在 K 卻仍直接迭代木工陣列。R6 的幾何可行區間由 K 計算；W 選合格支撐及優先政策後，在同候選完整重驗。`between` 只替代原有唯一性條件，不能被抽象介面偷偷放寬。

### 4.2 原子交易涵蓋模板狀態

K 的候選和 W 的定義／來源／owned mapping 是同一次候選的兩個部分，由 H 擁有完整快照與提交邊界。H 建立候選時固定 provider 集合與版本，W 只能改自己的候選狀態並呼叫 K API。共同完成完整依賴、領域政策與身分檢查後，才一次替換正式狀態。

失敗時核心幾何、模板定義、配號高水位、發布版本、owned mapping、身分帳與歷史均按原契約恢復；不能只回滾 K。預覽至確認間若 provider 集合或程式來源改變，該候選不得確認。預設固定模板不可在執行中熱換政策。

會明示刪除的操作必須在候選記錄刪除事實；不能只比較前後 id 集合。身分帳配號及歷史群組沿現行 D59–D62／I70–I72／R56–R58，不因 provider callback 分成多次提交。

三種復原狀態不能合併成一個預設策略：

| 狀態域 | 現有例子 | 原有復原語義 |
|---|---|---|
| World 快照 | D19a 來源規則及其 nextRuleKey | 隨完整 World Undo／Redo 恢復當時值；不承諾跨捨棄分支永久不重用 |
| 專案資料及不可回退標記 | D48 宣告餘料／原材 key 高水位 | 宣告可復原，高水位不隨 Undo／Redo 降低；開另一完整專案依 D51 整份替換 |
| session 配號器 | D61 身分區段與行程序號 | 區段由宿主設定；失敗候選不耗號，群組前面已成功提交取得的號不歸還；Undo 不回退行程序號 |

表列尚未在基準實作的能力仍維持未實作，不能藉共用歷史層自行新增。

### 4.3 Python 與原生橋接

`geometry.py` 的 exact region／extrusion／boolean／mesh 與 `engine.py` 的依賴、KEEP／UNION／DIFFERENCE、請求狀態屬 K。`base.py` 的編譯／子行程以及 `.scene` 解碼屬 H；材料、角材、斷面木工分類到中性來源的映射屬 W。

W/H 把原生定義解為中性的定義圖與幾何輸入，K 仍保留引用身分和原始來源所屬的 opaque provenance，不能只收到一包無來源的數字。K 產生中性結果，W/H 以既有 wire contract 編回 root kinds、source kinds、能力、診斷及 metadata。opaque 資料可原樣帶出但不能被 K 解讀來選木工演算法。

舊 `modeling` import 與 CLI 入口是相容 facade，明列為 H；純 K 測試直接匯入 `geometry_kernel`。依賴守門不能把 facade 後面仍未搬出的幾何排除掉，以假裝獨立。

## 5. 固定模板與存檔相容

第一版模板是**固定內建規範的 woodworking/1**。此名稱是裝配識別，不新增一個會讓舊 reader 拒絕的 `requires` token，也不是使用者可改寫的專案資料。現有公理 revision／SHA 與既有能力集合固定該規範；程式來源指紋另固定實際 evaluator 與模板 bytes。未來可切換或編輯模板政策須另立定義與保存契約，本案不預支。

| 項目 | 必須保持的相容契約 |
|---|---|
| `.scene` | 目前 SSOT 合法的全部舊語法仍合法；已被 2026-09-18 廢除的明寫長度／自由 at 等仍拒絕，不因「向後相容」復活 |
| dump | 同一輸入／操作序列的 canonical dump 逐字相同；角色、來源 token、順序、具體 anchor、signed 索引、key／高水位全保留 |
| 指紋 | 保留舊發布內容與去身分 dump 的 hash 規則；不能改排序、別名或攤平來源後重算成另一份內容 |
| 完整專案 | `.gcanvas` 原 schema、附件、參考圖、草稿原字串、孤兒／曾缺失旗標與歷史 owner 不變；`.scene` 不冒充完整專案 |
| 模型交換包 | 舊 fixture 全包重建仍符合現有比較；公理採納時只按既有測試允許更新 manifest 的 axiom_revision／axiom_sha256，不順手改 generator／root／source／geometry |
| 版本閘門 | 採納時同步 `modeling/__init__.py` 的 AXIOM_REVISION／AXIOM_SHA256，舊已支援 tuple 仍在相容集合；未知 revision+SHA 組合照舊拒絕 |
| 新建預設 | 915×1830、27×33、8 等只在原來會提議的入口由模板提供；空白、未設定、0、null 保持各自語義；讀舊檔不重套預設 |
| 缺模板 | 純 K 可用；需要木工能力的應用／檔案在替換正式狀態前明確拒絕，不當成未知幾何略過，不回退到另一組預設 |
| 診斷 | 既有 code、條號、結構化細節及既有測試要求的訊息保持；不靠中文標籤反解 ID 或角色 |
| 未使用資料 | 未使用材料／規則／卡片、未定位拉伸件、零構件斷面、合法紅色試排都照原契約保存／重建 |

基準程式的 `eng_definition_hash` 直接對去 canvas 的 canonical dump 算摘要，因此「讀得進」不足以證明相容。基準與候選需對每個正／負 fixture 比接受結果、dump、診斷、來源閉包及可重建結果；原本預期拒絕的 fixture 不能被當成失敗而略過。

### 5.1 所有舊入口的裝配矩陣

| 入口 | 必須走的裝配與核對 |
|---|---|
| 原生 CLI／互動 parser／場景載入 | H 明示固定 W，現有語法需要的能力仍由語法本身偵測；刪去 requires 不能繞過 |

## 6. 前端及來源指紋

H 的單一裝配入口注入木工 provider，所有既有按鈕、DOM ID、操作與用語維持。預設值與固定規格在 W 唯一登記；工作區請求具名配方，但不替空白欄位自動補值。像工程一般新面材、網格交接面材、新角材、斷面新建／切換，各入口的原預填不同，必須分別核對。

顯示字串不得用作型別：目前 `app.js` 以「角材」標籤反解 ID、網格工作區以「主支線」文字選 `data-role`，需改成具型別值先決定行為、模板字典再呈現。預設字典仍輸出原畫面。這是內部依賴修正，不新增或移除使用者操作。

模板移到新目錄時，同一片必須更新 `runtime_version.py` 的 source_files、明確 static allowlist、`RuntimeSnapshot` immutable asset bytes 與入口檢查。模板改動或消失要使 `/runtime` 判定過期；運行中的舊服務仍提供啟動時整套快照，不混入新檔案。

規則案例 catalog、配方與 validator adapter 搬移後，也必須參與 `rule_cases/runtime.py` 的 validatorVersion 來源閉包。不能只有舊 Python 目錄改變才使收據過期。

本案零新增可見入口、按鈕或常駐說明。既有入口數不變，不以新增模板管理頁面解釋架構。涉及工作區時依 GEO-219 一併檢視原常駐說明上限，但不在本案改變已核准操作流程。

## 7. 可執行的依賴證明

依賴測試須以**全部產品可執行來源**清冊為輸入，每個 C／header／INC／Python／JavaScript 模組及 HTML 內嵌執行碼歸 K／W／H；新增檔未歸類或重複歸類即紅。掃描 K 本身及其遞移本地依賴，不只掃選定幾個乾淨檔。歷史 oracle 路徑的 W 例外明列且鎖內容，不能當廣泛忽略目錄。前端另核對 script 載入／import／全域 provider 使用與 runtime 資產 allowlist；vendor 套件的明確清冊不混入自有核心責任，也不能用 vendor 排除包住自有程式。

1. C：追蹤 include 閉包、可執行識別字與字串；禁止模板模組、角色與規格識別字。獨立編譯與連結 K 測試，不把 template object 檔放上 link line。
2. Python：AST 檢查 import、from import、動態載入／路徑注入，另掃模板識別字；純 K 匯入時用阻擋 loader 證明不曾嘗試載入 W/H。
3. 公開核心型別／函式不得含 W 識別字或讓 K 對 opaque kind 分支。允許通用 `boundary`、`panel` 等幾何單字時必須按正式識別字／語境處理，不能因字串同名就胡亂禁掉；禁止清單以實際模板 API／角色 enum／規格 key 為準，另有人工逐函式責任審查。
4. 把模板整個目錄從隔離安裝排除後，核心建置、匯入與測試仍通過；這比環境變數聲稱「沒載入」更強。
5. 產品 default 裝配確實使用同一 K 實作。以負控制破壞一個共用幾何判式，核心和木工對應見證都必須轉紅，防止保留兩套引擎。

守門的負控制至少包含：在 K 加一個對 W header 的 include；經另一個 K helper 間接 include；Python 直接／動態 import W；在 K 加角色 enum 或固定板規格分支；漏登一個新來源檔。每案必須失敗並指出檔案、行號與違反的方向，還原後通過。mutant 若沒有命中目標、編譯失敗或環境受阻不能算 killed。

詞彙掃描只能證明沒有已知反向引用，不能單獨證明架構。API 覆蓋、無模板行為測試、共用實作負控制與獨立審查共同構成證據。
