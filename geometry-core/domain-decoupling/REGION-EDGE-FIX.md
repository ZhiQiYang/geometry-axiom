# GEO-261：區域孔相交與一毫米包含判定修正

本切片修復從既有實作抽取至 K 前就存在的兩個缺陷，獨立於 N1b 幾何抽取的相容性結論。
依據是 `公理層.md` I2（孔互不重疊）及 I5（整個 A0 位於有效範圍，不跨孔）；未修改條文。

## 改動

- `geo_region_is_valid` 原本只檢查孔頂點是否在另一孔內。外環 `[0,100]²`、橫孔
  `[10,90]×[40,60]`、直孔 `[40,60]×[10,90]` 的交集有正面積，卻沒有任何頂點位於對方孔內。
  在既有頂點檢查後補上互相垂直的邊之嚴格交叉檢查；既有包含、邊相接及點相接的拒絕維持。
- `geo_region_contains_rect` 在確認沒有孔邊穿入矩形開內部後，改用既有的雙倍座標中心判定。
  孔 `[2,3]²` 與同範圍矩形的 `min+1` 落在孔邊，舊入口因而漏掉整塊位於孔內的情形。
  新判定也修正 `geo_strip_intervals` 錯把該孔跨過、合成整段 `[0,10]` 的衍生結果。

孔邊與矩形只有邊或點相接仍允許。沒有浮點、epsilon、取整或新增幾何型別。D1 有界座標的和及
雙倍值最多為 ±200,000,000，仍在 `int64_t` 內；新增交叉檢查只做比較，沒有乘法。

## 驗證範圍與狀態

`tests/test_geo261_region_edges.py` 收錄 8 個測試，使用既有 `NativeBuild`：只複製 K 公開來源至隔離
目錄編譯，再以同一 K object 連結真正 `web_bridge.c`。正向案例包含順逆頂點序、孔順序互換、既有
接觸語意、1–3 mm 矩形、負座標與 D1 兩端，以及條帶最大區間及容量不足。兩個產品案例逐行送入
native bridge，要求拒絕且 `dump` 不變；兩個移除控制要求 K 斷言失敗及產品錯誤放行同時出現。

- 本地靜態檢查：Python 語法編譯通過；unittest discovery 為 8。
- `run_all.py` 與 `run_all.expected.json` 僅登記本 suite 的新 key，數量 8 來自 discovery；未改既有
  suite 數量。registry 登記不代表 native 或完整測試已通過。
- native 執行：待 `p1_validation` 於共用 WSL 鎖下執行；此時沒有將靜態推論記為執行成功。
- 凍結前版：指定 `51e9045b43078a77383afdaf5db379117ffc8871`。同一組正向斷言須對該版本的
  完整來源實際執行並獨立保存預期紅燈，不能把新 bridge 與舊 K 混合連結、不能改普通測試期待值。

執行入口：`python -m unittest tests.test_geo261_region_edges -v`。編譯器錯誤、程序崩潰及環境阻擋均
不是成功的負控制。凍結前版只執行六個正向測試；移除控制針對修正後版本執行。
