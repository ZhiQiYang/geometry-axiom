## 1. 現行依據、術語與裁決範圍

本文的「整卡引用」是網格持有的一個來源定義，來源單位是一張 D31 卡片；卡內的兩個長度如何給 u/v，另由同一份定義明示。
它不把卡片變成幾何向量，不把卡片內全部欄位都套用到網格，也不把兩個獨立 ParameterRef 稱作整卡引用。

「軸長度槽」是本文待新增的通用術語：D29 REPEAT 的 `step`，或 REPEAT_PANEL 的 `panel`。
`panel` 在本文只作既有協定欄位名，表示該排法的正長度；公式、`gap` 與 `anchor` 沿用 D29。
新機制只處理長度、軸、引用和交易；不增加材料分類、施工角色、領域預設值或自動生成物件。

| 現行條文（基準行號） | 可直接沿用的定義推論 | 不能由它推出的新增選擇 |
| --- | --- | --- |
| D1:61–67、D31:512–533、I38:1137–1147 | dimension 是精確 mm 有理數；幾何入值須為 D1 範圍內整數；名稱與顯示順序不是身分 | 卡片是否帶新型別、哪些欄位被整組使用 |
| D9:173–188、D29:453–471 | 保存來源定義；改參數重算，同一 signed 線索引／cell 身分不改；單欄不得有兩個有效來源 | 整卡定義、兩軸來源的不可分割範圍 |
| D30:491–510、I37:1119–1135 | 配置保留 vertexKey、cell、比例；依賴不合法整筆拒絕 | 長度對調是否帶動其他軸設定 |
| I8/I8a:891–929、R32/R33:1634–1672 | 候選全量驗證、同候選確認、取消／過期不提交、一次復原／重做 | 整卡選取與解除的操作單位 |
| I38/I39:1137–1160、D59/D60/D62:810–854 | 保護被引用卡片／欄位；存在期與內容分開；World 內引用仍用 id | 整卡新增欄位是否影響其資格 |

行號只作定位；下面「原文」逐字引用基準檔的受影響片段，未列出的原文保留。舊條文中的既有領域詞只出現在原文對照，不作新機制的定義。

## 2. 回答 #249 的八個問題

### Q1：保存什麼，引用單位如何成立

**定義推論：**D31 只有欄位型別和 `(parameterId, fieldId)`；卡片名稱、範本及位置都不是型別。D9 要求來源進核心保存。現行條文推不出整卡引用。

**待使用者決定 C1：**

| 選項 | 影響 | 建議 |
| --- | --- | --- |
| A：一個卡片 id 加 `uFieldId/vFieldId` 對應，由網格保存 | 保留任意 D31 卡片；模板只提供卡片內容，核心不認模板名稱。必須明確定義一筆整組操作與兩個受控槽，避免退回兩個獨立引用 | **採 A**；最小擴充且符合 #248 |
| B：卡片新增通用「二維長度組」型別，網格引用固定角色 | 也能領域無關，但須另訂卡片型別、角色 schema、型別轉換、範本與舊卡遷移；僅有兩欄不能自動證明已具型別 | 留待獨立提案；不可用材料名稱替代通用型別 |

A 的資料單位是 **一個 CardReference**，有一個 card id 與完整軸對應；建立、改卡、換對應、解除都一次處理整組。兩個槽不各存另一份 ParameterRef 或可編輯數值。使用清單報告「網格 G 引用卡 P」，並可展開兩條實際求值路徑。這是可持久化的核心關係，不是只在介面同時操作兩個選單。

### Q2：哪些卡合格

**定義推論：**D31/I38 允許自訂欄位；卡片至少一欄，所有已提交欄位須合法。count/ratio 不可當 mm，合法分數尺寸可以存在於卡片，是否能供網格使用另驗 D1。

**待使用者決定 C2：**可限定整卡「恰好兩個 dimension」，或允許「至少兩個 dimension，明選其中兩個不同 fieldId」。建議後者：新增第三個長度不會讓既有合法引用突然失效，模板無須為網格複製卡片。其他合法 dimension/count/ratio 欄位可共存；不被選到不代表可以藏錯誤欄位。

選中的兩個欄位須不同，但數值可相等（例如 12、12）。同一欄位供兩軸仍可用既有逐欄引用；整卡首版不把一個欄位猜成兩個角色。少於兩個 dimension 不合本能力資格；多於兩個時不能依前兩欄、名稱或數值大小自動選取。恰有兩個也須在確認候選中明示 u/v 對應，不能從畫面排序建立長期語意。

### Q3：控制哪些位置；逐欄引用如何並存

**定義推論：**D29 的兩軸排法各自定義；REPEAT 的 `step`、REPEAT_PANEL 的 `panel` 都要求正長度，其餘欄位另有自己的來源與約束。沒有條文說整卡應控制全部尺寸。

**待使用者決定 C3：**建議只控制兩軸各一個「軸長度槽」；兩軸都須為 REPEAT/REPEAT_PANEL，可混合這兩種無限模式。REPEAT 的 `phase`、REPEAT_PANEL 的 `gap/anchor`、D10b 的 `stagger` 仍為直接值或逐欄 ParameterRef，甚至可以引用同卡的其他欄位。任一軸為 none、legacy-finite 或其他來源模式時不接受本能力；舊單軸網格本身仍合法。

建立整卡引用會**明示取代**兩個槽原本的來源，預覽兩軸的舊／新來源；不在背後保留能復活的覆寫。已有整卡引用時，單獨改某一受控槽的直接值／逐欄來源應拒絕，或由使用者另選下述整組解除，不能默默拆半。

**待使用者決定 C4：**建議提供兩種明示整組轉換：

1. 「轉成逐欄引用」：移除 CardReference，兩槽各成為原卡及已映射欄位的 ParameterRef，仍隨卡片變動。
2. 「轉成直接值」：移除 CardReference，兩槽各取得候選求值後的有效整數，不再引用該兩欄。其他逐欄引用保持。

直接拒絕所有解除操作也是選項，但會妨礙回到既有工作方式，故不建議。轉換一律經預覽與完整驗證；不能轉一半。轉直接值與同候選改卡值並存時，以**完整候選中的最終卡片定義**求值，預覽明列捕捉值；不是使用畫面快取或不明時點的舊值。

改軸模式是另一項明示候選：保留對應時，長度依該軸新模式進 `step` 或 `panel`；其餘新模式必需欄位必須明設，不猜 gap/anchor。移除一軸或換成其他來源模式，須先在同候選明示解除整卡關係，不能留下孤立半份。

### Q4：u/v 與對調

**定義推論：**D29/D30 已固定 u/v 的含義與索引；參數卡不是向量（R33）。改長度不等於旋轉座標框架。

**待使用者決定 C5：**建議以對應本身保存方向：`uFieldId=3,vFieldId=8`，對調後為 `uFieldId=8,vFieldId=3`。另一選項是保存基準欄位對加 swap bit；但同時保存二者會有雙重真相，不建議。

對調只交換兩個長度的來源，不交換軸模式、phase、gap、anchor、stagger、main_along 或配置錨點。不用「較長者一定沿 u」等規則；數值交叉也不自動翻轉。即使兩數相等，對調仍改變定義，須保存及預覽。領域模板可把這個明示對應呈現為自己的方向選擇，核心不替模板下方向判斷。

### Q5：來源卡片變動

**定義推論：**改值重算全部依賴，線與 cell 身分維持（D29/I37/R33）；卡片或受引用欄位不能留下懸空引用（I38）；任何非法候選整筆拒絕（I8a）。

**待使用者決定 C6（採 C1/C2 後的精確化）：**

| 變動 | 建議規則 |
| --- | --- |
| 改選中欄位值／算式 | 同一 fieldId 重算；不改映射或索引；無效或下游失敗整筆拒絕 |
| 改名、排序、卡片移動 | 不改映射；改名／排序是定義變更，仍按現行預覽過期規則；純 canvas-pos 例外保持 |
| 刪選中欄位、改成 count/ratio | 拒絕剩餘的整卡引用；可在同一候選明示整組改映射／改卡／解除後再驗，不自動選替代欄 |
| 新增合法欄位 | 允許，映射不變；新增欄位本身及其依賴照 I38 全驗 |
| 刪未選欄位／改其型別 | 不因 CardReference 一律鎖全卡；若被算式或其他使用處引用仍照 I38 拒絕；不能只看網格沒選它 |
| 刪卡 | CardReference 引用卡片本身，仍存在就按 I38 拒絕；同候選明示解除全部依賴後才可刪 |
| 改指另一張卡 | 一次替換 card id 及兩個 fieldId，重新驗兩軸與所有下游；禁止只換其中一軸到另一卡 |

選項「任何增刪欄位都使整卡失效」較簡單，但會把卡片綁成封閉二欄型別，與 C1/A 的通用卡片方案不一致，故不建議。

### Q6：存在期、交易、歷史、保存及舊檔

**定義推論：**D60 的「刪除再同鍵建立是新存在期」與 D62 的「World 內引用仍用 id、不加記號」必須同時保留。不能因新存在期另造 World 內的 incarnation 引用，也不能靠刪除保護就宣稱卡片永遠沒有新存在期。

仍被引用的卡不能獨立刪除；同候選同鍵重建並不使卡片取得原記號。明示 put 同鍵、匯入配號與刪除保護依既有契約分別處理；**本文不改判 #193/P-117 的現有反例**。新增能力不得讓匯入的獨立副本偷接尚存的引用。若全部依賴先被明示解除，刪除／重建再明選綁定屬新的合法候選；存在期帳啟用時卡片與欄位記號須按 D60/R56 更新。

World 外預覽／證據若要主張身分延續，按 D62/R57 同時比較專案、鍵與記號；只有內容相同不夠。身分帳未啟用時，不虛構記號或宣稱已證明延續。Undo/Redo 恢復整份 World、映射及原身分帳，不重新配號。

**待使用者決定 C7：**建議所有整卡建立／改卡／映射／模式改動／解除一律走 I8a 的整組候選，無下游也先預覽。這把現有網格交易紀律明確套到新關係，而非新增幾何豁免。保存採 §5 的明示能力、定義重放與舊檔零自動轉換方案；不降級成兩個 ParameterRef。

### Q7：領域無關與 #248 邊界

**定義推論：**D31 的型別是 dimension/count/ratio，R33 明示卡片不是向量；模板名稱或快捷輸入不決定引用身分。

本提案只定義「一張卡的兩個明選長度 → 網格 u/v 的長度槽」。不按寬／長等顯示名稱匹配，不內建任一尺寸，不改目前範本，不在本 PR 把既有木工條文全面改名。依賴單向為模板提供卡片與明選對應，通用核心驗引用和幾何。#248 的其他解耦工作由其 owner 推進；本案無須等待全部重構，也不把研究當採納。

### Q8：驗收與突變

**定義推論：**現有逐欄測試只能證明逐欄行為，無法證明整卡的原子替換和保存。必須有新能力的具名測試，並保留原逐欄與 legacy-finite 回歸。

§6 每例指定輸入、精確結果與失敗不變量；§7 將每項新規則連到可被撤去的實作。這些是**待實作驗收計畫**，沒有把表格標成 pass。實作切片與可見介面減項仍待審查／採納，不由本文擴張授權。

## 3. 既有條文逐條差異與白話草稿

下列都是建議稿，採 C1–C7 時一起採納；不得只換 D31 一句而漏掉單一來源、交易或保存規則。
「在原文後新增」表示原文逐字保留；「替換」只替換列出的片段。白話草稿僅寫在本文。

### E1：D9，保存整組來源定義

原文：

```text
D31 的參數卡、欄位身分、型別、字面值／結構化算式與引用屬於定義。
欄位有效值、依賴列表及物件有效尺寸是推導結果，不保存成與算式並列的第二份有效來源。
```

在原文後新增：

```text
D-CR1 的卡片身分與兩軸欄位對應亦屬於網格來源定義，須進入核心保存與重放。
從卡片取得的軸長度只作推導結果，不另存為可獨立編輯的數值或兩份 ParameterRef。
```

白話 D9：原段「只存輸入,不存推導結果」保留；新增「整張卡的引用要保存是哪一張、哪兩個欄位分別供哪一軸。算出的兩個長度不是另一份來源，不能只保存數字或只在介面記住卡片。」

### E2：D29，兩個槽可由一個整卡來源供應

原文：

```text
每個欄位恰有一個來源，存直接值或 ParameterRef；引用的有效值先按 D1 與本條驗證，再使用原有排格公式。
```

替換為：

```text
每個有效欄位恰有一個來源。未由 D-CR1 供應的欄位，存直接值或 ParameterRef；
支援 grid-card-reference/1 時，兩軸各一個軸長度槽可共同由一份 D-CR1 卡片引用供應。
該兩槽不另存直接值或 ParameterRef；其來源由整組引用及軸對應唯一決定。
所有引用的有效值先按 D1 與本條驗證，再使用原有排格公式。
```

在原文「解除參數引用須明示轉為當下有效整數，經 I8a 預覽；不在網格內保存第二份可獨立編輯的有效值。」後新增：

```text
D-CR1 整卡引用的建立、替換、對調及解除另依 R-CR1，一次處理兩個軸長度槽；
其他逐欄引用的解除維持原義。相位、間隔、錨點及相位差不因長度對調而對調。
```

白話 D29 原段「兩軸的間距、基準座標、面材、縫與起點可明選參數尺寸。保存的是引用身分；卡片改名不會接錯。有限等差與明寫座標保持原本的輸入方式。」保留，後增：

> 也可明選一整張參數卡，確認兩個長度欄位分別對應 u、v。每軸依現有排法取得間距或該排法的長度；其餘設定仍各用原來源。整組綁定後不能只覆寫其中一個長度；可明確整組轉成逐欄引用或直接值。舊檔不自動轉換。

### E3：D31，區分欄位引用與卡片引用

原文：

```text
引用為 `(parameterId, fieldId)`，不使用顯示名稱、欄位位置或畫布位置配對；改名、排序、拖移不重綁。
```

替換為：

```text
欄位引用 ParameterRef 為 `(parameterId, fieldId)`，不使用顯示名稱、欄位位置或畫布位置配對；改名、排序、拖移不重綁。
支援 grid-card-reference/1 時，D29 得以 D-CR1 把一張卡片作為一個引用單位，另明示該卡兩個欄位與軸的對應。
卡片不因被整組引用而取得新型別；欄位型別、精確求值及欄位依賴圖維持本條。
```

白話 D31 原句「每張卡、每個欄位都有固定身分；改名、排序、移動畫布位置不會換掉引用。」後增：

> 一欄一欄引用仍可用。網格另可引用整張卡，並保存兩個欄位各給哪一軸；這不會把卡片變成向量或帶有領域意義的規格。

### E4：I8a，整卡影響及同候選確認

原文：

```text
參數卡建立／修改／刪除、欄位改綁／解除與參數包匯入亦一律先預覽候選，即使目前沒有幾何使用處。
預覽列出新舊定義、型別、精確有效值、直接使用欄位與沿依賴鏈受影響的卡片及物件。
```

在原文後新增：

```text
D-CR1 整卡引用的建立、替換、對應或軸模式修改及整組解除，同樣先預覽，即使網格尚無下游使用處。
預覽明列新舊卡片、兩軸欄位身分、目標槽與精確有效值，以及被取代或解除的來源；數值相同仍列來源變更。
兩軸與其全部依賴屬於同一候選、確認與復原單位；任一失敗不得只更新一軸。
```

## 4. 新增條文全文與對應白話

下列條文原文均為「無（新增）」，暫定號不表示已採納。

### D-CR1：網格卡片引用（GridCardReference）

```text
支援 grid-card-reference/1 的 D29 無限網格，可擁有零或一份卡片引用，作為其兩個軸長度槽的單一來源定義。
卡片引用保存一個 D31 parameterId，以及 uFieldId、vFieldId；兩欄必須屬於該卡且身分不同。
REPEAT 的軸長度槽為 step，REPEAT_PANEL 為 panel；兩軸皆須屬於這兩種模式，可互相不同。
所選欄位須為 dimension，其他合法欄位可共存；不以名稱、範本、顯示順序或數值大小推斷對應。
來源卡片不因被引用而變成向量、材料或另一種卡片型別，不反向擁有網格。
卡片引用沒有另一個獨立 World id，也不攜帶存在期記號；它是網格內部來源定義。
對調只交換兩個 fieldId 的軸對應，不交換其他軸設定、線索引、cell 錨點或世界框架。
```

白話新增段：

> 一個網格可以整組引用一張卡，並記住兩個不同長度欄位各給 u 還是 v。多出的合法欄位不礙事，也不會自動被挑進來。對調換的是兩個長度的去向，不是旋轉網格或交換其他設定。兩個長度相等仍是兩個不同欄位。

### I-CR1：完整、唯一且合法的整組來源

```text
卡片引用必須有現存卡片及完整兩軸對應；少一軸、跨卡映射、同一 fieldId 重用、型別不合均拒絕。
兩個受控槽不可同時有直接值、ParameterRef 或另一種來源；其他尺寸欄位維持原單一來源規則。
每個所選欄位先依 I38 求精確值，再各自驗 D1、D29 正值及全部目標限制；不把 count/ratio 當尺寸，不取整、不截斷。
任一依賴失敗整筆拒絕，錯誤列出網格、來源卡片／欄位、軸及違反條款；容量或精度不足沿 I33 明確分類。
不得因同名、同值或同鍵重建自動改映射、凍結長度或略過刪除保護；存在期與內部 id 引用仍分別依 D60、D62 處理。
```

白話新增段：

> 兩軸的來源必須完整且唯一。缺卡、缺欄、型別錯、長度不合法，或其他依賴不成立，都整筆拒絕並指出哪張卡、哪個欄位、哪一軸出錯。不能用同名替代，也不能把分數四捨五入後套進網格。

### R-CR1：整卡交易、求值及保存

```text
建立或替換卡片引用時，明示來源卡片、兩軸對應及將被取代的來源；在同一候選驗證參數圖、整卡來源、網格與全部下游。
改卡、改對應、對調或改軸模式亦走相同候選流程，依 I8a 預覽、確認同一候選，再一次提交。
來源卡改值仍依 R33 重算；同一格線／段／cell 的身分依 D29、D10b、D30 保持，幾何合法性不因此免驗。
整組解除須明選轉成兩個 ParameterRef，或轉成完整候選求值後的兩個直接整數；不得只解除一軸或保留隱藏覆寫。
移除軸或換到非本能力模式時，須在同一候選明示解除整卡關係並提供新定義；沒有隱含轉換。
取消、失敗與過期不改正式 World、metadata 或 history；確認重驗全部依賴。Undo/Redo 恢復完整定義與適用的身分帳。
場景及完整專案依賴順序先保存來源卡片閉包，再保存網格的整卡來源、兩軸對應及其他原設定，後保存配置與下游引用。
保存包括未使用網格的整卡來源，不保存有效長度、抽樣線或使用清單作為另一份定義。
讀取要求 parameters/1 與 grid-card-reference/1；實際新資料即要求新能力，移除宣告不能繞過驗證。
未知能力、缺宣告、缺閉包、映射非法或容量不足，在替換當前 World／專案之前拒絕，不部分載入或降級。
舊直接值、ParameterRef 及 legacy-finite 定義原樣可讀，不以兩個引用碰巧同卡就自動合成整卡來源。
```

白話新增段：

> 選卡、換卡、對調、解除都先看整組結果，再一次確認。可以整組拆回逐欄引用，也可以明確固定成候選中的兩個有效整數；其他來源不跟著消失。存檔會把完整卡片、對應與原設定一起保存，重開重新計算。不認識新資料就整份拒絕，不偷偷拆散；舊檔仍照原本方式用。

**不改 D60/D62：**新增條文引用其現有語意；不新增身分帳涵蓋種類，也不強迫舊專案啟用身分帳。對應白話 D60/D62 保持原文，不以本功能順便改寫。

## 5. 保存與相容契約草案

### 5.1 邏輯表示（非已支援的 API）

下列表示只定義不可遺失的資訊；正式 JSON／DSL 名稱由採納後的契約固定，不把例子交給目前執行器執行：

```json
{
  "cardReference": {"parameterId": 10, "uFieldId": 3, "vFieldId": 8},
  "u": {"mode": "REPEAT", "phase": -5, "stepSource": "card"},
  "v": {"mode": "REPEAT", "phase": 7, "stepSource": "card"}
}
```

`card` 是來源種類而非值或 ParameterRef；一份 cardReference 決定兩軸。無整卡引用的網格保持既有表示，不補空物件。兩軸模式與其他來源原樣保存；不能同時另存有效 step/panel，不能再存一個可能矛盾的 swap bit。

| 讀／寫情境 | 必須保持的規則 |
| --- | --- |
| 新執行器讀舊直接值或逐欄場景 | 原樣解析，無自動整卡化；同卡的兩個 ParameterRef 仍是獨立來源 |
| 新執行器讀舊有限場景 | 座標、條數、索引及 origin 保持；不因有參數卡就轉無限 |
| 含整卡的 `.scene` | 保存完整來源卡片閉包與整卡定義，宣告兩項能力；未使用的來源也不丟 |
| 含整卡的完整 `.gcanvas` | manifest 與 payload 均保留必要能力，選用採納時分配的正式格式版本；不假裝是較舊版本 |
| 舊執行器／刪新能力標記／未知版本 | 新語法本身亦觸發能力需求；明確拒絕且保留當前專案，不做降級匯入 |
| 新功能資料不存在 | 不強迫提升舊檔能力、不插入 cardReference、不更改舊直接值或逐欄表示 |
| 參數包匯出／匯入 | 仍是卡片閉包，不帶外部網格；匯入新卡 id、保留 fieldId，使用者之後明選整卡來源 |
| 通用定義匯入（D55） | 本提案不擴張其可選根種類；目前未納入的網格不能藉本能力悄悄成為可匯入根 |
| 同專案完整重開 | 保留卡片／欄位 id、映射、其他定義與已啟用身分帳；重新求值 |
| 跨專案交換 | 不攜帶 incarnation；依 I39/D62 配新身分與適用記號，不能自動改指目的專案既有同名卡 |

舊 `parameters/1` 單獨存在時的既定格式接受規則不變（含既有契約的場景能力補註例外）；本提案的新能力門檻只適用實際含整卡資料者。格式號不是公理政策，但實作前必須公布確切版本、語法、能力表及舊／新讀寫矩陣並測試，不能以「稍後訂格式」為由只交介面連線。

### 5.2 草稿與 UI 的邊界

D57 的既有逐欄草稿白名單不因本文自動擴張。含新整卡編輯的草稿，需在採納後同步補上原始欄位、來源對應、過期／永久缺失檢查與必要能力；完成此契約以前不得把整卡草稿假存成舊逐欄草稿或宣稱支援暫存／續編。此項隨 UI 切片另交逐條 diff，不在本提案暗改 D57。

正式入口建議合併目前兩個長度槽的來源設定為同一來源區，保留逐欄模式，使用者明選整卡時才展開映射；不是新增一排永久按鈕。這是待審查的 UI 減項方向，實作前仍須依 GEO-219 在 BACKLOG 列實際減項。本 PR 不改 BACKLOG 或目前 UI。

## 7. 突變計畫與測試邊界

採納後先以原實作跑新增案例，應因不支援整卡入口具名轉紅；加入實作後轉綠。再逐項撤去下表機制、重新編譯實際受測 binary，要求對應具名斷言轉紅；還原後重編恢復綠。啟動失敗、未編到被改來源、超時或 skip 不算 killed。

| 突變 | 應轉紅的案例與原因 |
| --- | --- |
| M01 整卡入口退回兩個獨立 ParameterRef，幾何相同 | CR01/19 `CARD_UNIT`／`CARD_SAVE_ROUNDTRIP`：來源種類與整組定義丟失 |
| M02 依顯示順序／名稱選兩欄，或以數值大小重排 | CR04/05 `EQUAL_VALUE_IDENTITY`／`STABLE_FIELD_IDS`：後續只改原欄即錯軸 |
| M03 放寬不同欄位／同卡／兩軸完整要求 | CR07/11 的三種具名結構拒絕分別失敗 |
| M04 拿掉單一來源守門，允許一軸覆寫／舊宣告暗拆 | CR11/13 `SOURCE_EXCLUSIVITY`／`EXPLICIT_UNBIND` |
| M05 拿掉 dimension、正值、整數、D1 或精確運算檢查（逐項） | CR09/10 分別在型別／範圍／精度具名斷言失敗，不用一個泛稱錯誤混過 |
| M06 拿掉刪卡／刪所選欄保護，或給未選欄全面免驗 | CR06/08 `EXTRA_FIELD_DEPENDENCY`／`MAPPED_SOURCE_PROTECTION` |
| M07 換卡依軸分次提交，第二軸失敗不回滾 | CR12 `ATOMIC_REBIND`：dump、history 出現半份更新 |
