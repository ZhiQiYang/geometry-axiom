## 1. 現行依據、術語與裁決範圍

本文的「整卡引用」是網格持有的一個來源定義，來源單位是一張 D31 卡片；卡內的兩個長度如何給 u/v，另由同一份定義明示。
它不把卡片變成幾何向量，不把卡片內全部欄位都套用到網格，也不把兩個獨立 ParameterRef 稱作整卡引用。

「軸長度槽」是本文待新增的通用術語：D29 REPEAT 的 `step`，或 REPEAT_PANEL 的 `panel`。
`panel` 在本文只作既有協定欄位名，表示該排法的正長度；公式、`gap` 與 `anchor` 沿用 D29。
新機制只處理長度、軸、引用和交易；不增加材料分類、施工角色、領域預設值或自動生成物件。

| 現行條文（基準行號） | 定義推論 | 本文落點 |
| --- | --- | --- |
| D1:61–67、D31:512–533、I38:1137–1147 | dimension 是精確 mm 有理數；幾何入值須為 D1 範圍內整數；名稱與顯示順序不是身分 | C1/C2：引用一般卡片，明選兩個尺寸欄位 |
| D9:173–188、D29:453–471、D42:613–616 | 保存來源定義及明示軸對應；整體來源加欄位沿向已有先例，數值相等亦須明選 | C3/C5：兩個長度槽、保存對應，不重存 swap bit |

## 2. 回答 #249 的八個問題

### Q1：保存什麼，引用單位如何成立

**定義推論 C1 = A：**D31:533 的快捷輸入建立的是一般參數卡，正是 #249 要直接引用的物件；先要求它取得新卡片型別不能滿足這個目的。D31:516 排除以名稱／欄位位置配對，D9 要求保存來源，故保存卡片 id 加明示 u/v 欄位對應。D42:613–616 已有「整體引用一個來源版本，再明選欄位沿 u 或 v」的先例，數值相等也須明選；本案沿用關係結構，不引入其領域語意。

| 方案比較 | 影響 | 依 P-120 的結論 |
| --- | --- | --- |
| A：一個卡片 id 加 `uFieldId/vFieldId` 對應，由網格保存 | 保留任意 D31 卡片；模板只提供卡片內容，核心不認模板名稱。以一筆整組操作控制兩個槽 | 由一般卡片需求、D9／D31／D42 推出，採 A |
| B：卡片新增通用「二維長度組」型別，網格引用固定角色 | 須新增型別、角色 schema、轉型及舊卡遷移，讓一般卡先變另一型別才能引用 | 不符合本需求，不作待決選項；不得以領域名稱替代通用型別 |

A 的資料單位是 **一個 CardReference**，有一個 card id 與完整軸對應；建立、改卡、換對應、解除都一次處理整組。兩個槽不各存另一份 ParameterRef 或可編輯數值。使用清單報告「網格 G 引用卡 P」，並可展開兩條實際求值路徑。這是可持久化的核心關係，不是只在介面同時操作兩個選單。

### Q2：哪些卡合格

**定義推論：**D31/I38 允許自訂欄位；卡片至少一欄，所有已提交欄位須合法。count/ratio 不可當 mm，合法分數尺寸可以存在於卡片，是否能供網格使用另驗 D1。

**定義推論 C2：**至少兩個 dimension，明選其中兩個不同 fieldId。R33:1670 規定修改來源只影響真正引用它的定義，因此新增未選欄位不能使網格失去合法性；D31:516 又排除依位置配對，即使恰好兩欄也不能省掉明選。「恰好兩個」的限制沒有依據。其他合法 dimension/count/ratio 欄位可共存；不被選到不代表可以藏錯誤欄位。

選中的兩個欄位須不同，但數值可相等（例如 12、12）。同一欄位供兩軸仍可用既有逐欄引用；整卡首版不把一個欄位猜成兩個角色。少於兩個 dimension 不合本能力資格；多於兩個時不能依前兩欄、名稱或數值大小自動選取。恰有兩個也須在確認候選中明示 u/v 對應，不能從畫面排序建立長期語意。

### Q3：控制哪些位置；逐欄引用如何並存

**定義推論：**D29 的兩軸排法各自定義；REPEAT 的 `step`、REPEAT_PANEL 的 `panel` 都要求正長度，其餘欄位另有自己的來源與約束。沒有條文說整卡應控制全部尺寸。

**定義推論 C3：**依需求與 D29:464–465，只控制兩軸各一個「軸長度槽」，其他欄位各保留原來源；兩軸都須為 REPEAT/REPEAT_PANEL，可混合這兩種無限模式。REPEAT 的 `phase`、REPEAT_PANEL 的 `gap/anchor`、D10b 的 `stagger` 仍為直接值或逐欄 ParameterRef，甚至可以引用同卡的其他欄位。任一軸為 none、legacy-finite 或其他來源模式時不接受本能力；舊單軸網格本身仍合法。

建立整卡引用會**明示取代**兩個槽原本的來源，預覽兩軸的舊／新來源；不在背後保留能復活的覆寫。已有整卡引用時，單獨改某一受控槽的直接值／逐欄來源應拒絕，或由使用者另選下述整組解除，不能默默拆半。

**定義推論 C4：**I38:1146 要求明確改綁／解除的路徑，D29:467 明定解除時轉為當下有效整數；整卡與既有逐欄來源並存，故提供兩種明示整組轉換：

1. 「轉成逐欄引用」：移除 CardReference，兩槽各成為原卡及已映射欄位的 ParameterRef，仍隨卡片變動。
2. 「轉成直接值」：移除 CardReference，兩槽各取得**有序候選中該步的當下有效值**，須為合法整數，不再引用該兩欄。其他逐欄引用保持。

轉換一律經預覽與完整驗證，不能轉一半。依 I8:895–897 的明確有序交易，轉直接值只讀該步執行時已存在的有效來源；後續改卡不回寫已解除的兩槽，不以整包最終卡值倒推前一步。來源在該步缺失或無法合法求值就拒絕，不從後步或畫面快取補值。預覽明列捕捉時點與兩個值，最後仍全量驗證整筆候選。

改軸模式是另一項明示候選：保留對應時，長度依該軸新模式進 `step` 或 `panel`；其餘新模式必需欄位必須明設，不猜 gap/anchor。移除一軸或換成其他來源模式，須先在同候選明示解除整卡關係，不能留下孤立半份。

### Q4：u/v 與對調

**定義推論：**D29/D30 已固定 u/v 的含義與索引；參數卡不是向量（R33）。改長度不等於旋轉座標框架。

**定義推論 C5：**依 D9 的單一來源及 D31:516 的明示身分，保存對應本身：`uFieldId=3,vFieldId=8`，對調後為 `uFieldId=8,vFieldId=3`。不另存 swap bit，避免兩份可矛盾的真相；D42:613–616 的明選沿向亦不依數值大小改綁。

對調只交換兩個長度的來源，不交換軸模式、phase、gap、anchor、stagger、main_along 或配置錨點。不用「較長者一定沿 u」等規則；數值交叉也不自動翻轉。即使兩數相等，對調仍改變定義，須保存及預覽。領域模板可把這個明示對應呈現為自己的方向選擇，核心不替模板下方向判斷。

### Q5：來源卡片變動

**定義推論：**改值重算全部依賴，線與 cell 身分維持（D29/I37/R33）；卡片或受引用欄位不能留下懸空引用（I38）；任何非法候選整筆拒絕（I8a）。

**定義推論 C6：**依 I38:1146–1147 的刪除保護、R33:1670 的實際依賴、D31:516 的欄位身分、I8a:923 的同候選確認及 C2，逐項如下：

| 變動 | 由現行定義推出的規則 |
| --- | --- |
| 改選中欄位值／算式 | 同一 fieldId 重算；不改映射或索引；無效或下游失敗整筆拒絕 |
| 改名、排序、卡片移動 | 不改映射；改名／排序是定義變更，仍按現行預覽過期規則；純 canvas-pos 例外保持 |
| 刪選中欄位、改成 count/ratio | 拒絕剩餘的整卡引用；可在同一候選明示整組改映射／改卡／解除後再驗，不自動選替代欄 |
| 新增合法欄位 | 允許，映射不變；新增欄位本身及其依賴照 I38 全驗 |
| 刪未選欄位／改其型別 | 不因 CardReference 一律鎖全卡；若被算式或其他使用處引用仍照 I38 拒絕；不能只看網格沒選它 |
| 刪卡／同候選同鍵重建 | 按 I38 保護每個引用者；仍指向該鍵者須在刪除之後被明示重新宣告（改綁或解除），否則整筆拒絕。僅重建來源鍵不算處理引用；詳 Q6 |
| 改指另一張卡 | 一次替換 card id 及兩個 fieldId，重新驗兩軸與所有下游；禁止只換其中一軸到另一卡 |

「任何增刪欄位都使整卡失效」違反 C2 與 R33 的實際引用範圍，不列為選項；卡片整體仍須滿足 I38，不能因此漏驗未選欄位的算式依賴。

### Q6：存在期、交易、歷史、保存及舊檔

**定義推論：**D60 的「刪除再同鍵建立是新存在期」與 D62 的「World 內引用仍用 id、不加記號」必須同時保留。不能因新存在期另造 World 內的 incarnation 引用，也不能靠刪除保護就宣稱卡片永遠沒有新存在期。

**I38 的刪除保護直接適用，不依賴其他 PR 才決定：**同候選 `[刪卡 P, 同鍵重建 P]` 若網格仍持有原整卡引用，整筆拒絕，指名來源與未處理的引用者。每個最後仍指向被刪鍵的引用者，都須在該鍵最後一次刪除之後被明示重新宣告（整組改綁或解除）；只有來源同鍵重建、或引用者僅在刪除之前被宣告，均不算完成。若先已明示改指另一張卡或解除而不再引用 P，刪 P 不再受該引用阻擋。

無任何引用時，同鍵重建可合法提交；有引用時，可在同候選刪 P、重建 P、再明示重新宣告每個引用者的完整整組來源，經預覽／全量驗證後提交。同一候選有多次刪除，不能拿較早刪除後的宣告抵銷後一次刪除。匯入配號仍不得配到同候選剛刪的鍵，不以配號碰巧相同接上引用。D60 只決定已合法提交物件的新存在期，不豁免 I38；已啟用身分帳時卡片與欄位依 D60/R56 配新記號。

World 外預覽／證據若要主張身分延續，按 D62/R57 同時比較專案、鍵與記號；只有內容相同不夠。身分帳未啟用時，不虛構記號或宣稱已證明延續。Undo/Redo 恢復整份 World、映射及原身分帳，不重新配號。

**定義推論 C7：**I8a:925 規定即使沒有使用處也先預覽，I37 的網格交易與 R32:1645 的完整復原亦適用；所有整卡建立／改卡／映射／模式改動／解除一律走同一整組候選，無下游亦同。保存依 D9/I39 與 §5 的明示能力、定義重放及舊檔零自動轉換；不降級成兩個 ParameterRef。

### Q7：領域無關與 #248 邊界

**定義推論：**D31 的型別是 dimension/count/ratio，R33 明示卡片不是向量；模板名稱或快捷輸入不決定引用身分。

本提案只定義「一張卡的兩個明選長度 → 網格 u/v 的長度槽」。不按寬／長等顯示名稱匹配，不內建任一尺寸，不改目前範本，不在本 PR 把既有木工條文全面改名。依賴單向為模板提供卡片與明選對應，通用核心驗引用和幾何。#248 的其他解耦工作由其 owner 推進；本案無須等待全部重構，也不把研究當採納。

### Q8：驗收與突變

**定義推論：**現有逐欄測試只能證明逐欄行為，無法證明整卡的原子替換和保存。必須有新能力的具名測試，並保留原逐欄與 legacy-finite 回歸。

§6 每例指定輸入、精確結果與失敗不變量；§7 將每項新規則連到可被撤去的實作。這些是**待實作驗收計畫**，沒有把表格標成 pass。實作切片與可見介面減項仍待審查／採納，不由本文擴張授權。

## 4. 新增條文全文與對應白話

下列條文原文均為「無（新增）」，暫定號不表示已採納。

### D-CR1：網格卡片引用（GridCardReference）

```text
支援 grid-card-reference/1 的 D29 無限網格，可擁有零或一份卡片引用，作為其兩個軸長度槽的單一來源定義。
卡片引用保存一個 D31 parameterId，以及 uFieldId、vFieldId；兩欄必須屬於該卡且身分不同。
REPEAT 的軸長度槽為 step，REPEAT_PANEL 為 panel；兩軸皆須屬於這兩種模式，可互相不同。
所選欄位須為 dimension，其他合法欄位可共存；不以名稱、範本、顯示順序或數值大小推斷對應。
來源卡片不因被引用而變成向量、材料或另一種卡片型別，不反向擁有網格。
卡片引用沒有另一個獨立 World id，也不攜帶存在期記號；它是網格內部來源定義。
對調只交換兩個 fieldId 的軸對應，不交換其他軸設定、線索引、cell 錨點或世界框架。
```

白話新增段：

> 一個網格可以整組引用一張卡，並記住兩個不同長度欄位各給 u 還是 v。多出的合法欄位不礙事，也不會自動被挑進來。對調換的是兩個長度的去向，不是旋轉網格或交換其他設定。兩個長度相等仍是兩個不同欄位。

### I-CR1：完整、唯一且合法的整組來源

```text
卡片引用必須有現存卡片及完整兩軸對應；少一軸、跨卡映射、同一 fieldId 重用、型別不合均拒絕。
兩個受控槽不可同時有直接值、ParameterRef 或另一種來源；其他尺寸欄位維持原單一來源規則。
每個所選欄位先依 I38 求精確值，再各自驗 D1、D29 正值及全部目標限制；不把 count/ratio 當尺寸，不取整、不截斷。
任一依賴失敗整筆拒絕，錯誤列出網格、來源卡片／欄位、軸及違反條款；容量或精度不足沿 I33 明確分類。
不得因同名、同值或同鍵重建自動改映射、凍結長度或略過刪除保護；存在期與內部 id 引用仍分別依 D60、D62 處理。
同候選刪除並重建來源卡鍵時，每個最後仍引用該鍵的定義都須在最後一次刪除之後明示重新宣告；
只有重建、只有刪除前的宣告，或只處理部分引用者，均按 I38 整包拒絕並指名未處理者。
```

白話新增段：

> 兩軸的來源必須完整且唯一。缺卡、缺欄、型別錯、長度不合法，或其他依賴不成立，都整筆拒絕並指出哪張卡、哪個欄位、哪一軸出錯。不能用同名替代，也不能把分數四捨五入後套進網格。同鍵重建也須逐一處理舊引用；繼續指向該鍵的使用處，必須在最後一次刪除之後明確重新宣告。

### R-CR1：整卡交易、求值及保存

```text
建立或替換卡片引用時，明示來源卡片、兩軸對應及將被取代的來源；在同一候選驗證參數圖、整卡來源、網格與全部下游。
改卡、改對應、對調或改軸模式亦走相同候選流程，依 I8a 預覽、確認同一候選，再一次提交。
對調後須按新長度重新驗 D10b 等全部目標限制；相位差不對調，不代表原本合法的相位差仍合法。
來源卡改值仍依 R33 重算；同一格線／段／cell 的身分依 D29、D10b、D30 保持，幾何合法性不因此免驗。
整組解除須明選轉成兩個 ParameterRef，或轉成有序候選中該步的當下有效值，且兩值皆須是合法直接整數。
轉直接值後的卡片修改不回寫已解除的槽；該步缺來源或值不合法即拒絕，不借用後續步驟補值。
整包最後仍須全量驗證；不得只解除一軸或保留隱藏覆寫。
移除軸或換到非本能力模式時，須在同一候選明示解除整卡關係並提供新定義；沒有隱含轉換。
取消、失敗與過期不改正式 World、metadata 或 history；確認重驗全部依賴。Undo/Redo 恢復完整定義與適用的身分帳。
場景及完整專案依賴順序先保存來源卡片閉包，再保存網格的整卡來源、兩軸對應及其他原設定，後保存配置與下游引用。
保存包括未使用網格的整卡來源，不保存有效長度、抽樣線或使用清單作為另一份定義。
讀取要求 parameters/1 與 grid-card-reference/1；實際新資料即要求新能力，移除宣告不能繞過驗證。
完整專案格式依 I39 於實作時分配；D25 交換包依實際根依賴保留整卡閉包與能力。
未知能力、缺宣告、缺閉包、映射非法或容量不足，在替換當前 World／專案之前拒絕，不部分載入或降級。
舊直接值、ParameterRef 及 legacy-finite 定義原樣可讀，不以兩個引用碰巧同卡就自動合成整卡來源。
```

白話新增段：

> 選卡、換卡、對調、解除都先看整組結果，再一次確認。對調後要重新檢查相位差是否仍合法。可以整組拆回逐欄引用，也可以明確固定成有序候選執行到解除那一步的兩個有效整數；之後改卡不會回寫，其他來源不跟著消失。存檔與交換包會按各自範圍把完整卡片、對應與原設定一起保存，重開重新計算。不認識新資料就整份拒絕，不偷偷拆散；舊檔仍照原本方式用。

**不改 D60/D62：**新增條文引用其現有語意；不新增身分帳涵蓋種類，也不強迫舊專案啟用身分帳。對應白話 D60/D62 保持原文，不以本功能順便改寫。

## 5. 保存與相容契約草案

### 5.1 邏輯表示（非已支援的 API）

下列表示只定義不可遺失的資訊；正式 JSON／DSL 名稱由採納後的契約固定，不把例子交給目前執行器執行：

```json
{
  "cardReference": {"parameterId": 10, "uFieldId": 3, "vFieldId": 8},
  "u": {"mode": "REPEAT", "phase": -5, "stepSource": "card"},
  "v": {"mode": "REPEAT", "phase": 7, "stepSource": "card"}
}
```

`card` 是來源種類而非值或 ParameterRef；一份 cardReference 決定兩軸。無整卡引用的網格保持既有表示，不補空物件。兩軸模式與其他來源原樣保存；不能同時另存有效 step/panel，不能再存一個可能矛盾的 swap bit。

| 讀／寫情境 | 必須保持的規則 |
| --- | --- |
| 新執行器讀舊直接值或逐欄場景 | 原樣解析，無自動整卡化；同卡的兩個 ParameterRef 仍是獨立來源 |
| 新執行器讀舊有限場景 | 座標、條數、索引及 origin 保持；不因有參數卡就轉無限 |
| 含整卡的 `.scene` | 保存完整來源卡片閉包與整卡定義，宣告兩項能力；未使用的來源也不丟 |
| 含整卡的完整 `.gcanvas` | manifest 與 payload 均保留必要能力，格式號於實作時分配；不改 geometry-canvas/1–6 原義，既有 /6 不承載新整卡資料 |
| D25 交換包的根依賴整卡網格 | definitions 保留網格整卡來源、軸對應、所需卡片與傳遞閉包，manifest 宣告兩項能力；不以 derived snapshot 或有效長度取代定義，依 I31/I32 核對／拒絕 |
| 舊執行器／刪新能力標記／未知版本 | 新語法本身亦觸發能力需求；明確拒絕且保留當前專案，不做降級匯入 |
| 新功能資料不存在 | 不強迫提升舊檔能力、不插入 cardReference、不更改舊直接值或逐欄表示 |
| 參數包匯出／匯入 | 仍是卡片閉包，不帶外部網格；匯入新卡 id、保留 fieldId，使用者之後明選整卡來源 |
| 通用定義匯入（D55） | 本提案不擴張其可選根種類；目前未納入的網格不能藉本能力悄悄成為可匯入根 |
| 同專案完整重開 | 保留卡片／欄位 id、映射、其他定義與已啟用身分帳；重新求值 |
| 跨專案交換 | 不攜帶 incarnation；依 I39/D62 配新身分與適用記號，不能自動改指目的專案既有同名卡 |

舊 `parameters/1` 單獨存在時的既定格式接受規則不變（含既有契約的場景能力補註例外）；本提案的新能力門檻只適用實際含整卡資料者。格式號不是公理政策，但實作前必須公布確切版本、語法、能力表及舊／新讀寫矩陣並測試，不能以「稍後訂格式」為由只交介面連線。

### 5.2 草稿與 UI 的邊界

D57 的既有逐欄草稿白名單不因本文自動擴張。含新整卡編輯的草稿，需在採納後同步補上原始欄位、來源對應、過期／永久缺失檢查與必要能力；完成此契約以前不得把整卡草稿假存成舊逐欄草稿或宣稱支援暫存／續編。此項隨 UI 切片另交逐條 diff，不在本提案暗改 D57。

正式入口建議合併目前兩個長度槽的來源設定為同一來源區，保留逐欄模式，使用者明選整卡時才展開映射；不是新增一排永久按鈕。這是待審查的 UI 減項方向，實作前仍須依 GEO-219 在 BACKLOG 列實際減項。本 PR 不改 BACKLOG 或目前 UI。
