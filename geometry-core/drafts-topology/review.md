### F3 「同一已提交目標」以 id 判定，但 id 會被重用：舊草稿會搶走新物件（推不出唯一行為）
- 位置：AXIOM-DIFF.md:30、42、44-45；R⟨K2a-1⟩（AXIOM-DIFF.md:139）；I⟨K2a-1⟩（:92）；PROPOSAL M06。
- 證據：web_bridge.c:464-497 newid 的配發方式是「現有最大 id + 1」（WORLD_NEXT_ID，GEO-156）。刪掉編號最大的系統 2 之後，下一個新建的系統又會拿到 2。
- 反例：(1) 編輯草稿 E 指向系統 2（指紋 F）；(2) 刪除系統 2（A-9 允許），E 標成「基底已不存在」；(3) 新建系統，拿到 id 2；
  (4) 開啟「編輯系統 2」：依 R⟨K2a-1⟩ 會開到 E，而 E 其實是舊物件的草稿；依 I⟨K2a-1⟩ 不能再為新的系統 2 建編輯草稿，使用者只能丟掉 E 才能編輯。
  M06 的標示也會從「基底已不存在」變成「內容已變更」。如果新系統 2 的內容剛好和舊的相同（指紋相等），E 甚至會通過 pin 檢查，直接套到另一個物件上，
  這違反 D30「不以編號／位置猜身分」的同一紀律。
- 最小修改（擇一寫死）：(a) 基底缺失時，草稿永久標成「孤兒」：之後即使同 id 重新出現也不復活、不算同一目標、不佔用唯一性名額；
  或 (b) 唯一性只計算未過期的編輯草稿，開啟時讓使用者明選續開過期稿或新建。另補一條驗收：刪掉最大 id → 新建同 id → 開啟編輯。

### F4 過期的編輯草稿能不能「明選重新取得基底」沒寫清楚
- 位置：AXIOM-DIFF.md:44-45。
- 為什麼錯：「重新取得來源」裡的「來源」是否包含 baseRef？條文沒說。後面又加一句「不自動…改用新基底」，暗示可以手動改用新基底；

- 最小修改：明寫「重新取得只適用於 inputRefs；baseRef 不符時只能保留、捨棄」，或者明寫允許重新 pin 基底，並規定預覽要列出被覆蓋的差異。
