## Δ2 定義（插入於第 542 行之後，前面加一行空行）

```text

**D⟨Q38j-1⟩ 保存的空間模型（SavedSpaceModel）**：專案層的建模結果紀錄，不屬於 World：不進入場景 dump 或 World 定義指紋，也不被 World 物件引用。
它保存一份來源快照（建立或最後一次整筆取代當下的來源場景，即當時的 World 或內建範例場景）、建模設定（如牆底、牆高、牆厚、邊與封口用途）、
明選清單（障礙、角材、拉伸件），以及由這份來源快照依 D24 / D25 推導出的各交換包。
各交換包是 D9 所說的衍生快照；建模設定與明選清單是專案層的建模輸入，不是 World 定義；來源快照是當時來源場景的副本，不回寫 World。
單一來源版本：同一模型的全部交換包都由同一份來源快照推導。一個模型呈現某一時刻的設計；
把不同 World 版本的定義或幾何拼進同一模型，會得到任何 World 版本都不曾存在的配置。
不隨 World 改變：World 之後的重宣告、刪除、重算（R2、R6(e)、R40）或同 id 重建，都不改寫已保存模型；模型不保存對 World 物件的即時引用。
快照內的 id 只在該來源快照內有效：僅憑 id 相同或內容相同，不得把模型內的物件連到 World 中的物件，或宣稱兩者是同一物件。
可比對兩者內容是否相同並如實標示。模型以其來源快照的時點呈現，World 已變時不得冒充現況（D9）。
修改模型設定（如牆高）時沿用同一份來源快照重新推導，所納入物件的定義與幾何不變。
要改用另一個 World 版本，只能明選該版本與納入清單、重新推導全部交換包，經預覽核對後整筆取代紀錄（可一步復原），或另建模型；
不得只把其中部分物件或部分交換包換成目前定義。整筆取代後的紀錄同樣只有一份來源版本，保留的模型 id 不證明其中物件延續。
```

說明（不進條文）：
- 「單一來源版本」是本條的**規定**，不是定義推論：D25 只約束單一交換包，公理層原本沒有「模型」這個單位。理由見 `PROPOSAL.md` §2-1（S1 拼出不存在的配置）。
- 「來源場景」兩種來源都存在：從目前面建立為 World dump，試用內建範例為範例場景（`source.kind` 為 `scene`／`example`，`geometry-web/project-store.js:440`、`geometry-web/space-workspace.js:432,661`、`geometry-web/scenario_verify.py:408`）。
- 「建模設定」「明選清單」的實際欄位（`settings`、`obstacles`、`timbers`、`profile_runs`）屬產品契約，條文只舉例，避免把欄位名寫進 SSOT。
- 「修改模型設定時沿用同一份來源快照」是既有行為的形式化：`space-workspace.js:703,711`、`geometry-web/docs/TIMBER-IN-SPACE.md` T08、GEO-210 G06。
- 「整筆取代」是既有 #44 F1b「採用現行來源」的形式化：`geometry-web/model_update.py:367-413`（以 `current_scene` 與明選 selection 重算整筆紀錄、保留 id／name／created_at），回執 `identity:'unknown'`；2026-10-04 CONT-8 第 3 項採納。
