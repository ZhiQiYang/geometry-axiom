## Δ3 定義（插入於第 542 行之後，前面加一行空行）

```text

**D⟨K1-1⟩ 裁切設定（CuttingSettings；cutting-plan/1）**：專案層的使用者宣告，保存以下內容：
鋸縫 k、加工餘量 a、留用下限 r_min、D⟨K1-2⟩ 原材種類清單、D⟨K1-3⟩ 宣告餘料清單，以及兩份清單各自的 key 高水位。
所有數值都是直接整數 mm。本版不收 D6b、D31 或 D28 來源，設定也不被 D6a、D28、D31 或任何幾何定義引用。
k 是一次鋸切從料上移除的長度。鋸片有厚度，下刀必然移除材料；實際鋸路不是整數時，以不小於它的整數宣告。
因此 k ≥ 1 是定義推論。低估 k 會讓末件或剩料短於方案，這是硬失效側。
a 是每一需求件在完成長度之外另加、留待現場修切的長度，a ≥ 0。
r_min 是剩料可留用的最小可用長度，r_min ≥ 1。
k、a、r_min 未宣告時保持未設定；不從鋸片型錄、地區習慣、其他專案或材料名稱補預設值。
原材種類數與宣告餘料數的上限由執行器宣告。

**D⟨K1-2⟩ 原材種類（StockType；cutting-plan/1）**：保存以下欄位：
非零 uint32 key、名稱、截面 (A, B)、材料鍵、新料長度 S、原廠端修整量 e。
名稱為非空 UTF-8，至多 96 bytes；名稱不是身分。
截面比對不分順序，{A, B} 與 {B, A} 是同一種原材截面。
這是定義推論：橫切不改變截面，長方柱轉 90° 仍是同一支料。
材料鍵為「未設定」，或一個 D26 timber 材料版本的 (id, version, 內容指紋)；比對時三者皆等才算相同。
材料鍵只是比對鍵，不是尺寸來源，不構成 I34 的引用，也不阻擋 World 的任何操作。
所記載的版本不在計量世界時，此原材種類配不到任何需求件。
材料鍵「未設定」是使用者的宣告：此原材供應所有材料未設定、截面相符的需求件。這不是系統推定兩件需求同材。
e 是新料每個原廠端被切除的總長，含該刀的鋸縫，e ≥ 0；e = 0 表示原廠端面直接作為件的端面。
S 依 D1 為正整數，且 S > 2e。新料支數不設上限，方案推導出的新料支數就是需購入的支數。
宣告餘料是實物；原材種類被任何宣告餘料引用時，其截面與材料鍵不得修改（I⟨K1-1⟩）。要改，須新建原材種類。

**D⟨K1-3⟩ 宣告餘料（DeclaredRemnant；cutting-plan/1）**：保存以下欄位：
非零 uint32 key、所屬原材種類 key、實長 R、起端修整 h、末端修整 t。
它是使用者對目前持有的一段實物的宣告，不是加工紀錄。系統觀察不到實際鋸切，
所以方案、預覽、匯出或復原都不會新增、刪除或改變宣告餘料。
h、t 是排料時從該端切除的總長，含該刀的鋸縫，皆 ≥ 0。可用長度 U = R − h − t，須 ≥ 1。
key 在清單內唯一。高水位只增不減，刪除後也不重用，因為寫在實物上的標記（如「R7」）日後不得指向另一段料。
高水位為 0 表示已耗盡，此時新建一律拒絕。

**D⟨K1-4⟩ 計量世界與需求件（CuttingDemand；cutting-plan/1）**：一次裁切請求恰有一個計量世界。
計量世界是現行 World 的某一個定義指紋，或一筆已核對保存模型的 candidate World（沿用既有模型快照料單的核對）。
請求以零或多個範圍選取需求。每個範圍是下列兩者之一：某承載面的全部正式已放置角材，或某承載面上明選的 typed 角材集合。
需求件是範圍聯集中每一支 D7 已放置角材，實例鍵為 typed timber id（含 0）。
同一 id 不論被幾個範圍選中，都只計一件；不同 id 即不同件，即使截面、長度、範本或組構規則都相同。
不同計量世界之間沒有已證明的實物對應，所以請求不跨世界合併，
也不以 id、名稱、尺寸、範本、UUID 或世界指紋推定兩件是同一實物。
D36 斷面構件與 D3／D4 的面，不是本版的需求件。需求範圍是請求而非定義，本版不保存。
每件帶完成長度 L、截面、材料鍵及毛料長 C = L + a。L 取原生值（D7／R6），不另行計算。
材料鍵由核心決定：核心依 D28／R31 的查找鏈，求出每個 A、B 綁定的具型別末端來源，讀取介面原樣提供。
末端來源是一個材料版本 (id, version, 內容指紋)，或 literal、spec、parameter 之一。
前端不重做這條查找鏈，也不解析來源路徑文字。沒有工程來源的 A 或 B，視為非材料末端。
A、B 的末端都不是材料版本時，材料鍵為「未設定」；兩者是同一材料版本（三者皆等）時，材料鍵為該版本。
其餘情形依 I⟨K1-2⟩。

**D⟨K1-5⟩ 裁切方案（CuttingPlan；cutting-plan/1）**：由 D⟨K1-4⟩ 的需求件與 D⟨K1-1⟩ 的設定，依 R⟨K1-1⟩–R⟨K1-3⟩ 推導出的衍生結果，不保存（D9）。
每支被使用的料（宣告餘料或新料）是區間 [0, 長度]，0 為起端。起端修整為 h、末端修整為 t；新料的 h、t 都取 e。
件依放入順序從起端排列，相鄰兩件之間恰有一次鋸切，耗損 k。
鋸切是一次實際下刀，只有實際下刀才耗損鋸縫。設末件終點為 y：
- y = 長度 − t 時，末端只做修整，耗損 t；t = 0 時不下刀，原端面即是件的端面。
- y < 長度 − t 時，必須再下一刀分離（末刀），耗損 min(k, 長度 − y)。
剩料 = 長度 − y − 末端耗損。剩料為 0 時，沒有剩料。
剩料大於 0 時，其起端是新鋸面，末端沿用該料的 t，可用長度 = max(0, 剩料 − t)。
可用長度 ≥ r_min 為「可留用」，否則為「廢料」。
方案標示為「本次找到的方案」；本層不定義也不宣稱最少用料。
```

## Δ4 不變量（插入於第 880 行之後，前面加一行空行）

```text

I⟨K1-1⟩ 裁切設定合法：k、a、r_min、S、e、R、h、t 都是整數 mm，且在 D1 範圍內。
    k、a、r_min 已設定時，須 k ≥ 1、a ≥ 0、r_min ≥ 1。
    原材種類與餘料的所有欄位都必填：每種原材 e ≥ 0 且 S > 2e；每段餘料 h、t ≥ 0 且 R − h − t ≥ 1。
    材料內容指紋為 64 個小寫十六進位字元。小數、分數、空字串或超界一律拒絕，不取整、不夾值（同 D1／I46）。
    只有 k、a、r_min 可以保存為未設定；這是合法狀態，但有需求件時方案會不完整（R⟨K1-1⟩）。
    原材種類 key 唯一。任兩種原材的（不分順序的截面，材料鍵）不得相同；本版每種原材只有一種新料長度。
    餘料所屬的原材種類必須存在。仍被餘料引用的原材種類：
    不得刪除，除非同一次編輯一併移除或改綁那些餘料；
    不得修改截面或材料鍵（STOCK_TYPE_IN_USE），要改須新建原材種類。
    名稱、S、e 可以修改，因為餘料自帶 R、h、t，不受溯及。
    兩份清單的 key 高水位依 D⟨K1-3⟩，只增不減、不重用。
    原材種類數、餘料數與名稱長度超過執行器宣告的上限時，在保存驗證拒絕該次編輯，不截斷。
    每次編輯先整份驗證，全部成立才提交為一步專案歷史；失敗不改現有設定。

I⟨K1-2⟩ 需求合法、去重與歸屬（求值順序見 R⟨K1-1⟩）：
    (a) 計量世界：請求格式只帶一個計量世界（依 D⟨K1-4⟩），跨世界在格式上無法表達，不另設執行分支；世界種類非 live → UNSUPPORTED（WORLD_KIND）。
        執行器未宣告支援的世界種類回 UNSUPPORTED（WORLD_KIND），本版保存模型快照即屬此類。
    (b) 範圍：以同一次讀取的已放置角材清單預先核對。明選 id 不存在或不在該面時，回 INVALID（SCOPE_STALE）並要求重選；
        不以導出失敗的文字判斷，不改計為 0，也不推測改指其他物件。
        沒有產生任何需求件的範圍回 INCOMPLETE（SCOPE_EMPTY），不靜默丟棄。
    (c) 列：沿用既有角材料單的導出。導出失敗時，依其具型別失敗碼回 INCOMPLETE（ROW_NOT_READY 加細碼），不比對錯誤文字。
    (d) 材料鍵：讀取回覆缺少末端欄位時，回 UNSUPPORTED（NATIVE_CAPABILITY）。
        某綁定的末端為空（有效值無法求值）時，回 INCOMPLETE（MATERIAL_UNRESOLVED）。
        A、B 的末端分屬不同材料版本，或一邊是材料版本、另一邊不是，回 INCOMPLETE（MATERIAL_MIXED）。
    (e) 配料：每件恰配一種原材種類，條件是截面不分順序相等，且材料鍵三者皆等。
        配不到時，依下列順序取第一個成立的診斷，並列出所缺的截面與材料鍵：
        有原材種類與件的材料 (id, version) 相同但指紋不同 → INCOMPLETE（MATERIAL_FINGERPRINT_MISMATCH）；
        件的材料鍵已設定（非「材料未設定」），且有原材種類材料鍵相同但截面不同 → INCOMPLETE（STOCK_SECTION_MISMATCH）；
        其餘 → INCOMPLETE（NO_STOCK）。
        依 I⟨K1-1⟩，不會配到兩種原材。
    (f) 容量：範圍數或需求件數超過執行器宣告的容量時，在求方案時回 UNSUPPORTED（CAPACITY），不截斷（I33）。
        原材種類數與餘料數的容量屬 I⟨K1-1⟩ 的保存驗證。

I⟨K1-3⟩ 方案守恆，對每一支被使用的料逐支成立：
    長度 = h + Σ C_i + (n − 1)·k + 末端耗損 + 剩料，各項都是非負整數。
    每件區間 [x_i, x_i + C_i] ⊆ [h, 長度 − t]；相鄰件的間距恰為 k；件與件不重疊。
    末端耗損、剩料與可用長度依 D⟨K1-5⟩。
    下刀次數 = [h > 0] + (n − 1) + 末端下刀：恰到修整線時末端下刀為 [t > 0]，有末刀時為 1。
    每一需求件在方案中恰出現一次。未被使用的宣告餘料不切，也不計耗損。
    任何一支不成立都是執行器錯誤，不得顯示為完成，也不得匯出。

I⟨K1-4⟩ 唯讀與不回寫：
    求方案、顯示、排序、單位切換與匯出，都不改 World、角材長度、已保存模型、專案 dirty、歷史、裁切設定或宣告餘料。
    不得縮短需求件、加長原材或宣告餘料，也不得以接料（§四「料長續接」）求可排入。
    設件所配原材種類的單支最大可用長度 M = max(S − 2e, 該種類各宣告餘料的 U)；沒有餘料時 M = S − 2e。
    C > M 時回 INVALID（OVER_LENGTH），並列出該件、C 與 M。
    a 未設定時以 L 判定：a ≥ 0，L 已超過 M 就是任何 a 都超過；L 未超過時，留待 a 設定後再判。
    每件都 ≤ M，但排料時某件只能放進已被先排件占用的宣告餘料、新料又放不下時，
    回 INCOMPLETE（REMNANT_EXHAUSTED）：本次找到的方案無法排入；不宣稱料不足，也不宣稱不存在可行方案（與 D⟨K1-5⟩「不宣稱最少用料」一致）。診斷清單：各原材種類組各自繼續評估，每組只報第一件排不進的件。
    預覽不消耗原材。本版沒有「已加工」狀態，系統不記錄、也不宣稱任何實物已被鋸切。
    裁切設定的復原與重做只還原使用者的宣告，不代表實物恢復。

I⟨K1-5⟩ 能力、保存與狀態：新增能力 `cutting-plan/1`，依 I32 另行宣告。
    完整專案保存 D⟨K1-1⟩ 的全部內容，包括未被需求使用的原材種類、餘料及兩個高水位；不保存需求範圍與方案。
    含裁切設定的專案必須宣告此能力；遇到未知能力或 schema 一律拒絕，不降級為忽略。
    方案狀態沿用 D24 的詞彙：請求沒有任何範圍時是 EMPTY；其餘狀態依 I⟨K1-2⟩、I⟨K1-4⟩ 及 R⟨K1-1⟩ 的 MISSING_SETTING。
    多個原因並存時，整體狀態依 INVALID > UNSUPPORTED > INCOMPLETE 決定，並保留逐件診斷。
    OVER_LENGTH 歸為 INVALID：在「不接料」之下，宣告的需求長於所有宣告的料，屬 D24 所稱的已知矛盾，
    並非缺少明示資料；要解除，只能改宣告。
    本版不輸出部分方案（I31 的 allow_partial = false），只有 COMPLETE 可以匯出。
```

```text

R⟨K1-1⟩ 求值順序：
    (0) 請求檢查：沒有任何範圍 → EMPTY；計量世界的唯一性與種類依 I⟨K1-2⟩(a)；範圍數依 I⟨K1-2⟩(f)。
```

### 仍推不出唯一行為、或只能由使用者宣告的地方

1. **「材料未設定」的兩件是否同材**：物理上推不出來。條文改由原材種類的宣告決定，系統不宣稱兩件同材。
2. **原廠端是否需要修整、要修多少，以及餘料兩端的狀況**：只能由使用者宣告。skill 沒有記載修整慣例，系統也不提供預設值。
3. **鋸切與量測誤差**（skill 記載刀誤差 ±0.5mm）：屬 §四「容差」，不建模。
   方案中的位置是名目值，實物夠不夠長只能靠 k 取整往上與 a 吸收，條文本身推不出實物的實際結果。
4. **最佳方案**：未定義。唯一確定的是由 FFD 得出的「本次找到的方案」。
5. **同一 session 內同 id 刪除後重建**：以當下世界為準，不宣稱 durable 身分。
6. **原材截面與其材料版本 A／B 不一致**：只有當計量世界中有該材料的件時，才會以 STOCK_SECTION_MISMATCH 診斷出來。
   沒有該材料的件時，這個不一致不影響方案，所以不檢查（設定驗證是純函式，讀不到 World）。
7. **E1／E2 的部分 L 值**：依條文推導，尚未以原生實跑核對，實作時必須以原生讀值為 oracle。
8. **配號**：條號、格式號、`featureAttachments` 的 records 上限都須與另外 4 份提案統一配號。
   records 上限在 main 是 `> 3`，在 a7bff8f 是 `> 4`，寫入時以實際基底加 1。
