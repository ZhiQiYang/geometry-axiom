# K1 修訂 r1.2：宣告餘料的復原語意與 key 高水位（P-047）

- 狀態：**已寫入公理層**（commit 〔下一個 commit 回填完整 SHA〕，分支 `axiom/adopt-cutting-plan-k1-20261011`，PR #185）。定義推論，暫定（依 2026-10-09 授權 L）；主迴圈裁決 P-047。
- 觸發：PR #185 整合審查 dot 第 2 項，以及 Codex 實作前的停工回報。

## 問題

1. **字面矛盾**：D48 原寫「方案、預覽、匯出或復原都不會新增、刪除或改變宣告餘料」；I61 末句寫「裁切設定的復原與重做只還原使用者的宣告」。
   使用者新增一段餘料後按復原，依 I61 應還原宣告（清單變回沒有那段），依 D48 字面卻「復原不會刪除宣告餘料」，兩條推不出同一個行為。
2. **未定義**：復原或重做時，宣告餘料的 key 高水位要不要跟著回退，條文沒有寫。

## 推論（定義推論，不是取捨）

- D48 那句的意旨是「**系統動作不得模擬實物加工**」：系統觀察不到實際鋸切，所以求方案、預覽、匯出，以及與餘料無關的其他操作的復原，都不能讓餘料憑空出現、消失或變短。
  使用者對宣告餘料本身的編輯，就是使用者改變自己的宣告；這類編輯的復原與重做仍是使用者在改宣告，是改變清單的唯一途徑。I61 說的正是這件事。
- **高水位是系統計數器，不是使用者宣告**。D48 已定高水位只增不減、刪除後不重用，理由是實物上寫的標記（R49 的 R<key>）日後不得指向另一段料。
  使用者可能在復原前已把 key 寫在料上；若復原讓高水位回退，下一段新料會拿到同一個 key，正是 D48 要排除的情況。所以高水位不隨復原或重做回退。

## 修文（只改兩句）

| 條 | 原文 | 修訂後 |
|---|---|---|
| D48 | 所以方案、預覽、匯出或復原都不會新增、刪除或改變宣告餘料。 | 所以方案、預覽、匯出，以及其他操作的復原，都不會新增、刪除或改變宣告餘料；只有使用者對宣告餘料本身的編輯及其復原／重做會改變清單。key 高水位不隨復原或重做回退。 |
| I61 末句 | 裁切設定的復原與重做只還原使用者的宣告，不代表實物恢復。 | 裁切設定的復原與重做只還原使用者的宣告（含宣告餘料清單），不回退 key 高水位，也不代表實物恢復。 |

白話 D48、I61 同步。

## 驗收例（實作 K1-b 的 `tests/test_cutting_project_store.js` 須逐例覆蓋，並做突變測試）

| # | 操作 | 預期 | 要打掉的變異 |
|---|---|---|---|
| U1 | 空清單、高水位 1 → 新增一段餘料 → 復原 → 再新增一段 | 第一次新增得 key 1、高水位變 2（下一個可用 key 為 2）；復原後清單為空、高水位仍為 2；再新增得 **key 2** | 復原連高水位一起回退，再新增又得 key 1 |
| U2 | 新增一段餘料得 key 1 → 復原 → 重做 | 重做後 key 1 那段原樣回來（R、h、t 不變），高水位不變（仍為 2）；不另配新 key | 重做時重新配 key，或重做讓高水位再加一 |
| U3 | 有 key 1 一段餘料時：求方案、預覽、匯出；做一個與餘料無關的操作（例如改鋸縫 k，或改 World）再復原 | 清單逐位元組不變、高水位不變 | 復原無關操作時把餘料清單一起回到更早的狀態，或求方案、匯出時改動清單 |

說明：U1、U2 的「高水位」指 `nextRemnantKey`（下一個可用 key，見 `PROPOSAL.md` §4.1）；「key 1、高水位仍 1」的說法若以「已用到的最大 key」計，等價於上表。
原材種類的 key 高水位（`nextStockKey`）同理：同樣不隨復原或重做回退。

## 如何推翻

改 D48、I61 這兩句與上方驗收例；若要讓高水位隨復原回退，須先另立「實物標記不得改指」的替代保障，因為那是 D48 不重用 key 的理由。
