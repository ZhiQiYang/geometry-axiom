# 後續設計評估：唯一 ID 的單一區間支配查詢

這是未實作、未量測、未驗收的候選方向；不屬於這次 bitmap／單次壓緊產品變更。

若**全部輸入 member facts** 的 ID 唯一，而且查詢仍在現有容量內，原排序 order 與遮蓋 earlier 順序一致。不能只檢查已收集的面：未放置、被排除或容量截斷以外的事實，也參與原 order 索引。重複 ID、超容量或任何尚未證明的情況，一律保留完整原語意後備。

在這個受限路徑，RC 前綴先進索引；member tail 依穩定排序後的相同 order 分批。整批先查詢較早 order 的存活面，批末才把本批存活面加入。因此同 order 的面不會互相遮蓋，未來較晚 order 也不能回頭刪除前面的面；索引只需要插入，不需要刪除。

依完整 `fixed` 分組，每組依完整 `lo` 建座標索引，保存每個 lo 前綴中的最大 hi 及其單一見證面。Fenwick prefix-max 等插入查詢結構可能給 O(F log F) 工作量；這裡尚未證明整個 collector 的總成本，原 insertion sort 若維持，總體仍可能有平方項。

查詢不能把多個相鄰或重疊區間的聯集當成單一覆蓋面。原判斷必須同時滿足：

```
j.fixed == i.fixed
j.lo <= i.lo && j.hi >= i.hi
i.lo < j.hi && j.lo < i.hi
```

一般正長度 i 可使用 lo≤i.lo 的前綴、查 max hi≥i.hi。零長度或反向的公開事實仍可能被一個嚴格包圍它的正長度 j 遮蓋，不能直接視為無效面：i.lo≥i.hi 時，必須查 lo<i.hi 的嚴格前綴，並要求 max hi>i.lo。不得做端點 ±1 或相減比較，以免 GeoCoord 邊界溢位；使用原完整比較及明確 inclusive/strict 二分界線。

索引候選必須是一個當下 active、原判斷可用的面。前綴最大值應保留有效旗標與原面身分，不能靠虛構 sentinel 或把幾個面合成一面。索引不改輸出順序，最後仍按原穩定順序輸出。

必要新正反例包含：相同 order 不互遮、不同 fixed 的完整 64 位差異、兩個半面聯集不能刪完整面、零／反向 i 被嚴格包圍與端點相等的區別、RC 截斷、filtered facts 的重複 ID、同 ID min/last 循環退回原算法，以及所有舊原子容量與 owner/pointer 斷言。

先做等價／操作計數對照，才能決定是否實作這個更大的變更。不採用新時間或記憶體通過門檻。
