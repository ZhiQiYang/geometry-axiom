## 環境與方法

| 項目 | 值 |
|---|---|
| 程式版本 | main `04ba0adc99be33e93d99a36f48b3d5d997e97673`（#371 合併後） |
| 啟動 | `npm run build` → `python3 geometry-web/start_local.py --port 18839`；`runtime_version.py --probe 18839` 回 `fresh:true`、version `f02464ed510820082080cf046d88c15783e2bafe93d3697f3aa4cc8911ef7994` |
| 機器 | 雲端 Linux 容器（`Linux 6.18.44`，`cc` 13.3.0），不是使用者的 Windows 本機 |
| 瀏覽器 | Playwright 1.63.0 驅動 headless Chromium 153，視窗 1400×900，滑鼠／鍵盤實際點按 |
| 腳本 | `scripts/`（`lib.js` 共用；每項一支 `walk_*.js`）；每項先「檔案 → 新專案」再開始，避免伺服器上前一項的世界殘留 |
| 結果 | `walk_*.result.json`（腳本當下讀到的畫面文字）、`screens/*.jpg`、保存出來的 `.gcanvas`／CSV |

操作一律走畫面上的按鈕、選單、欄位。只有兩處用 `page.evaluate` 唯讀：

- R07 校準時，用 App 自己的 `feUlImgToMm` 算出「底圖第 30、290 px」在螢幕上的位置，再用滑鼠點下去。
- R09a、R10 用 `identity-read`（唯讀 API）確認身分帳是否已啟用。

保存與開檔：headless Chromium 沒有原生檔案對話框，腳本把 `showSaveFilePicker`／`showOpenFilePicker` 設成 `undefined`，
讓 App 走下載與 `<input type=file>` 的後備路徑，與 CI 的瀏覽器測試相同。Windows Chrome 上使用者會看到原生對話框，這部分未核對。

**界線：** 這是雲端的實際操作核對，不是使用者驗收（L5）。沒有核對：Windows 本機、實體觸控、中文輸入法、原生檔案對話框。

## 操作中發現的問題（都不擋上面判定的可用範圍）

1. **重複開間預覽直接顯示原始 JSON**（R06）。預覽的「來源」欄位把整段 `{"bindingId":1,…}` 給使用者看（`screens/R06-3-bay-preview.jpg`）。
2. **網格兩軸相位差的拒絕訊息放錯標題**（R18）。拒絕原因出現在「斷面與拉伸的連動影響」標題下，並帶著 `I43-I49 line 45: I24: …；預期："valid atomic transaction"；實際：…` 這種核心原文（`screens/R18-1-both-axes-rejected.jpg`）。
3. **刪除影響預覽同樣的標題問題**（R11）。刪除有參考線的面時，主交易被拒的原因同樣顯示在「斷面與拉伸的連動影響」下，訊息是 `I8a: impact preview required…`（`screens/R11-5-delete-preview.jpg`）。2 與 3 看起來是同一個根因：主交易本身被拒時，斷面複驗段把主交易的拒絕當成自己的連動結果列出。
4. **啟用身分帳後，空間建模的下一步一定被判為過期**（R09a）。在「以此面建立空間」裡按「啟用物件身分追蹤」後，接著按「確認用途與觀看方向」會被拒：「來源或專案已變更。請重新『使用目前面』」，使用者得自己再按一次「使用目前面」（`screens/R09a-1a-stale-after-activation.jpg`）。原因：`space-workspace.js:588` 拿「使用目前面」當下的場景快照比對，而 `activateIdentity()`（`space-workspace.js:270-296`）本身就會改場景。這牽涉 K3-44 的快照守門，未在本次改動。
5. **參數 ID 起點不一致**（觀察，不是錯誤）。UI 新建的第一張參數卡是 #1，R08 匯入到沒有參數的專案時配到 #0（`參數 1 → 0`）。原生測試也用 `card(0, …)`，0 是合法 ID。
