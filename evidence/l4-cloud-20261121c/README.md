## 環境與方法

- 乾淨的 main `1b1c6674` 工作樹（只多了本目錄）。用 Node 24.22.3（官方 tarball，SHA256 已核對）、`LANG=C.UTF-8`、`ulimit -s 16384`、`GEOMETRY_FEEDBACK_DIR=<scratch>`。
- 啟動：`npm run build` → `python3 geometry-web/start_local.py --port 18839`。
- `runtime_version.py --probe 18839` 回 `fresh:true`、version `e6574fc2a0e58f94b62563fe0d9be08d1dd75f929396b76559bbc350f170e61b`，原件在 `main-1b1c6674/runtime-probe.json`。
- 瀏覽器：Playwright headless Chromium，1400×900；R16 另開 390×844。
- 存檔時把 `showSaveFilePicker`／`showOpenFilePicker` 設成 `undefined`，走下載與檔案欄位的後備路徑，下載檔名因此是 `download`。冷開都是全新的瀏覽器，先「新專案」再「開啟專案」。

- `page.evaluate` 只做三件事：
  - 讀畫面文字與狀態：`dump`、`objects`、`ReferenceWorkspace.getSpaceModels()`、`ReferenceWorkspace.active()`。
  - 把面內 mm 或底圖座標換成螢幕座標，再用滑鼠點。
  - 用 `elementFromPoint` 查某點最上層是誰。
- 所有變更都經由滑鼠點擊、鍵盤或右鍵，沒有用 bridge 指令或 JS 改狀態。
- 「零寫入」用 `dump` 逐字比對。空間模型與工程覆寫不在場景行裡的，另外比模型紀錄或解碼後的 engineering 行。「一筆歷史」用「按一次 Ctrl+Z 剛好回到確認前、再按一次回到更早一步」來證明。
- 重現：

  ```sh
  OUT=evidence/l4-cloud-20261121c/main-1b1c6674/<編號> node evidence/l4-cloud-20261121c/scripts/walk_<編號>.js
  ```

### 21c-5（D06）：用不等價輸入觀測到的 PDF 照描寬度差異

兩份原 PDF 第 2 頁使用不同的輪廓。`two-page.pdf` 的末段是 `220 200 l 60 200 h S`。`h` 從目前點 (220,200) 閉回起點 (60,40)，前面的 `60 200` 沒有 `l`，因此該處沒有頂點。`two-page-explicit.pdf` 的末段是 `220 200 l 60 200 l 60 40 l S`，路徑經過 (60,200) 再回起點。這些是 PDF 頁面座標。

原雲端 Chromium 以相同六個預定點位照描。下表是 Enter 後外環的實測值，單位為 mm。[四筆原始收據](main-1b1c6674/D06/probe_d06_snap.result.json)

| 第 2 頁輸入 | 吸附開（左邊 x／寬度） | 吸附關（左邊 x／寬度） |
|---|---|---|
| `two-page.pdf`（五個頂點） | 500／2500 | 600／2400 |
| `two-page-explicit.pdf`（六個頂點） | 600／2400 | 600／2400 |

原腳本 `scripts/probe_d06_snap.js` 的 `expected` 記錄預定點位。[審查 7058600652](https://github.com/ZhiQiYang/geometry-axiom/pull/432#issuecomment-7058600652) 已核對兩份 PDF 的原始位元組與產生器。

[ChatGPT 的 close-current-point 分析](https://github.com/ZhiQiYang/geometry-axiom/pull/432#issuecomment-7057226577) 用明示的縮放與格距重播 App 函式。原檔最後一次點按的位置缺少 PDF 端點，重播時退回格線至 x=500 mm；按 Enter 補直角並移除共線點後，外環寬 2500 mm，點列與原收據相同。原 Chromium 收據未記逐點縮放、格距與解析就緒時間。此次紀錄更正未另做幾何等價 PDF 的真瀏覽器對照。原次執行的根因**未確認，修正另案處理**。

該分析另以 `h` 後接 `l` 的路徑驗出延續線段遺失：`pdfSnapFeatures` 在閉合時清掉目前點，後續線段因此失去起點。候選修正 P 在閉合後保留子路徑起點。原 D06 兩份輪廓畫回起點後都以 `S` 結束，這四筆收據沒有覆蓋延續線段。

`pdfSnapFeatures` 也用在「選房間」的向量候選（R22），D13 走的時候吸附是關的。
