## 啟動參數與新輸出

root 給完整 L2 SHA、確認主樹 checkout L2 clean 並明確排程後，才填入參數執行。canvas 的原 `--label L-formal` 是工具固定的正式模式名稱，輸出及 sourceSha 區分 L2，不改工具 enum。

canvas launcher argv：

```text
env -u CC -u PYTHONOPTIMIZE python3 -B /workspace/geo261-evidence/canvas-L-preparation/launch_canvas_job.py
  --sha L2_SHA --root /workspace/geometry-axiom
  --output /workspace/geo261-evidence/canvas-L2-formal-L2_SHORT
  --port 18856 --cdp-port 9322 --release-note ROOT_實際放行原文 --execute
```

five launcher argv：

```text
env -u CC -u PYTHONOPTIMIZE python3 -B /workspace/geo261-evidence/browser-five-preparation/launch_browser_five.py
  --sha L2_SHA --run-id l2-L2_SHORT-formal
  --output /workspace/geo261-evidence/browser-five-L2-formal-L2_SHORT
  --release-note ROOT_實際放行原文 --execute
```

上述是 argv 模板，不是可直接執行的 shell 指令。正式時以 argv 陣列建立最外層父程序，保存完整命令／環境清除／來源與工具 hash；父程序對 launcher 的真 `wait` 碼另寫 `.launcher-exit-code` 與完成收據。原 launcher 已保存 wrapper 真 wait 碼、stdout/stderr 原 log；Node 真碼由原 wrapper 保存。工具 session 若失聯保留未知，不由 passed 推測 top exit。外層若收到訊號只處理自己的直接子程序，不廣殺 Chrome。保留所有層的開始、PID、結束與真碼。

five 不帶 `--suite`，完整依 assembly→documents→grid→space→timber 執行；一個失敗會原樣停止並保留該輪結果，不能跳過後稱全五完成。每項完成即回報。canvas 完成及自有 cleanup 後才開 five；同時最多一 browser。

## 來源、執行檔與環境綁定

1. 開始前記完整 L2、branch、tree、clean 與四 wrapper hash。將實際 browser 入口、golden、workflow、package、start_local/runtime、所有 wrapper 記錄的來源逐項比對 L2 Git blob；L2 若只有 ledger 更新亦保留實際 L2 checkout，不把 A2 推導結果標成 L2 實跑。
2. 原 `npm run build` 等於 `python3 geometry-web/start_local.py --build-only`。build 與 service 皆走原 `prepare_binaries`，對三支 binary 做 `require_fresh`（`start_local.py:75–96`）。保留 build/server 的 `LOCAL_RUNTIME`，逐項保存 binary 路徑、長度、SHA-256、mtime 及原 sidecar bytes，核 sidecar 的 compile command、files/fingerprint、exe hash/size/mtime 與 L2 來源。five 原 wrapper 已有 `native-identity.json`；canvas 另做完成後資料核對，避免假稱是原 wrapper 內建欄位。可在服務 ready 後保存當時 sidecar／binary identity，完成後再比，均標實際採樣時點。
3. runtime 前後須 fresh、root 正確、同一自有 PID/session/version。不能用另一 checkout 的 fresh、舊服務或任意相同 binary 代替。fresh 不等於重新編譯，`built`／`reused` 依本輪原 log 記錄。
4. 父啟移除 `CC`、`PYTHONOPTIMIZE`，不加 `-O`；原 wrapper 設 16 MiB stack、清 inherited GEOMETRY flags，保留 `/usr/bin/chromium --no-sandbox` 及實際版本。字型必須驗已裝 `fonts-noto-cjk`、直接 Noto CJK 匹配與字型檔 hash，另外保存 default sans；不要求 default sans 首選是 Noto，不再次安裝或調系統字型。
5. canvas 的 feedback/profile/XDG 使用本輪 PID 專屬名稱；five 的獨立根為 `/tmp/geo261-browser-five-l2-L2_SHORT-formal/<suite>`，documents 自己在該 TMPDIR 建 profile。output/temp 不存在才准開始。server 的 TMPDIR 固定 `/tmp`，測試 screenshot/download roots 獨立。原 subreaper/pidfd／owned-PID cleanup、最後無 live/zombie 與 HTTP/CDP `ECONNREFUSED` 仍必核，不處理其他 agent 程序。

## native 並行判定

目前實際程式入口支持「native 初建完成後，native 與一個 browser job 並行」，不需要把 browser 指向 native 的共用 binary。

* native 在 `/workspace/geo261-native-<L2標記>` checkout L2；`tests/binaries.py:47` 的正式輸出為 `/tmp/geometry-tests`。`run_all.py:1082–1088` 初建使用 build lock；`546–556` 給各 suite fresh overrides。`_bridge.py:55–81` 與 `test_scenario_verify.py:47–59` 在缺 override 且 stale 時仍有重建 global bridge/model-base 的入口，所以不宣稱 native 全期間絕不寫 global。
* browser 主 root 是 `/workspace/geometry-axiom`。`start_local.py:26–31` 以 resolve(root) SHA-256 前 20 位分目錄，主 root 是 `/tmp/geometry-runtime/b9bc23103ebb114398f3`，與 native global 完全不同。`75–79` 只將動態載入的私有 registry.OUT_DIR 改到這個 root；`102–110` 將絕對 binary 路徑交給自有 server。
* `test_local_launcher.py:20–23` 從測試自己的 checkout 載入入口；其唯一真 build/service 測試 `167–192` 只讀 native fresh originals，再 copy2 到其 TemporaryDirectory 的 explicit binary-dir 或 temp/root-hash。其他 launcher 測試使用 mocks。`test_binaries.py:25–39` 把 ROOT/OUT_DIR/REGISTRY 及 compiler 換成私有 fixture，不是覆寫 browser runtime。
* 有界檢索已查正式 `tests/*.py`、已登記入口與必要 helpers，未見硬編碼 `/workspace/geometry-axiom` 的 runtime writer。不能把這個檢查擴稱任意未登記程式的形式證明。以上 browser/native入口在舊 L→目前 A2 沒變（唯讀 Git diff exit 0）；L2 出現後仍核其來源。
* `run_all.py:1115–1129` 是逐 suite 同步迴圈，沒有多 worker 總調度；`525` 的 `node --test` 多檔保留 Node 原預設 file concurrency，不可宣稱所有子程序單 worker。root 的「最多兩 heavy」以兩個 job 計，無 ledger／其他 heavy 同時執行。

root 已採最少變更排程：不預置或搬移 browser binary，不指向 native global，不新增這類工具。native 與 canvas 可並行，但 canvas 在 native 初 build 完成且原 binary index 保存後才啟動。原 wrapper 仍讓主 root 私有 runtime 的 npm build／require_fresh 正常建置與裁決；built／reused 完全依原 log 記錄。最多兩個 heavy job，原 2100 秒不變；CPU／IO 爭用列為本輪未排除限制。

實際放行仍須兩根 resolve 不同、runtime 不被 symlink 指到 native global、前後三檔 hash/mtime 與 sidecars 核對、沒有另個 browser writer。主要未確定處是 CPU／IO 爭用對 35 分鐘期限的影響，不能事前保證通過；若 binary/path 證據不符，就退回 native 完成後順序，不延長期限。native 啟動前的 global 目錄移存必須在 canvas 開始前完成；canvas 原硬路徑 assembly PNG 在完成後立即捕捉，避免下一工作移存或覆寫。
