## 候選內容與規格

`geometry-web/uiux_review_test.js:219` 原四條件均保留：成員數字串為 `0`、SVG 無 polygon/rect/path、空態存在、文案含加入或成員。候選將四條件擷取為具名狀態，於同一題增加 metrics 必須 hidden 且文字為空，沒有刪除題目、改 golden 或縮小選取範圍。缺少空態時由原本可能拋錯改成具名條件失敗，並不使它通過。差異是一個 check 換成一個 check，完整模組仍預期 69 題。

`app.js:3482–3558` 先以成員面與柱樑實體足跡計算範圍。候選沿用既有 `noGeometry`，清除並隱藏空態 metrics；回到非空時解除 hidden，原同步函數重建文字與格線。這符合公理 D5 空集合不產生有限範圍與 DOM 空態契約，沒有把零成員直接視為不得呈現任何幾何。

`app.js:3637` 的同步 guard 改查 SVG 真正的 hidden attribute，並要求 viewBox 已建立。正常幾何分支在呼叫同步前一定設定 viewBox，柱或樑也參與範圍計算，因此沒有成員、但有合法柱樑足跡的空間仍可通過 guard。缺 viewBox 時提早返回，亦避免初始尚未建圖的 SVG 產生零範圍裝飾。此 RC-only 相容性是程式路徑審查結論；本輪轉換 browser fixture 使用成員面，沒有獨立實跑 RC-only 情境。

原同步使用 `svg.hidden`，但真瀏覽器中 SVG 此 property 為 undefined，hidden attribute 為 true 時 CTM 仍可為單位矩陣。空態清圖後自然 observer 添回裝飾的診斷可支持此機制。隱藏 SVG 中的零尺寸 rect 並不是實際可見的有面積房間；真正可見瑕疵是 SVG 外的零範圍或前空間 metrics。不能把這兩者混述。

## 採入後仍待驗與最不確定處

v2 full 直接 require 磁碟的原 `uiux_review_test.js`，所以本輪候選 69/69 是候選 app 搭配原四條件版，尚未實跑候選新增 metrics 的同題斷言。新增條件的行為由轉換 6 題獨立支持，仍須正式套入後以 `none` 模式跑強化後的 69 題，再做 `actualFixed=true` 的精確撤回自證。正式來源完整 canvas 及其他必要驗收由主代理處理，本報告不宣稱已完成。

最大不確定處是原完整 canvas 失敗瞬間的 DOM 沒有保存。現有來源、自然最小 browser、真轉換及明示 callback 控制互相支持此根因，但不能宣稱精確重演原 fullcanvas 每一個 observer 排程。原完整 P73 曾自然 69/69，單撤 guard 自然 6/6，也已保留此限制。
