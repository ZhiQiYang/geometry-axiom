# P-189 複測方法

本次依交接 `59796b1af9259eb23d30134c2ce5a56317a06091` 的 `handoff/scripts/fix_verify.sh` 與 `scale_compare2.py`，對以下三個已提交版本重建同一 `web_bridge.c`：

- main：`adbaebf9c73ea6801d7b4d5214e4b846b132923b`
- 修正前 base：`3e600772076465fc65a26ac09055028301c0fb0b`
- 本次 final：`7dae5f21c7ca401e660450d437e60ba566218da8`

編譯命令是 `gcc -std=c11 -O2 geometry-web/web_bridge.c -o bridge -lm`。執行時使用 16384 KiB stack、停用 core dump；產品來源只從指定 commit 的 Git archive 取出，不使用工作區未提交內容。測量器及編譯產物放在 repository 外，不改產品、`tests/*.py` 或公理。

產生器沿用交接 `handoff/drafts/issue300/bench/gen_scene.py` 的 single 家族。N=16、32、48、64，各量三輪；偶數輪 main/base/final，奇數輪 final/base/main。每筆重開程序，在 `Popen` 回傳後、`communicate` 送 `loadfile` 前開始計算 wall time，直到程序結束。包含該起點之後的初始化和退出成本，不包含 `Popen` 自身的全部啟動成本，也不扣除固定成本；這與交接 `scale_compare2.py` 相同。採各版本三筆中位數相除，每一個 N 都必須 `final/main <= 2.0`，任何一次 timeout、載入失敗、非零退出或缺樣本都不算通過。

等價比對沿用 `fix_verify.sh` 的原判準：四個產生器場景以及 base 的全部根目錄 `.scene`，比較 base/final `loadfile` 加 `dump` 的完整 stdout 位元組。根目錄含刻意非法的案例，所以其預期 `ok:false` 不額外判成效能失敗；仍要求程序正常退出、回傳兩份有效 JSON，並由完整 stdout 比對確認拒絕行為一致。三方都執行，但既有根目錄場景的 main 比對只作附加紀錄，避免把兩版本新能力差異變成額外門檻。四個產生器場景則三方 `loadfile`、`dump` 都必須 `ok:true`，且三方完整 stdout 位元組相同。

原交接腳本只列出時間，不會因超過 2 倍、載入失敗或缺樣本而回傳失敗；本次另加收據判定器以確實執行 P-189，沒有放寬門檻。`selftest` 以正常、超標、缺樣本、載入遭拒、程序崩潰及故意改動某版本 dump 的控制檢查判定器；錯誤必須包含 N、版本或病因。這是量測工具的突變自證，本次沒有產品修正可撤銷。

收據判定另要求每筆時間為有限正數，逐筆樣本 SHA 與要求的三個 commit 相符，並核對 dump 等價及建置收據的 commit 集合。`--final` 換成其他 SHA 不能重用舊樣本冒充新版本；錯 SHA、NaN、Infinity、零及負時間都有負控制。各階段保留當時實際使用的測量器 hash，後續加強判定器不回填修改既有階段的 hash。

執行命令（都由 `/workspace` 執行）：

```sh
python3 /workspace/geo261-evidence/p189/p189_verify.py selftest
python3 /workspace/geo261-evidence/p189/p189_verify.py build
python3 /workspace/geo261-evidence/p189/p189_verify.py equivalence
python3 /workspace/geo261-evidence/p189/p189_verify.py timing
python3 /workspace/geo261-evidence/p189/p189_verify.py check
```

`build` 可以和一般測試並行；`timing` 等主代理安排獨占時段。正式結果以 `receipt.json`、逐筆 `samples.json` / `samples.tsv`、`dump-equivalence.json`、原始 stdout/stderr 與各階段執行紀錄為準。本文件不預先宣告通過。

限制：這是同一 Linux 容器內的 bridge `loadfile` 比較，不測 Python 模型更新、瀏覽器互動、使用者原 WSL USB HDD 或完整專案讀檔耗時。舊記錄已有相同 #321 產品碼在雲端和 WSL 不同倍數的情形，本次會保留環境及原始時間，不以先前 WSL 1.94 倍代替本次判定。
