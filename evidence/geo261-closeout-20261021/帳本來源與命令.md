判定為 **70 killed、1 crashed、4 equivalent、3 retired**，沒有新增或改寫判定。core 基準的 165/165 綠結果與基準 binary 在本輪共用，57 筆中的相同 baseline 收據不是 57 次各自重跑。bridge 也先共用一次 27/27 baseline；每個 mutant 完成後各自復原來源、重建及跑共同 27 方法，18 次復原全綠且 binary 與該基準相同。這些共用均由既有 `mutate.py`／`mutation_bridge.py` 流程提供，未更動官方裁判。

唯一 `crashed` 是 M20：三次均在 `_test_lshape.scene` 出現 mutant native exit `-11`；三次裁判程序的 exit 均為 `2`（各 164 pass／0 fail／1 infrastructure）。這是既有重複異常退出規則的偵測，**不是斷言 killed**。M36 的 equivalent 理由內 7143 組差分是 2026-10-01 的歷史實證；本輪只按現行 165-case 裁判執行，不宣稱重跑該歷史實驗。

證據限制：core 工具只在原帳本保存結構化裁判結果及各子程序 stdout／stderr 的 SHA-256，**沒有另存每個 core 子程序的原始 stdout／stderr**；上表完整 `mutate.stdout`／`mutate.stderr` 僅屬頂層，不能補回未保存的子輸出。bridge 的 build／baseline／mutant／restored 原始 stdout／stderr 另存於[bridge 原始輸出目錄](ledger-S3-cc/執行原件/raw/bridge)；逐筆位置與 hash 仍以原帳本為準。`--check`／`--check --killers` 的 0 證明既有判準下帳本一致，不能消除此 raw 缺口，也不替代其他 L3 驗收。
