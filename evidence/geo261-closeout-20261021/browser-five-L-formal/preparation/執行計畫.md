本文件只整理唯讀調查結果，尚未啟動五項驗收。初始指派來源 S 為 `ab6869b86a4ad82345359b72397fc055280d8308`；規劃期間架構登記完成為 A `7159530c0e494d3211e6ab1764eb691137211707`。真正執行將使用主代理明示凍結的最終 ledger L 完整 SHA；不把規劃時 SHA 當成已執行來源。工作樹、來源 hash、命令與版本都在每輪起訖重新記錄。

依據是目前 `.github/workflows/integration-tests.yml:35–160`、`geometry-web/start_local.py`、三支正式 browser harness、`cdp_floor.js`、`space_test_floor.js` 與 `docs/SPACE-GROUP-VALIDATION.md`。沒有引用交接 WSL 題數作通過預設，沒有新增正式工具或改 repo。

本機每項在 `npm run build` **之前**啟動同一個 monotonic 總期限（900／600／900／900／1200 秒），依序計入 build、`start_local` 的新鮮度檢查、啟動探測、browser 與正常收尾。每一子步驟只可使用剩餘預算，不能另外給測試一整段 15／10／15／15／20 分鐘；強制收尾另外記錄短暫 grace 時間。workflow 的分鐘數是整個 job，還含 checkout 與字型安裝；本機 checkout 已存在、`fonts-noto-cjk` 已安裝，只保存 `fc-match`／`dpkg-query` 核對，不再 apt，也不宣稱精確重現 GitHub job 的所有牆鐘成本。若被 deadline 中止，原 node 結束碼、signal 與 timeout 分開記錄，不捏造成斷言失敗或正常完成。外層期限 wrapper 的實際 bytes/hash、argv、環境、monotonic 起訖與每步剩餘預算另存證據。

## 來源與 runtime 新鮮度

1. 等 L 與排程放行；起跑要求 `git rev-parse HEAD` 精確為 L，`git status --short` 為空。記錄完整 SHA、分支、workflow／harness／helper／golden 的 SHA-256，以及 Node、Python、Chromium、核心版本、CJK 字型查詢與負載。保留命令、cwd、完整明示環境及被移除旗標名稱。此階段不變動套件或來源。
2. `ulimit -s 16384`，或於外部編排程序為其自己的子程序設定同等 16 MiB stack。每項用新的 feedback、cache、暫存與 profile。環境先移除所有繼承 `GEOMETRY_*`，再只加入下列明示值；清除 `P52_*`、`P73_*` 等先前探針值及 `NODE_OPTIONS` 注入，保留基本系統環境。不改 HOME。
3. 開啟本項總期限，先以正式 `npm run build` 執行 workflow build（package.json 指向 `python3 geometry-web/start_local.py --build-only`），保存 build.log 與原結束碼；成功後用剩餘預算新啟動自己的 `python3 -u geometry-web/start_local.py --port <HTTP>`。build 與 server 的 `TMPDIR=/tmp`，因此可重用本 checkout 的 `/tmp/geometry-runtime/b9bc23103ebb114398f3` 建置快取。兩次入口仍會走 registry build／`require_fresh`，不是看執行檔存在就跳過；本輪實際 binary 路徑、狀態、bytes hash、建置收據依 `LOCAL_RUNTIME` 保存。若來源變動需重建，仍算進本項同一 deadline，不以舊 binary 硬跑。
4. 服務與 browser 共享該項的 `GEOMETRY_FEEDBACK_DIR` 與 `XDG_CACHE_HOME`；server 獨立 PID/session，不沿用其他代理的服務。依 workflow 最多 30 次、約每秒一次探 `python3 geometry-web/runtime_version.py --probe <HTTP>`，先確認自有 server 存活。最後一個成功探測原樣保存 `runtime-before.json`；失敗保存輸出與結束碼。要求 schema `geometry-runtime/1`、fresh=true、root 為 `/workspace/geometry-axiom`，pid 與自有 server 相同，version 等目前來源計算值。
5. browser 完成後再跑同一 runtime probe，保存 `runtime-after.json`；記錄實際 HEAD/status。HEAD 或來源 hash 變動列為來源／編排有效性失敗，保留 browser 本身結果，不修改既有收據、不假稱受測 SHA 不曾變動。

## 結果解析與 golden 界線

外層編排以原始 stdout/stderr `run.log` 為 SSOT，另存 `server.log`。不用任意 ✓ 字元或 console 訊息推計題數，也不用程序 exit 0 單獨判綠。

**assembly／grid：** 每份 raw 必須恰有一筆完整 `CDP_RESULT ` JSON，schema 正確、completed=true、failedAssertions=0、uncaughtBrowserExceptions=0、passedAssertions>0，且原 node exit 0。scope 必須是 partial，filters 精確只含指定旗標，modifiers 空，URL、feedback、browserProfile、CDP port 與本項一致。各段數合計應等 passedAssertions，不能有 sectionsFailed。保留 skipped 原值並核對它只是被 scope 排除的段。

正式 `evaluateSections()` 對 partial 回傳 `not compared (partial mode)`，所以報告必須原樣標明「未比對完整 golden」，不能改寫 matched。另以凍結 L 的 `cdp_sections.golden.json` 做外部範圍完整性核對，明確標為選定段核對：assembly 應僅含 P77、P82；grid 應含 P70、P71、P78、P87、P88。數量從當次封存 golden 讀取並與 raw 比較，不用交接或前次成功總數。規劃時 A 的值分別為 P77=134、P82=16，以及 P70=121、P71=9、P78=23、P87=60、P88=137；這些只是已讀現行 golden 的對照，不預填執行結果。若多段／少段／變量或差異，保存差異並調查，不能自動更新 golden。

**documents：** 原 harness 沒有 golden 或 completed 欄位；成功 `DOCUMENTS_RESULT` 只在 main 的全部檢查後輸出。要求恰好一筆結果、原 node exit 0、failedAssertions=0、passedAssertions>0，實際 `PASS ` 行數等 JSON 通過數，無 `FAIL ` 或 fatal/catch 結果。成功末尾必包含「no uncaught browser exceptions」「no failed asset requests」檢查。保留實際題數，不補造 completed 欄位，也不硬套 WSL 52 題等舊數字。失敗結果的 exceptions/failures 陣列保存原值；若缺 marker 則結果不完整，不能由既有 PASS 行數判綠。

**space／timber：** 要求 raw 恰好一筆 `SPACE_RESULT`，且與 artifacts/result.json 的 scope、groups、passed、failed、completed、completenessProblems、exceptions、consoleErrors 一致。原 node exit 0、completed=true、failed=0、兩個錯誤陣列空、completenessProblems 空；每個選定 group 的 completed=true、failed=0、passed=expected，groups 集合精確符合當次 `space_test_floor.js`，總數等各群合計且等完整 results 陣列實際成功數。

space 必須 `full-space-suite`、filters 空，包含 setup、space-height-library、projection-lifecycle、projection-placement、font-layout、space-flow、projection-close、browser-health；timber 必須 partial、唯一 TIMBER_ONLY，包含 setup、timber-material、timber-source-guards、font-layout、browser-health，不能偷偷改成 timber-history-guard。規劃時來源 census 合計是 242／79；正式收據讀實跑值和 L 的固定 census，不能把它們預填成通過。此 census 是既有獨立固定盤點，沒有從本次結果學習 expected。space 的 omitted timber 群與 timber 的 omitted space 群照實保留。

若任一項失敗：先保留完整 raw、結果與截圖、清理自有資源並回報；不在這個執行任務中修改產品、oracle、golden、scope、sleep 或重跑至綠。其他項是否繼續由主代理排程，原紅燈不覆蓋。

## 程序所有權與收尾

服務和 node 各以獨立新 process session 啟動，保存 PID、PGID、啟動時間／`/proc/<pid>/stat` starttime、argv、profile 路徑與 listener。五項正式 harness 本身都有 port／endpoint 所有權防護；外層不連上其他既存 CDP。

CDP harness 正常結束呼叫 `chrome.kill()` 後直接 exit，documents 的 finally 也只 close ws／kill browser，未等待整棵 Chrome 樹；space 雖送 Browser.close 並等 300ms，仍需外層實查。不能把 node exit 0 當成瀏覽器已清完。

每輪先等正式 harness 自行收尾。仍有自有 browser 時，核對本輪 endpoint/profile/PID starttime 後才送 Browser.close 並短暫等待；必要時對本輪新建 process group 或已記錄、身份仍相符的子程序用 TERM，再 KILL，逐步保存清理結果。對可能已 orphan 的 renderer，只能用本輪精確 profile／記錄過的 PID/starttime／專屬 group 追認；不得用 `pkill chromium`、名稱模糊搜尋或依 port 廣殺。documents profile 必須位於本輪專用 T，不能把其他 geometry-documents profile 視為自有。

server 先對自己的 PID 送 SIGINT 讓 `serve.py` finally 關閉 native context，等待後再對自己的 session/已追認 descendants 做 TERM/KILL fallback，保留各層 returncode。最後檢查本輪 HTTP／CDP port 已釋放、自有非 zombie 程序為零；zombie 狀態另列，不能說仍有 CPU 負載，也不能只數 process 名稱。任何清理異常是獨立欄位，不覆蓋 browser 斷言結果。清理完才釋放排程並進下一項。

## 每項收據與回報

所有輸出檔以排他建立，重跑另用 attempt 目錄。起跑先寫 `command.json`（命令、環境、來源、期限、資源配置），不等成功才留收據；finally 無論成功、失敗、逾時都寫 `receipt.json`，缺少 harness 結果時也保存 null 與缺少原因。

必存：command.json、build.log、run.log、server.log、runtime-before/after.json 及其命令結束碼、原 harness 結果擷取檔、acceptance.json、receipt.json、source-hashes.json、外層期限 wrapper 與 hash、程序所有權／清理紀錄、截圖及 artifacts manifest。receipt 分列 build returncode、原 node returncode、timeout/signal、外層資料核對 exit、runtime 有效性、HEAD guard、清理狀態與最後整體接受結果，不把多種失敗壓成模糊 exit 1。永久證據 manifest 只包含已凍結檔案，不把仍追加的 log 提前當定版。
