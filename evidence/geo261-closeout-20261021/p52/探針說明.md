# P52-5 外部診斷器

這是診斷工具，不是正式 canvas job 的替代品。產品工作樹未修改。

應採用 `probe-v2.cjs`，SHA-256 為 `1b1fb5e55f83be15d0a082fb4c32ea3d6526cc8dc7c73b4aeb0bac9bbbc9f083`；`probe.cjs` 是保留的舊版，不再修改或當成新版收據。

工具在記憶體擷取指定工作樹的 CDP helpers、頁面啟動、`__cdpSettleUI`、`setupLinesG196`、`F_SUPPORT`、`openFace48` 與完整 P52 區塊，保持原來 43 個斷言。預設只包裝 `apiRequest` 記錄時間，不額外啟動輪詢。若真實來源已經有有界等待，來源原本的輪詢會照常執行。原斷言完成後，若尚未看到 geometry 或 busy 尚未解除，才繼續等診斷資料，讓後面的世界重置不會撞上仍在進行的放置；診斷另設 15 秒總上限。

真實來源可為舊版或已套用候選的版本。每次收據記錄工作樹完整 SHA、狀態、真實 CDP 源碼 SHA-256、有效源碼 SHA-256、探針 SHA-256 與 `memoryPatch`。`memoryPatch=none` 才表示沒有在記憶體改變來源；不得把安裝候選的結果稱為該 SHA 的原版結果。

目前以捕獲 `pointerdown` 當作點擊時間。最早的兩次功能測試用 `mousedown`，因此可能晚於產品開始處理數毫秒，僅列為功能測試；新執行結果另帶探針本身的 SHA-256。

## 執行方式

```sh
GEOMETRY_TEST_URL=http://127.0.0.1:18840/ \
GEOMETRY_FEEDBACK_DIR=/tmp/geo261-feedback-main \
GEOMETRY_CHROME=/usr/bin/chromium \
GEOMETRY_CHROME_FLAGS=--no-sandbox \
GEOMETRY_CDP_PORT=9350 \
node /workspace/geo261-evidence/p52/probe-v2.cjs /workspace/geo261-main
```

服務必須是隔離測試服務；不得和其他 canvas job 共用服務。

- `P52_REPEATS=3`：同一新瀏覽器中重跑完整 P52 三次；每個情境仍重新建立原版場景。必須為正整數；完成時檢查斷言數為 43×輪數，避免零輪假綠。
- `P52_ACTIVE_SAMPLING=1`：點擊起每 50ms 主動讀 references，只用於量測可見性。它會影響原有 fetch/DOM settle，不能把該模式的 `assertionPassed` 當作原版無干擾證據。
- `P52_DELAY_NEWID_MS=700`：刻意延遲 `apiRequest('newid')` 的實際 fetch，展示一般 settle 未涵蓋此等待期間。這是故障注入，不是原始 WSL 病因的重現證明。
- `P52_DELAY_NETWORK_MS=6000`：由 CDP Fetch 攔截唯一一次真正的 newid 請求，令原版 fetch pending 持續六秒，驗證五秒機會式 settle 的上限。
- `P52_CANDIDATE_WAIT=1`：對舊版來源在記憶體安裝候選。真實來源已有候選時會拒絕此選項，應直接預設執行。
- `P52_WITHDRAW_WAIT=1`：要求真實來源已有候選，在記憶體撤回等待修正，作突變自證；不修改產品檔案。
- `P52_TARGETED_CONTROL=1`：只取原 P52-3 收尾重建與原 P52-4/5；檢查斷言地板為 2×輪數。這是縮短前置的負控制，不能替代完整 P52 43 個斷言。
- `P52_REFERENCE_CONTROL=hold`、`wrong-geometry` 或 `error`：對 P52-5 的 references 刻意永不回應、回傳 origin[0]+1，或回傳 API 失敗。必須明列為注入控制。
- `P52_PROBE_PARSE_ONLY=1`：只驗擷取後的程式語法，不啟動瀏覽器。

`firstTimberObservedMs`／`firstGeometryObservedMs` 是第一次 references 回應實際看到資料的時間上界；被動模式不宣稱捕捉了真正的發布瞬間。v2 的 `waitAndReadMs` 是整段等待與 references 取樣，不能和早期 smoke 只量 sleep 的 `originalSleepMs` 混比。

## 已確認的只讀線索

1. main 與 final 的 P52 測試完全相同；`cdp_test.js` 的兩版本差異僅是後段掛入 `grid_inspector_rename_test.js`。
2. `sleep(400)` 不是單純400ms：`cdp_test.js:99–103` 接著呼叫 `__cdpSettleUI(0)`，它在約384–393行最多再等待5秒，且本來就允許逾時返回，並未保證 timber3 已發布。
3. P52-5 舊 log 的 `{}` 只能證明 `g` 為 undefined，不能單憑該行判斷 timber3 完全不存在、尚未放置完成、點擊未送出，或被拒絕。
4. 普通角材放置走 `app.js:4887` 的 `fePlaceTimberFromForm` → newid → source-inspect → history-begin/timber/place/history-end → feLoadGuides。`serve.py:123–160` 直接送 native bridge，沒有直接進 Python model_sources 的模型驗證流程。
5. 非唯讀請求會經 `serve.py:538` 的 `RUNTIME.fresh()`；`runtime_version.py:153–175` 每次讀完整來源並二次掃檔。靜態計數：main466檔/20,827,317bytes，final731檔/22,409,362bytes。這是相關耗時路徑，不是已證實的原失敗原因；不可為效能繞過版本守門。
6. P68 原 log 卡在第二面加入共用參考線，最後完成的 API 是 newid，畫面仍「正在驗證…」。`project_audit_test.js:59` 接著等 settled15秒；API fetch本身也是15秒，逾時後還可能查收據。這是另一個尚未判定的同步／負載問題，沒有證據說 P52-5 導致它。
7. 原始 WSL log 的 trace 摘要是121,232筆、62,023,942bytes、23個未完成請求，狀態為 `incomplete-or-mixed-trace`；交接沒有原始trace內容，無法判定當時卡在來源掃描、bridge鎖或其他等待。
