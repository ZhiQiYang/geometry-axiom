來源為 `43f85313c32410ac01406ab585846bbacafea278` 的全新 git archive；673 個來源檔逐一等同正式載入 closure。正式 P-189 N64 比值 2.852459784097019、check=1，診斷不改該結果、不重抽正式樣本。

正式 binary 的 `nm -an` 與 `objdump -drwC` 均為 0。沒有獨立 `wd_read` 符號；它已 inline，但 `wood_definition_sources_placement`（正式位址 0x4ec50）中仍有 4-byte（0x4ed40）與 8-byte（0x4eec0）shift/or 迴圈；`wood_definition_sources_member`（0x4db70）也仍有迴圈。此觀察不證明迴圈是倍率失敗的主要原因。

診斷 binary 的實際旗標為 `gcc -std=c11 -O2 -g -pg -fno-omit-frame-pointer geometry-web/web_bridge.c -o bridge-profile -lm`；16 MiB stack，使用同一 N64 scene 原 bytes。archive、compile、單次 load、`gprof -b -p -q` 與 driver 真碼皆 0。compile 24.859 秒，load 1.734 秒，後者只為帶 instrumentation 的診斷牆鐘，不能當正式效能樣本。載入 stdout 與正式 N64 final 完整相同，正式 binary 雜湊未改。完成於 2026-10-21T00:55:35.341239Z；driver PID 294512 後來為 Zs 殭屍，不能宣稱所有 PID 消失，亦無須強殺殭屍。

原 gprof 有 compiler clone 名稱錯貼，原 stdout 完整保留。`gmon-address-review.py` 用原 gmon 位址與 `nm -anS` 的非零大小 T/t 函式完整範圍衍生核對：75 個 10ms histogram 樣本中 73 可整 bin 歸於唯一函式，2 個跨界／gap 不強派。736 個原 callgraph arc 記錄也按 mcount 返回 PC 歸屬。衍生解析真碼 0，完整方法、所有非零 bin／arc 與輸入 hash 在 JSON。

單次取樣僅 0.75 秒 histogram CPU 樣本，且 `-pg` 與 frame pointer 可改變成本／函式邊界。沒有同 flags main 對照，也沒有把每個 inline byte loop 單獨歸因；因此仍未證明哪一項導致正式 2.85 倍。解碼函式是具體可試的小候選，但 contact/source 也有明顯成本，不能承諾固定寬度改動足以通過。#323 的 memo／排序與 #300 容量不混入 #288；P177 次數與時機不改。
