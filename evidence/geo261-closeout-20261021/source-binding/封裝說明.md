# 來源綁定證據包

本包保存產品來源 A 的只讀快照，以及**未採用、未推送的歷史 L1** 的來源快照、精確帳本差異和預設 CC check 失敗原件。最終 L／E 尚未驗證。來源核對成功不代表正式測試或預設 check 通過。

- A：`7159530c0e494d3211e6ab1764eb691137211707`。
- 歷史 L1：`cd4ac98f44174729fb3a2f1c291c6c258c9a239a`。
- `snapshot-A.json`／`snapshot-L.json` 是同一正式只讀快照工具的原 stdout；後者名稱保留，但內容 SHA 精確指向 L1。
- `binding-L1.json` 為來源比較原 stdout；對全部 tracked tree 的差異只允許 ledger，對快照的 1,010 路徑則確認 1,009 不變、一份 ledger 改變。
- `ledger-L1-import/` 完整保留主代理的 L1 匯入、預設 CC check=1、57 stale、遠端仍 A 等原件；本包不改內容。
- `command-code.txt` 與外部 `snapshot_bindings.py` 原 bytes 相同；`comparison-code.txt` 與外部 `compare_A_L.py` 原 bytes 相同。封裝只改副檔名，不改原碼，實跑 hash 在輸出／索引內。後者固定核歷史 A/L1，不能無修改地拿來驗後續 L。
- `compile-context-code.txt` 是只讀 hash 比較來源，與實跑檔原 bytes 相同；`compile-context.json` 是其 stdout。它不編譯、不代替正式 check。
- `README.zh-TW.md` 保留完整 A→L→E 綁定清單；`L1-README.zh-TW.md` 說明本輪實證與失敗界線。舊文件中以外部工作區為基準的相對路徑，以封裝索引 sourcePath 對照；最新審查原文在本包上一層 `review/最新審查原文.md`。

在對應乾淨 checkout 可用 `python3 -B command-code.txt --root <checkout> --expected-head <完整SHA>` 重新擷取只讀快照；stdout 存在 repo 外。此命令不執行測試，輸入範圍與限制詳見 README。不可把另一 HEAD 的結果改名當成原 stdout。

`封裝索引.json` 記來源、目的檔、bytes、SHA-256；它明示排除自身，避免自我雜湊。歷史原件必須保留，最終 L 的新證據另加，不覆寫 A/L1 raw。
