# owned 來源刷新外部方法：待採用與執行

目前只準備外部原碼與不可執行的 review 範本；沒有跑正式 CLI／兩套架構測試、詞法盤點或探針，沒有改產品四產物，沒有 S2／A2 成功收據。

預備命令：`env -u CC -u PYTHONOPTIMIZE python3 -B /workspace/geo261-evidence/architecture-owned-preparation/refresh_owned.py --root <已採用且clean的工作樹> --out <repo外且尚不存在的out> --source-head <最終S2完整SHA> --review-file <完成逐檔審閱及hash的review.json>`。

腳本以原 bytes compile 載入既有正式 `refresh_receipt.py`（固定 SHA-256 `b0b80afbdbbbb451ab29e774ffbdd1699f0438619b5f84280ef954c8b72fc5a3`）的來源枚舉、closure、test 摘要解析與四產物失敗還原工具，不執行其 exclusion 必紅刷新入口。正式工具與裁判保持不變，外部腳本不進既有 source roots。

review 須填最終 sourceHead、變更前 baseHead、舊 receipt raw hash、全部 changedOwnedSources／changedOutsideInventory（每個項目含 rawSha256、lfSha256、繁中 reason）及新 guard 的繁中理由與完整來源路徑清單。後者只允許既有 `tests/` 直下 `.py`／`.c`，以及精確單一路徑 `tests/run_all.expected.json`；不接受其他 JSON。這份 expected 是本輪 H 契約測試 17→27、contact 契約測試 10→12 的必要數量登記，並非正式工具修改；採用前須獨立核對只有兩個具名 count 改變。這些檔案另外綁定，不能誤稱含於 611 inputs。基底至 S2 的 Git 總差異必須精確等於 review 的既有檔案修改集合，不接受新增／刪除／改名或先改架構裁判／四產物。

執行後只准寫 `geometry-core/domain-decoupling/` 四檔：`product-architecture.json`、`product-architecture-scan.json`、`PRODUCT-ARCHITECTURE.md`、`product-architecture-receipt.json`。manifest 只有完整 W C 詞法盤點所得、逐項審閱的新 guard 追加；舊 guard、來源責任／集合、exclusions、vendor／route 政策全部保留。沒有新 guard 時 manifest 原 bytes 不變。

prior CLI 預期真綠並保存原件；再跑新 manifest CLI、原 generic tests、原 product tests，逐條存真 wait 碼／環境／argv／時間／原 stdout、stderr。記 fresh TMPDIR 與 16 MiB stack；Python child 使用全新 pycache prefix 且禁止寫 bytecode，避免載入工作樹既存 pyc。全部受驗來源先與指定 Git raw／LF bytes 核對，每條命令前後及封存後固定來源與工具；舊四檔存 previous/，新四檔存 final/。成功後由 root 查核並 commit A2，再做 S2→A2 bytes 綁定；收據不可回填成 A2 實跑。

新 W identifier／string 的探針每項三次：同一真 K geometry.c 文本在記憶體注入，舊 manifest 接受 0、新 manifest 精確拒絕 1、只撤回該 guard 再接受 0；另中性 identifier 接受 0。所有控制使用未改 scanner，保存真輸出，不改產品、不增加原18題。不捏造 exclusion 紅燈，也不把這些靜態控制冒充行為或效能撤回。

待 peer 完整審閱外部腳本，最終 S2／review 到齊並由 root 放行才執行。外部 out 的 method-source.txt 為非執行原碼證據；封裝應只 curate 原收據、原 logs、JSON／Markdown／來源文字，勿把 TMPDIR 的測試 snapshot 或可執行副本放入證據根。
