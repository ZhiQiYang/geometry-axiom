## R19 閱讀 A：找不到能依序放出來的場景（未到 L4）

R19 的條文是 I19 例外三與 R6(d)(e)：`boundary` 固定段在它覆蓋那條外輪廓邊的端點，端面可以頂一支或多支已放角材的側面，不要求全寬、不比優先級；短於料寬的 RC 面可以留著。帳上寫「App 沒有專屬入口，要在牆轉角有柱的面上放壁邊材才看得到」。

這次先用原生 CLI 試場景能不能依序放出來，再決定 App 的操作路徑。App 的「進階指令」與面內工具走同一個原生核心；本分支沒有改原生碼，和 main `724d0370` 相同。
執行方式：`/tmp/geometry-tests/core --scene <檔> --no-window`（`ulimit -s 16384`）。場景與原生回覆在 `r19/`。

| 場景 | 做法 | 原生回覆 |
|---|---|---|
| `column_corner.scene` | 柱在左上牆角（輪廓缺角 u∈[0,400]、v∈[2600,3000]）。主支放在格線 u=413，足跡 u∈[400,427]，貼著柱面；打算讓短牆 e4 的邊界材端點頂它側面 | 第 10 行放主支就被拒：`V_EXTENSION：非 boundary 角材（3）的 footprint 超出定位邊範圍——定位邊 e3 [2600,3000] mm，低端超出 [27,2600] mm`。貼柱面的主支不能越過凹角往下走 |
| `step13_a.scene` | 13 mm 薄牆階（#318 使用者確認可以的排法），只放低邊 e0 的邊界材 | `跨距終點沒有擋面（端面懸空）`：端點那裡還沒有角材可頂 |
| `step13_ab.scene` | 同上，先放低邊 e0、再放高邊 e2 | 第一支就被拒，同上 |
| `step13_b.scene` | 同上，只放高邊 e2 | 接受，`L=1000`，頂點 (0, 13)–(1000, 40)：越過牆階一路延伸到左牆（`step13_b.stdout.txt`） |
| `step13_ba.scene` | 同上，先放高邊 e2、再放低邊 e0 | 高邊那支同上；低邊那支 `中線上沒有任何合法跨距`（v 13–27 已被高邊那支佔掉） |

**判讀**：這三種都卡在「兩支要互相當對方的擋面」，依序放時先放的那支沒有東西可頂，或先占掉了位置。13 mm 薄牆階正是 R17（D16a 固定段互頂組，`boundary-pair/1`）要處理的情形，R17 產品還沒實作。原生測試 `tests/geo318_host_boundary_ends_harness.c` 的註解也寫明，它直接組好世界來驗，不主張這個場景能經由依序放置、載入或重建得到。

**沒試的**：#318 缺陷 1 的「柱跨牆階」房型（外框 `0,0 4100,0 4100,3661 3000,3661 3000,3700 0,3700`、柱孔 x 2600–3000、y 3444–3644）；牆中段的柱；其他角色組合。所以這裡只能說「這三種放不出來」，不能說「App 一定放不出例外三」。
