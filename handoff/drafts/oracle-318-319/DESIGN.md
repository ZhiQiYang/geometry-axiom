## 1. #318 缺陷 2:建構崩潰

### 1.1 現象與觸發條件
〈任何一條水平邊的中點 x,等於任何一個頂點的 x〉(外環自己的凹角也算)。L 形房缺角寬 = 房寬一半是最簡單的例子,3600×3000 缺 1800、4000×3000 缺 2000、5000×4000 缺 2500 都中。
崩潰位置:`build` 的邊界材迴圈 `framing_oracle.py:413`(與 A 軸平行的邊;板長沿 Y 時 A 軸 = x,這些邊是水平邊)或 `:422`(與 B 軸平行的邊;板長沿 X 時 B 軸 = x,這些邊是水平邊)→ `Region.inside` → `Region._ring_section:184` 的 `assert len(vals) % 2 == 0`。兩處都是在問〈水平邊中點的上方半 mm 是不是室內〉,切線是垂直的、落在 x = 中點。

### 1.2 為什麼在牆線上取 section 會碰到 assert(根因)
`_ring_section(ring, k, m)` 收集〈嚴格跨過 m〉的邊(`min(p[k], q[k]) < m < max(p[k], q[k])`)的另一軸座標,排序後兩兩配對。這個做法只有在 m 不是任何頂點的 k 座標時正確。
m 恰好是頂點座標時,端點落在切線上的邊被丟掉。設這條切線上:

- S = 嚴格跨過的水平邊數;
- L = 有端點在線上、另一端在線的左邊的水平邊數;R = 同,在右邊。

緊貼切線左邊(m−ε)與右邊(m+ε)的切線都是一般切線,穿過邊數必為偶數:S+L 與 S+R 都是偶數。所以 **S 為奇數 ⇔ L 為奇數**。
線上的每一段垂直邊,兩端的水平鄰邊:同在一側(凸出的 U 形、凹進的槽)給 L 或 R 加 2(偶數,沒事);一左一右(牆階的 Z 形,L 形的凹角牆就是)給 L、R 各加 1。**線上有奇數段〈階梯形〉垂直牆就崩潰。**
L 形房 `[[0,0],[W,0],[W,ys],[W/2,ys],[W/2,H],[0,H]]`:垂直牆 x = W/2 從 (W/2, ys) 到 (W/2, H),下端的鄰邊往右(到 (W,ys)),上端的鄰邊往左(到 (0,H))= 階梯形;下緣水平邊 (0,0)–(W,0) 的中點 x = W/2 正好在這條牆線上,且它嚴格跨過 x = W/2(S=1,上緣與缺角下緣兩條端點在線上被丟掉)→ 奇數 → assert。

另一個隱憂(同一根因的安靜版,**手推,沒實跑**):牆線上有**兩段**階梯形垂直牆時 S 的奇偶回到偶數,不崩潰,但探測點若落在兩段之間,垂直切線少數了一次穿越,`inside` 悄悄回錯答案。新的 `inside` 對這種情形也是對的(改用水平切線);舊結果只可能在這種(非常罕見、目前沒有任何對照房)的房間裡不同。

建構端問的是〈這條牆邊的哪一側是室內〉(決定邊界材貼哪一側),探測點取邊的**中點**往室內側偏 0.5 mm。中點只是任意挑的一個點,碰巧落在牆線上沒有任何物理意義。

### 1.3 呼叫點盤點(哪些會崩潰)
全檔案 `.section(` / `.inside(` 呼叫點逐一查切線座標是否可能是頂點座標:

### 1.4 修法
`framing_oracle.py`:

1. `Region.inside(x, y)`:`x` 不是頂點 x 座標 ⇒ 舊路徑 `iv_find(self.section(0, x), y)`(**結果逐位元組不變**);`x` 是頂點 x 座標 ⇒ 沿水平切線 `iv_find(self.section(1, y), x)`。呼叫端的探測點都有一個座標是 ±0.5(整數頂點不可能是半整數),所以水平切線不會同時落在牆線上;兩條都在牆線上就明確 assert(格點上〈在不在室內〉本來就不定義)。
2. `_ring_section` 的 assert 加說明文字,並把前提寫進 docstring(以後有人在牆線上直接叫 `section` 會看到原因)。**不改 `section` 的行為**:突變 X3(縫線探測不偏半 mm)靠它在牆線上當掉才抓得到,保留。
3. 檔頭〈已知限制〉那句拿掉〈柱跨牆階的 C3/C6/C8〉,改指向缺陷 1 的處理。

為什麼不改探測點(例如改取 `s0 + 0.5`):探測點可以同樣避開牆線,但 5 個呼叫點各改一次,且每個都要再保證〈取邊角落旁一格〉的語意;改 `inside` 一處,並保證〈能算的結果一個字不變〉(golden 與掃描不會動)。

### 2.2 根因
兩層:

1. **現象層**:柱下緣離牆 y=3661 只有 17 mm,放不下 27 mm 的料;柱面的垂直線又正好是牆階的垂直牆,三個角材(沿柱料、沿牆料、牆階邊界材)在 (3000, 3644–3661) 這一帶互相擋住,中間留下一塊沒料的室內缺口。

## 3. #319:C3 承接帶被房間分塊截斷

### 3.1 根因
C3 的結構:`R = reg.rects()` 把房間切成 x 分塊(只在頂點 x 座標切);每片板(cell)與每個分塊相交得到碎塊 `q`;對每個碎塊的四個邊各取外側 1 mm 的 strip,扣掉同一片板其他碎塊蓋住的部分(那是板內部,不是板邊),剩下的才是真板邊;板邊內側取寬 X 的承接帶驗有沒有料。
承接帶的寬 X 被夾在**自己的碎塊**裡:左邊 `(x0, …, min(x0+X, x1), …)`、右邊 `(max(x1−X, x0), …, x1, …)`。縫(板邊)離分塊邊界 xb 不到 X 時,承接帶有一部分在隔壁碎塊裡;隔壁碎塊那一側的 strip 又被當成〈板內部〉,不驗。**那一段承接帶沒人看**。
實例(H6 轉置版,手推,與 issue 一致):候選縫 3605,分塊邊界 x=3600(頂點 x),低側板邊 x=3604,承接帶 [3596,3604]:舊 C3 只量 [3600,3604](主支 [3600,3627] 蓋住),[3596,3600] 不在任何人眼裡 ⇒ 沒有併料也全過。
板長沿 X 時主支縫的承接帶沿 y,y 方向不被 x 分塊切,所以沒事;但**垂直的板端縫(板長沿 X 的 B 向縫)的承接帶也沿 x,同樣被截斷**,issue 沒提,補在 README 已知限制。上下兩邊(承接帶沿 y)不受影響。

### 3.2 修法
`x_band(qs, seg, d, X)`(放在 `bridged` 之後):左邊(d = +1)從板邊 x 往 +x、右邊(d = −1)往 −x,走 X mm;沿路收集同一片板所有碎塊的 x 邊界當停靠點,每走過一段,把 y 範圍與〈那一段 x 上同一片板的碎塊 y 範圍〉取交集(`iv_intersect`)—— **射線連通**:板邊上的每個 y 從板邊一路連續走過去才算,中間遇到孔(沒有碎塊)就不再往後算,孔另一側的碎塊不會被誤算進來。y 範圍相同的相鄰段合成一個矩形(`bridged` 要看整段空檔,切碎了可能把〈相距 < min_piece〉的判斷變寬鬆)。
沒跨過碎塊邊界時,結果與舊的夾在碎塊裡的承接帶**完全相同**(我逐一核對:停靠點只有兩端;第二段 y 範圍為空 ⇒ 不產生矩形)。所以新量法只會〈多驗〉,不會〈少驗〉;舊的綠燈只可能變紅,不會反過來。

C3 的迴圈改成 `for bnd in band(seg)`;上下兩邊的 lambda 包成單元素 list,行為不變。

### 3.3 驗收
- `BC_no_doubling_cand`(候選建構不放併料)在轉置版 H6:舊 C3 全過 ⇒ 新 C3 紅。直接測試 T-C1:同一個候選 3605 用 `build_candidate`,不放併料(`mut = {"no_doubling"}`,與 BC 的效果相同)時,**板長沿 X 與轉置版的 C3 缺口都要是 [3596,3600]**,有併料時整個候選檢查全過。
- 再加左右鏡像的轉置版(右上起鋪,縫 115,分塊邊界 x = 120,缺口 [120,124]):走 C3 的**左邊**(承接帶往 +x),前兩個走右邊 —— 只有三個都有才能同時釘住兩個方向。
- `x_band` 直接測 7 個手寫案例(同 y 範圍合成一個矩形、隔壁較窄、右邊對稱、隔壁有孔、隔壁是牆、隔壁較寬)。
- 人工驗證步驟(TESTS.md §5):把 `TR182_DBL` 的 H6 那筆暫時拿掉,再套原始碼突變 `BC_no_doubling_cand`,`--mutants-only` 仍要紅,而且紅的是 C3 這一條(轉置版 H6 的候選變成不可行),不是手釘的併料範圍。

### 3.4 掃一遍現有的轉置族
TR182 的 16 間 × 4 種排法(64 個排法)本來就跑 `fo.check`,C3 變嚴之後這 64 個就是〈掃過〉:有隱藏缺陷會直接紅。更廣的掃描不寫進 selftest(對稱性在其他族未驗過,硬塞會產生我無法預測的紅燈),另附 `tp_scan.py`(草稿,沒有執行):房間 R 用排法 l 與轉置房間 T(R) 用轉置排法 T(l) 的結果必須完全相同(衝突碼、縫位、檢查失敗碼),涵蓋凹角/壁龕/柱房、牆階與雙牆階、縫離牆階垂直牆 < 10 mm 的專屬一族、壁柱加柱。轉置是保朝向的對稱(不像鏡射有 ⌊w/2⌋、⌈w/2⌉ 的 1 mm 不對稱),所以〈不一致〉就是缺陷的證據,不需要手算期望值。

## 5. 風險與我最不確定的三件事
1. **所有期望值與〈不會誤報〉的結論都是手推,沒有任何一行程式跑過**。尤其是 §1.7 的 24 個 L 形排法(可施工、檢查全過、縫位)與 H6 鏡像案例的缺口 [120,124];鏡像時置中主支差 1 mm(⌊w/2⌋ 與 ⌈w/2⌉),推 9 mm 而不是 8 mm,我用手推支撐,但這一筆最脆弱。若紅燈,不要改期望值遷就程式,先判是手推錯還是程式有缺陷。連 Python 語法我也只用眼睛核對過。
