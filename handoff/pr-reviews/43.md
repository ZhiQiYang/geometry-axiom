### 7. C：有界的「高度與 RC 待補資料」附件

以下是**新擬宿主工程契約**，補足原 C 的字段與生命週期，不宣稱是現有 schema 或新公理。原需求已明定保留已知值、區分樑底／樑頂／樑深、補資料後沿用關聯、完整後走既有核心。[geometry-web/docs/REFERENCE-RECONSTRUCTION-PLAN.md:70–80](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/docs/REFERENCE-RECONSTRUCTION-PLAN.md#L70-L80)。

新增一種功能附件 `kind:"reconstruction-data"`、`schema:"reconstruction-data/1"`。一個專案至多一個集合，至多 256 筆；每筆至多 16 KiB、集合至多 1 MiB，仍受既有 8 MiB manifest／附件整體上限。只收以下封閉結構，不接受任意 JSON、算式或隱含幾何：

| 欄位 | 完整契約 |
|---|---|
| `id / revision / kind / label` | id 是穩定的專案附件識別，不是 World id；revision 為本筆正整數版本；kind 僅 room-heights／column／beam；label 0–96 UTF-8 bytes，只供展示。 |
| `anchor` | 可為 null；或本專案已提交 boundary／placement／column／beam 的 typed id、內容指紋及關聯狀態。id 0 合法。可帶已存在 SourcePlane／RoomRecord 的附件 id 供定位，但不把 RoomRecord 當 D5/D22。不保存第二份輪廓或 frame。 |
| `fields` | 依 kind 的有限欄名。room-heights：bottom、top、height、wallThickness；column：x、y、width、depth、bottom、top、height、spaceId；beam：axis、from、to、at、width、depth、top、bottom、spaceId。所有輸入先存原樣字串，單欄至多 64 字元；axis 僅 x/y 或未填，spaceId 未填不等於有歸屬。 |
| 每個尺寸的 `unit / datum / evidence` | unit 僅 mm／cm；datum 為來源基準說明（至多 256 字元）；各欄最多 8 個來源記錄引用。來源定位只用現存 sourceHash／page／頁座標，或已存在的證據 id；頁數、範圍、來源存在性按既有驗證。缺基準時不能冒稱已轉到 World z。 |
| `confirmed` | 使用者明確認可的整數 mm 值、其原字串與單位 hash、基準核對狀態。未填為 null；無效原字串可保存但不產生 confirmed 值。mm/cm 轉換採精確十進位有理數，只接受結果為整數且在 D1 範圍內，不捨入。 |
| `derivations` | 只容許具名三值關係 top=bottom+height（柱／房間）及 top=bottom+depth（樑）；保存來源欄位 revision/hash 和結果，明標「推導值，待核對」。不是任意運算引擎；確認後才可採用。 |
| `adoptions` | 上次明確採用的 typed target、當時定義指紋、record revision、confirmed 欄位 hash 與採用方式「複製已核對輸入」。它是核對收據，不是 native 身分沿革或 live 幾何依賴。每筆最多保存最後一次收據及一個失效原因；完整 undo 歷史由既有專案歷史承擔，不塞入附件。 |

### 7.1 records 的完整封閉形狀

以下都是新附件的宿主資料，不新增來源種類、公理或可執行算式。型別式中的每個物件只允許列出的鍵；所有 nullable 欄位必須明寫 null，不能以缺鍵或 undefined 代替。Hash一律為64個小寫十六進位字元，uint32為0至2^32−1的整數，Revision依7.2；HostId沿所引用資料種類的既有reader。JSON 讀取時即拒重複鍵；只接受 plain JSON、有限數字及有效 Unicode 字串，拒 accessor／原型物件、孤立 surrogate、NaN／Infinity；巢狀最多16層，並先驗前述位元組及集合容量。

~~~text
Record = {
  id, revision, kind, label,
  anchor: Anchor | null,
  fields: FieldsForKind,
  derivations: Derivation[],      // 至多1筆
  adoptions: Adoption | null      // 只有最後一筆，不是任意陣列
}
Anchor = {
  target: {kind:"boundary"|"placement"|"column"|"beam", id:uint32},
  definitionFingerprint:Hash,
  state:"confirmed"|"needs-review"|"needs-reassociation",
  sourcePlaneId:HostId|null, roomRecordId:HostId|null
}
DimensionField = {
  raw:string, unit:"mm"|"cm", revision:Revision,
  datum:{text:string, review:"unknown"|"world-confirmed"|"not-applicable"},
  evidence:EvidenceRef[],
  confirmed:Confirmation|null
}
Confirmation = {
  kind:"literal"|"derived", valueMm:SignedIntegerString, inputSha256:Hash
}
AxisField = {raw:""|"x"|"y", revision:Revision}
SpaceField = {
  raw:string, revision:Revision,
  selection:null|{kind:"space",id:uint32,definitionFingerprint:Hash}
}
Derivation = {
  relation:"top=bottom+height"|"top=bottom+depth",
  target:"bottom"|"top"|"height"|"depth",
  inputs:[{field,revision,inputSha256,valueMm},
          {field,revision,inputSha256,valueMm}],
  valueMm:SignedIntegerString
}
Adoption = {
  target:{kind:"column"|"beam",id:uint32},
  definitionFingerprint:Hash, recordRevision:Revision,
  confirmedSha256:Hash, method:"copy-confirmed-input",
  invalidReason:null|"source-changed"|"source-missing"|"target-changed"|
    "target-missing"|"target-replaced"|"history-unknown"
}
~~~

kind 恰為 room-heights／column／beam；fields 的**全部且僅有**下列鍵，不能少填欄位，未填用 raw=""、confirmed=null：

| kind | DimensionField 鍵 | 其他鍵 |
|---|---|---|
| room-heights | bottom、top、height、wallThickness | 無 |
| column | x、y、width、depth、bottom、top、height | spaceId:SpaceField |
| beam | from、to、at、width、depth、top、bottom | axis:AxisField、spaceId:SpaceField |

raw至多64個Unicode scalar，datum.text至多256個；label沿前表96 UTF-8 bytes。SignedIntegerString 是無正號、無前導零的十進位整數，負號只用於負數，零只寫 "0"，數值在 D1 範圍；用精確整數讀取，不先轉 JS Number。width／depth／height／wallThickness 必須大於0才能確認；位置類欄位可為合法負座標。毫米／公分 raw 只作精確十進位解析，允許首尾空白與正負號，但 hash 保留原字串；不得接受算式、指數、千分分隔或捨入。raw 不合法時仍可保存，但 confirmed 必須 null。

位置類 x／y／from／to／at／bottom／top 的 datum.review 必為 world-confirmed 才可採用；unknown 可保存。width／depth／height／wallThickness 的 datum.review 固定 not-applicable。world-confirmed 表示使用者已核對目前輸入為 World 座標，不建立新的 frame 來源或自動座標換算。SpaceField 的空 raw 對應 selection=null，代表本次不指定 D5；非空須精確解析 uint32，與 selection.id 相同，且 selection.kind 恆為 space。選取及採用時依同版 native 核其 D5 型別與指紋；D22／模型庫 id 不接受。保存歷史失聯 selection 不補猜目標，採用前須重新明選。AxisField 不接受其他字串。

Anchor 只記核對關聯。新增／改指時 target 必存在；sourcePlaneId／roomRecordId 非 null 時指向本案既有附件，兩者同時有值須符合實際 room→plane 關係。歷史 Open 若目標缺失、內容改變或沒有足夠沿革證據，可保存原 typed id／pin，但標 needs-reassociation／needs-review，不自動改指；來源回來不自動清掉已觀察的缺失。Anchor.state 不是 D59 記號，也不能代替採用當下的 native 守門。

每個尺寸的 evidence 至多8筆，以完整引用形狀去重；只接受現有來源頁或 #48 證據連結：

~~~text
EvidenceRef =
  {kind:"reference-page",sourceHash:Hash,referencePageId:HostId,
   page:PositiveInteger,
   coordinateSpace:"pdf-page-viewport/1"|"image-pixel/1",
   region:null|[x,y,width,height], basisSha256:Hash}
  |
  {kind:"evidence-link",evidenceId:HostId,contentSha256:Hash}
~~~

HostId 沿其既有 reader 的 id 格式；不是新 World id。新增引用時來源原 bytes、頁與既有 reference page／證據紀錄必存在；來源頁 page 1–100000，影像僅page1。region用該頁既有座標，有限且正寬高、完全在頁內；null指整頁。不得把 #48 的 pdf-viewport-scale-1-y-down 標記當成 SourcePlane 的 coordinateSpace 直接互換；由既有來源頁轉接器取明確座標和基準。basisSha256 的資料固定為既有頁欄位 {sourceHash,referencePageId,page,coordinateSpace,imgW,imgH,crop,mmPerPx,x,y,rot,calibration}；對來源 reader 合法而原本選用的缺項明寫 null，不補校準值。contentSha256 對完整既有 evidence-link 記錄取 hash。兩者算法沿7.3；不另存來源圖片、輪廓或改變 #48 target。

歷史紀錄的頁／證據後來失聯，可保留引用並呈現缺失，不能再確認／採用；若來源清單仍宣告有原 bytes 而其 bytes/hash不符，沿既有完整專案規則拒絕，不能把壞來源檔偽裝成合法斷鏈。SourcePlane／reference page校準、對位、圖頁或證據內容改動使相關確認需複核；舊 RC不自動改。

literal Confirmation.valueMm 必等於 raw＋unit 的精確結果；inputSha256 必等於7.3定義的欄位輸入hash，datum與evidence均須當下已核對。derived Confirmation 只容許對應唯一 Derivation 的 target，valueMm與其結果相等；target.raw必空、unit="mm"，不得蓋過使用者另填的第三值。三個literal都已填卻不滿足等式時，保留raw並阻擋採用。

Derivation 恰有另外兩個不同欄位的 inputs，按 field 名排序；兩者必為目前**literal confirmed**、revision／inputSha256／valueMm逐一相符。關係與kind相符，target是該關係唯一未填欄位，結果以精確整數唯一求得、在D1及正尺寸規則內；不接受推導引用推導，不形成另一個算式圖。pending推導的target.confirmed為null；使用者確認後才寫derived Confirmation。任一input、unit、datum或evidence改變，在同一筆附件修改清掉受影響推導及target.confirmed，不能沿用舊確認。

Adoption只用於column／beam，同record.kind與target.kind必相同；room-heights的adoptions恆為null，其建模採用由modelReview記錄。recordRevision是本次所採用核對輸入的record.revision，confirmedSha256依7.3取當次完整fields；definitionFingerprint取同一成功native結果的目標定義指紋。單寫採用收據不再推進核對輸入revision，不能讓同一次建立的modelReview立即過期。invalidReason只記上表有限原因，重新採用前需核對，不因同id出現自動清除。

### 7.2 ID、revision與高水位

Record.id沿現有宿主UUID建立器（crypto.randomUUID）生成小寫canonical UUID，不是使用者輸入、World配號或陣列序號；建立前驗不與現有records及modelReviews中的歷史recordId重複，碰撞重取。建立另一筆紀錄一律新UUID；刪後新增不沿用被刪id，不因此新增複製按鈕。完整專案Open／整筆undo可還原原UUID，但不把它當native沿革證明。其他source／room／model的id格式及配發保持原契約。

revision與欄位revision均為1至2^53−1的安全整數；集合revisionHighWater為0至2^53−1。它是本附件的版本分配水位，不是D59身分記號。revision只追蹤核對輸入 {kind,anchor,fields,derivations}，不因純label修改、adoptions收據／invalidReason或modelReview寫入而增加。版本欄位由宿主分配、不可作一般欄位編輯；判斷核對輸入是否真正改變時，先排除宿主產生的record／field revision與derivation輸入revision標記，比較其餘內容，再按下述規則分配並重驗完整衍生來源，不能因預先填了新revision便製造變更。每筆成功的核對輸入變更，依受改record id排序，為每個真正改變的record取一個大於目前水位的新revision；該record本次改變的欄位也用此revision，未改欄位保留舊revision。新record全部欄位用其新revision。no-op、唯讀、預覽、取消、失敗不消耗版本；容量或計數器不足在提交前整筆拒絕，不回繞。

revisionHighWater須不小於records／field revisions、derivation inputs、adoption.recordRevision，以及modelReviews中所有recordPins／excluded的revision；讀入低於任一已存版本者拒絕。Undo/Redo還原原資料與原revision，但宿主保留本context已使用水位的最大值；復原後另開的新編輯不能重用被捨棄分支的版本。Save將此最大水位寫回附件，Open初始化自檔案；完整替換是另一context，不能把前一案水位帶入。這個H分配欄位不參與confirmed資料hash、不表示時間或跨案先後，亦不擴充native身分帳。修改多筆record與其review失效標記屬同一ContextHistory步驟；不逐筆提交造成半套版本。

### 7.3 唯一hash定義與驗證

新增資料的hash一律是 **SHA-256(UTF-8(GeometryScenarioCatalog.canonical(value)))**，直接共用固定main既有canonical函式，不另造「Unicode code point」版本：[scenario-catalog.js:19–23](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/scenario-catalog.js#L19-L23)。其物件鍵依JavaScript字串sort的UTF-16 code unit次序、陣列原順序，primitive沿JSON.stringify；null／true／false各有自身JSON字面值，數字與字串不互換，字串quote／反斜線／控制字元依同函式escaping，其他Unicode不正規化，無額外空白／換行／BOM。入口先拒非JSON值、孤立surrogate、非有限數；精確mm大整數保存字串，不能先失真再hash。其他語言須對此同一序列化bytes驗證，不用其預設json.dumps冒充。既有model／native的指紋算法不改。

- DimensionField的inputSha256只取 {raw,unit,datum,evidence}，不含revision或confirmed本身，避免自我hash。
- record的confirmedSha256固定取 {kind,fields} 完整值，包含各欄raw、revision、證據與confirmed；不含record.id／revision、anchor、label、derivations或adoptions。版本與輸入的對應另按7.1／7.2驗，不以hash代替核對。
- modelReview的inputSha256／resultSha256分別取保存的完整record.input／record.result；expectedOldModelHash取完整保存模型record（含sourceIdentity等可選正式欄位）的canonical hash。sourceSha256沿既有load_base去身分正規化來源hash，不重新規定另一種scene正規化。
- 新增／替換時重算全部hash，不信任呼叫者傳「已通過」；歷史Open不拿今日live求值覆寫保存的input/result。即使hash格式合法，欄位結構、來源、型別、數學等式及native包驗證仍逐一執行。


### 7.4 集合與模型核對連結

**集合完整形狀補充：**`{schema:"reconstruction-data/1",revisionHighWater:0,records:[...],modelReviews:[...]}`，四個鍵都必填；兩陣列可為空，不接受未知鍵。版本高水位、records 的精確形狀與 hash 規則依7.1–7.3，概述表不授權額外欄位。`records` 依上表至多 256 筆；`modelReviews` 至多 64 筆、每個 modelId 至多一筆、單筆至多 64 KiB，所有資料仍計入前述 1 MiB 集合預算。每筆 modelReview 僅有下列鍵：

| 欄位 | 型別、來源與守門 |
|---|---|
| `modelId` | 既有保存模型 id；不是 World id，必須存在於同一專案 models。 |
| `sourceSha256` | 同一模型 `result.source_sha256`／`source.scene_hash`，64 位小寫十六進位；等於既有 load_base 正規化後去身分來源的 UTF-8 SHA-256，不另以未正規化輸入文字猜算。 |
| `inputSha256 / resultSha256` | 依7.3同一既有canonical函式，分別對保存的完整input／result取SHA-256；不用UI render、另一種鍵排序或今日求值覆寫原結果。 |
| `recordPins` | 最多256筆、以recordId唯一的 `{recordId,revision,confirmedSha256,role,binding}`；role僅plan-settings／obstacle／source-review，binding形狀見下。pin指採用當時C資料的版本／7.3 hash及其用途，不是native IdentityPin。 |
| `excluded` | 最多256筆、以recordId唯一的 `{recordId,revision,reason}`；reason僅missing-value／invalid-value／needs-review／source-missing／not-selected。須是本次明選範圍中的既有C紀錄，與recordPins按recordId互斥，不自動掃所有房間或隱藏排除。 |
| `scope` | known-subset／fully-reviewed；新增／替換review時，有excluded或被採用資料尚缺核對只能known-subset，所有引用須當下存在且missingRecordIds=[]。fully-reviewed只表示該明選資料範圍當時已核對，不代替D24或整份圖源完整性。歷史review後來過期／缺失仍保留當時scope，但目前有效性另由pins／缺失觀察推導，不能仍顯示有效核對。recordPins與excluded合計須1–256筆；沒有核對範圍就用review=null。 |
| `missingRecordIds` | 必填陣列，初始化 []；最多 256 個 distinct recordId，且每個 id 必出現在本筆 recordPins 或 excluded。觀察到其 C 紀錄刪除即永久加入；只有整筆 undo 到刪除前快照可還原，不能因同 id 重建自行清除。recordPins 與 excluded 合計最多 256 筆。 |

**binding 的封閉形狀及新增守門：**

~~~text
plan-settings → {kind:"plan-settings",fields:["bottom"|"height"|"wallThickness",...]}
obstacle      → {kind:"column"|"beam",id:uint32,definitionFingerprint:Hash}
source-review → null
~~~

plan-settings的fields非空、無重複，record.kind須room-heights；bottom／height／wallThickness分別對應新模型input.settings.bottom／height／wall_thickness。只列本次真正採用的欄位，逐欄值必與同一候選模型完全相等且有有效confirmed；兩個record不得宣稱供應同一模型欄。沒有採用wallThickness就不列，不能把null當0。obstacle的kind須與C紀錄及當次有效adoptions.target一致，typed id必出現在新模型input.obstacles，且definitionFingerprint與**模型保存base_scene**所求得的該RC定義一致；不能只比今天live同id或同bbox。source-review明示只是人工核對範圍，不宣稱值已用於幾何，不能用它繞過plan-settings／obstacle的供值守門。

新增／替換review時，在同一鎖定候選依final after-records重算revision、confirmedSha256及binding；每個recordId必存在、版本及hash相符，所用欄位的確認／證據當下有效。excluded的recordId及revision也須存在／相符，reason由實際狀態或明確not-selected決定。先完成本次C輸入修訂，再產review pins；不能先取舊pins後更新record而立即stale。呼叫者提供的scope/hash/binding一律重驗；全部採用欄及所選核對範圍都成立才可fully-reviewed。

modelReview指定模型不存在、三個模型hash不符、binding不符合該保存模型或欄位越界，在Open替換前拒絕。**歷史Open與新增review分開**：C紀錄後來失聯／改版／改confirmed hash，或其來源頁／證據／關聯核對已過期時，可保留歷史review，顯示過期或缺失；不把「可保留歷史」當成新review可引用不相干紀錄的許可。已存obstacle binding固定於當時模型快照，不跟著C紀錄後來的最後一次adoption改指。純更新adoption收據不增加C輸入revision；沒有改輸入與原模型的歷史review不因此失效。

records的刪除與補missingRecordIds在同一H交易；Open／方案替換／本機恢復的載入掃描若發現pin或excluded指向不存在的record，即在隔離候選補missingRecordIds，再驗容量及全部閉包後一次發布，不先開案再補。已在missingRecordIds的id，即使同id／revision／hash再次出現仍缺失；只有整筆undo到原刪除前快照可還原，不能局部清旗標。新review初始化[]且先驗當前records存在；重新核對產生新review。新增review先保留全部referenced recordId日後加入缺失陣列的escaped UTF-8容量，flags亦計64KiB單筆及1MiB集合；不足時在造成狀態變更前拒絕，不截斷或丟紀錄。歷史scope只描述當時範圍，UI必另標現在過期／缺失，不能顯示仍已核對。不保存token、context或history frame。

新增宿主操作 `commitModelWithReconstructionReview({operation,modelId,expectedContext,expectedFrame,expectedProjectRevision,expectedOldModelHash,record,review})`（**新提案API**）：operation僅create／replace／remove。三種都先核context、history frame及project revision；create要求id尚未存在且old hash=null；replace／remove均要求目標存在且7.3的完整舊模型hash精確相符，不能對已換版模型盲刪。create／replace的record必非null且record.id=modelId；remove的record／review都須null。非null review的modelId也必等於modelId，並依上段從候選C資料與同一候選模型驗pins／bindings；review=null表示明示沒有或清除核對連結，不隱含沿用舊review。

在同一鎖定區段完成既有validateSpaceModel、K3 sourceIdentity、上述新review驗證、完整附件／容量及刪除閉包，再以一次ContextHistory快照共同替換model與review；no-op零歷史。刪模型同一步移除其review；F1b及修改牆高寫新模型時必同一步重建合適review或明示清除，不能留下舊input/result hash的有效連結。所有模型create／replace／remove writer共用這個模型邊界；不得先updateSpaceModel再另寫附件，也不能只修C入口。確認前失效、取消或驗證失敗兩者不變；一旦成功提交，晚渲染不重複提交或把成功描述成取消。Save/Open、方案快照及本機恢復都驗此閉包；沒有C review的既有模型不強制新增附件。

原始資料和已確認值分離：使用者修改 raw 後，舊 confirmed 即失效，不能繼續拿舊值產生柱樑。三值全部存在但不滿足等式，顯示衝突並阻擋採用，不自動覆寫其中一欄。只有兩個已確認值時可顯示第三個的唯一整數推導，使用者確認後採用；圖面高程基準仍未知時不以「看起來是樓板」自動轉成 World z。

柱平面已知但高未知：保存 width／depth／x／y 與來源，顯示尚缺 bottom/top 或可推導的條件；不呼叫 newid、不創造柱體、不畫帶假高度的 3D ghost。已確認的 D3 平面繼續可編輯。RC 尺寸從某個面取值時，必先核對該面確為需要的正交矩形及明確位置；L 形或旋轉／未放置面不能以 bbox 冒充柱足跡。也可保留手填的獨立 x/y 尺寸及明確證據。

來源變動只令關聯／證據評估顯示需複核，既有RC不跟著改；原核對輸入未改時不為顯示狀態製造revision，只有實際修改anchor／fields／derivations才依7.2升版。刪除來源或觀察到刪除後同 id 重建，保留原始記錄並標關聯失效，不自動改綁。內容 hash 相同不證明同一物件。重開後無足夠沿革證據的關聯明標身分未證；要採用到現有物件時須重新明選目前目標、核對差異並預覽，不能用附件 id 替代 native 身分。source review 不阻擋獨立的既有手動 RC 操作。

### 8. C 的正式入口與可見減項

在原「來源紀錄」區，把「增加紀錄」改為同一個「記錄資料」選單：自由紀錄、房間高度、柱、樑。保留既有自由紀錄內容；結構化欄位和來源證據在同一抽屜切換，不另加畫布卡片、工具列、第二閱讀器或常駐提示區。既有柱／樑inspector以原常駐#rcfApply的位置改成單一「尺寸操作」選單：第一項「套用尺寸」保留原#rcfApply節點、handler、鍵盤與native流程；第二項「核對來源資料」開同一C抽屜。原常駐Apply按鈕移入選單，不另外保留一顆，也不加第三個工具列入口；關閉選單／抽屜把焦點還給原尺寸操作入口。這是該情境入口自己的可見減項，不拿來源紀錄選單或其他issue抵帳。

原「放置與空間（選用）」區接續提示改成依缺項顯示的一個主要動作：缺位置→原放置表單；柱樑資料齊→預覽建立／變更；僅能建已定面→原空間工作區 faces 模式。說明與錯誤留在現有狀態區。手動新增柱／樑、既有面放置、自由紀錄與 #48 的證據閱讀操作保留，不移除其能力。既有來源入口與選用區：[geometry-web/docs/REFERENCE-PROJECT.md:7–18](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/docs/REFERENCE-PROJECT.md#L7-L18)。

來源紀錄採用到 RC 時，明寫「將已核對數值填入柱／樑定義；不是即時來源連動」。如果使用者需要正式引用連動，另有相應公理與原生能力才可提供，這裡不偽造。

### 9. C 的 bridge、原子提交、保存／取消

既有建立路徑確實組出以下 DSL；編輯也用同型重宣告，不需要另一種 RC 幾何：

```text
column ID [in D5_SPACE_ID] at X Y size WIDTH DEPTH z BOTTOM TOP
beam ID [in D5_SPACE_ID] along x|y from A to B at C width WIDTH depth DEPTH top TOP
```

來源：[geometry-web/app.js:10228–10283](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L10228-L10283)、[geometry-web/app.js:9688–9705](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L9688-L9705)。本入口一律送已明確認可的完整 z/top；不利用省略欄位暗中套用 D5 槽高。使用者若明選既有 D5 槽高，先原生讀取並在核對區顯示來源與取值後才確定採用，仍不拿 D22 模型 id 填 spaceId。

**新增宿主接線**：紀錄完整且來源／目標同版後，產生原生 line preview；由原生完整候選驗尺寸、歸屬、既有依賴與影響。新目標 id 只是現有 newid 的候選，不提前保留。確認必提交同一 line token；取消只取消自己持有的 token。現有 `api()` 會在遇到 preview 時沿 `confirmReferenceImpact`，既有 `mutate()` 管理整組歷史；此處須抽用其既有候選／提交護欄，不能先 mutate 再補做假預覽。[geometry-web/app.js:701–704](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L701-L704)；[geometry-web/app.js:10120–10167](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L10120-L10167)。

為讓成功 native 確認與 adoption 收據在同一完整專案歷史步驟，新增 typed 宿主介面（新提案，非現存 API）：

```javascript
prepareReconstructionConfirmation({
  owner: "line", token,
  contextToken, historyFrame, projectRevision, definitionRevision,
  beforeAttachment, afterAttachment, recordId, recordRevision
});
```

準備時先完整驗證afterAttachment、資料revision、水位及所有受影響modelReview，並保留缺失旗標容量。prepare固定完整before/after與native候選、recordRevision、requestId，從送confirm到確定receipt期間由共同操作租約阻止其他確認及會替換該project context的動作；不得改寫已準備的after資料。只在同owner/token/requestId的確定成功收據中一次發布native結果與prepared metadata，建立一個完整歷史步驟。prepared資料保留至收據結算，沿既有pending／receipt恢復接點查回，不另給自動Resume資格。

不得先改正式附件、不得成功後另打一個local步驟，也不能借用#249的engineering token種類。native與metadata都無變更為no-op；只增加adoption核對收據是明確的一筆本機歷史，不偽裝core修改、不增加核對輸入revision。native已成功但metadata結算尚未完成時保持pending並禁止下一次修改／保存成功宣告，依同一receipt完成，不能丟prepared資料或重送建柱。

**確認前**的取消、native拒絕、附件容量不足、來源／表單／歷史／context改變，均零提交，保留raw及原World；遲到preview只丟棄舊結果。**confirm已送出後**，不能因close、timeout或晚回覆便宣稱原World不變：沿原requestId查確定終態，成功就結算同一prepared metadata／history一次，拒絕才保持before。未知保持pending，不重送建立、不改標採用成功；回覆已成功但render失敗仍保留成功收據，恢復呈現不再建第二支。若重連後無法取得同一prepared資料或無法確認receipt，保留恢復資料並明示未結算，不能猜補adoption或冒稱整筆完成。

新增附件必登記 `reconstruction-data/1` 宿主能力與新的可攜格式，不得塞入舊白名單。現存附件只容許四種類型、重複 kind 拒絕；實作要將該封閉列舉擴成五種、補 source closure／容量／未知鍵／保存重開驗證，不能改成接受任意附件。[geometry-web/feature-attachments.js:285–333](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/feature-attachments.js#L285-L333)。與 Q38j、#249 等格式變更由同一整合者配號；各功能能力獨立偵測，不能因別項升版就跳過 C 的 validator。舊 reader 明確拒不支援格式；新 reader 依原規則開舊案，沒有 C 資料不自動製造紀錄。

紀錄 raw 編輯按一個欄位編輯動作合併本機歷史；IME 組字中不確認／不採用。保存前 flush raw，非法／未完成字串可留在附件，不能進 World。關閉抽屜保留已記錄原始輸入；明選捨棄才移除。完整專案保存帶來源原 bytes、附件與原生 scene；.scene 仍只有 World。無來源的斷鏈紀錄可保留為待補，不讓附件靜默遺失。
