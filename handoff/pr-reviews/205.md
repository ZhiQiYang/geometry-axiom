1. **選來源。** 明選閉合 D3＋完成面框架／結構側，或既有 D41；明選柱／樑與外環哪些邊代表 RC。名稱、最近物件、同空間都不能替代引用。原輪廓的孔、凹階及 apply-proj 缺口保留。
2. **選排法與來源。** 明選起鋪 u/v 側、板 length 軸、固定 panel 材料版本、gap 來源、X ParameterRef、角材 A/B 來源。並列來源與有效值；B 與宿主 h 的關係由原生核對。方板也不自動猜 length 軸。治具、min_piece、原縫偏好採既定版本規則，不另露出未採納的模式選項。
3. **完整生成候選。** 在獨立 World 副本，建立必要的完成面／試排／衍生宿主；先建完整值來源依賴 DAG，依現行 FT 與核心的合法候選順序展開外環 boundary、柱邊 primary／secondary、R45、記號及逐跨副支。既有提案五步是其可達配置的排序，不能壓過實際依賴；#335 明示成組若已採納，以整組值節點求值後共同驗證，不拆回兩次順序放置。R45 只能修改外層候選，不能呼叫公共 confirm 先提交；既有禁止巢狀 history 的守門不刪。
4. **看同一份預覽。** 顯示真板片、孔、有效縫、各角色角材及來源、每支 L/A/B、總支數、明確未生成位置／理由、所有既有下游影響。退縫表逐候選列原位、選中位置、累積退距、兩側板寬、是否補併料及失敗碼；無固定總退距上限，但越過前一縫、非法板寬、無支撐或碰撞仍拒絕。
5. **確認。** 必須是同一輸入世代、來源及完整候選；成功一次提交、一次 history／undo。任一步違規整筆失敗，World、專案附件、dirty、history 及記號結算都回候選前；不留下半套宿主或參考線。候選中可有暫時配號，但正式 id／存在期只由原生成功提交結算。
6. **取消／改選／失效。** 修改設定立即廢掉舊結果；切面、切專案、Undo/Redo、來源變動、重連使 token 失效；輸入保留供重預覽。晚回覆不重開表單或覆寫新輸入。確認回覆不確定時沿原 requestId 查回執，不盲目重送、也不先當未提交。

零料／部分結果不等於完整骨架成功。若有合法零板片，顯示「沒有面材需求」，不虛稱已排完整天花。受容量、未支援配置、引用多解或引用循環阻擋時分別診斷，不用「現場不可能」掩蓋產品未支援。PF-5 能描述樑，不表示 FT 已定遇樑的自動分段策略；超出已定 FT07 的配置仍按原未支援界線拒絕，不能忽略樑。

## 四、native／bridge 的具體新增介面（提案）

以下是待實作名稱與 wire 契約，**不是聲稱 main 已有 API**；所有正式幾何驗證沿共用候選 owner。

```text
GET  /framing-template/capabilities
POST /framing-template/preview
POST /api  framing-template-confirm <token>  [既有 requestId envelope]
POST /api  framing-template-cancel <token>
```

capabilities 回版本化 schema、可用模板版本／policyFingerprint、所需 PF／scene 能力、容量、支援配置及拒絕原因；未滿前置時 UI 顯示實際缺項，不假開可確認入口。preview 請求為 `framing-template-request/1`，必帶 `expectedRevision`；宿主另固定 context、history frame、connection session 與 inputGeneration，任何變更即撤銷候選：

- `template:{id:"flat-nailed-ceiling",version,policyFingerprint}`；
- `target:{kind:"finish",id}`，或 `{kind:"boundary",id,frame,structuralSide,obstacles}`；兩種互斥；
- `layout:{lengthAxis,startU,startV,panelMaterialVersion,gapSource,thresholdRef}`；
- `section:{A:DimensionSource,B:DimensionSource}`、`support:{heightSource:DimensionSource,derivedPlacementId?,gridId?}` 與明選 RC 語意集合；新建宿主須明選 h 來源，引用既有宿主時 h 從該正式定義取得，不暗把 B 的有效值填成 h。新宿主／主格以候選暫時鍵表示，確認才配正式 id；RC 集合以具型別障礙及 `(boundaryId,edgeKey)` 表達，不傳輪廓端點當 RC 擋面。target=finish 時只讀該 D41 的正式框架／障礙；若要修改，必帶明確的同候選 D41 變更並列預覽，不能另外保存一份 shadow 框架；
- `replaceTargets:[]`，只在使用者明選替換流程時才帶目前 World 的具型別定義集合。

輸入不得含 authoritative 料長、板片／角材八頂點、建構者自稱的通過旗標或可執行腳本。preview 回 `framing-template-preview/1`，包含同一來源 revision／輸入指紋、完整性及 valid、temporary-key→預覽定義、完整 before/after、板片／縫及退縫理由、逐料診斷、容量與來源依賴；只有完整合法者有 token。C／HTTP／JS 精確傳遞超安全整數面積及有理數，不拿四捨五入的畫面值回寫。

confirm／cancel 接既有可寫守門、requestId／receipt、確認租約、nativePending、definition-changed、dirty、history.observe、保存同步等同一條路；漏任何一處都不算產品接線完成。純 read／preview 不改正式 World。新指令須列入相關白名單及能力登記，但此留言只呈閱設計，不直接改登記檔。

### 替換已有布局

A 方案沒有排他 owner，因此不能依「看起來是同一次生成」猜測刪除集。使用者明選現行 trial／宿主及要替換的一般定義，原生展開引用檢查並列完整刪除／保留集合；未明選者保持。任何被外部引用而不能刪除的目標、D34 owned、未知 owner 或不完整 pair 都拒絕，不能自動拆組或移植引用。

明選的刪除與新骨架置於同一外層候選；依 D60 記錄全部明示刪除，已啟用身分帳時新物件得新存在期。不能以相同 id／幾何沿用舊記號，也不對每個子步驟獨立結算。若只是調整既有正式定義，沿一般編輯就地修改與 I8 重算；本流程不自動把它改稱「重新生成」。

### A 的持久格式與版本

完整專案新增一份 `kind:"framing-template-recipes"` 附件，schema／reader capability 為 `framing-template-recipes/1`。每筆配方含：

```text
recipeId                  專案層 UUID；不是 World id／owner
name                      顯示名稱，不作來源身分
template {id, version, policyFingerprint}
settings {lengthAxis, startU, startV, gapPreset, sectionPreset}
slots[] {slotKey, requiredType, preferredFixedVersion?}
lastBindingHints[] {slotKey, typedReference?, displayLabel?}
```

slots 明列完成面／邊界框架、固定 panel 版本、角材 A/B 與宿主 h 的合法尺寸來源、gap、X ParameterRef、RC 障礙與外環語意。preset 只是下次表單的提議，必須由使用者明選正式來源後才進候選；lastBindingHints 只方便找回，不證明存在期、不自動關聯。重開、換專案、同 id 刪建時均要求重新核對本次來源；不能把 unknown 變成 continuous。原生模板版本內容不可變，`policyFingerprint` 對應規則清單、候選偏好與資料契約；不能用主線程式 SHA 的變動暗升配方版本。

工程上限提案：每專案 32 配方，name≤96 UTF-8 bytes，slots≤16，hint≤64，附件≤128 KiB／4096 nodes；超限整筆拒絕，不截斷。此為首版工程容量，不冒稱幾何定理。未知附件 schema／required capability 或 known version 的 policy 指紋不符，完整載入前拒絕。讀得懂 schema 但沒有該 generator 版本時，配方可原樣保存、唯讀查看；標明該版本無法生成，不能偷偷升級。既有正式 World 的通用定義仍可獨立重建。

配方保存／改名／複製／刪除是一筆專案附件歷史，不改生成物；刪配方不刪料，刪料不回寫配方。保存當前草稿為配方必須是明確操作、先驗完整設定；未完成表單、preview token、候選結果、退縫搜尋記錄、產物清單、求值 cache 或核對通過旗標不暗存（使用者明設的 gapPreset／sectionPreset 仍是合法意圖，並非求值 cache）。明示保存成功後，此型別是 D51 的正式專案設定；尚未送出的編輯仍屬 D56 的未提交資料，不因換名為配方就成為正式設定。本切片不暗增未完成草稿的保存承諾。

`.scene`／dump 只包含已確認的正式定義與能力，不攜帶專案配方；`.gcanvas` 同時保存正式 World 和附件。loadfile／reference_rebuild 重算已存正式定義，不重新執行 W 的候選偏好搜尋；undo/redo 還原正式定義與已提交附件各自的同一步狀態。完整專案及 A/B 方案保存附件；D25／definition-import 首版不順帶搬模板配方，也不以它帶入來源記號。

### A 的來源變動

一般來源改動仍沿 D7／D42／I55 完整重算既有物件；不能凍結舊料長或忽略碰撞。模板不保證原先的 FT 搜尋結果在新房間下仍是目前最佳／完整骨架，因此先前預覽與完整配置宣稱立即過期，不在重開時顯示永久「模板通過」。需要改數量、重新選縫或支承策略時，走前述明選替換／再生成，同樣整筆候選。這個差異在第一次確認前就須明示，不能保存後才補充。



## 六、局部板縫表示的範圍

有限的「每軸原 signed k → 新整數中心」可以完整表達目前直排 FT 的**縫位結果**：oracle 用每軸一份全長縫位置陣列，FT02、牆階退縫及 P-182 對末縫連續退縮最後仍只決定該線的一個中心。局部對牆是決策依據，並沒有使同一條直排縫沿長向彎折或分段改位。最終只需把有變動的原鍵寫入有限 map；多輪退距不另生新縫、不重編鍵。[現行 FT01–FT06](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/PROPOSAL.md#L36-L51)；[seam_centers](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/oracle/framing_oracle.py#L237-L264)；[P-182](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/oracle/framing_oracle.py#L1183-L1232)。

這證明表示法足夠，**不證明所有 oracle 說可行的場景都已通過真 D42 板片、材料尺寸、D7 及完整 I8**。oracle 目前只用縫陣列與角材幾何，新的正式候選還必須驗真板片。交丁、同鍵按 band 分別移位、彎折縫或任意切板拓撲不在這個首版擴充內；既有無覆寫交丁仍按原契約。

以下配合本稿 FT-S1 的 A 方案：配方是專案生成意圖；確認產物為一般 D42／D6／D7 等定義，無排他 owner。W 的搜尋結果經明選確認後成為 D42 的直接定義值。核心重建這些值與正式引用，無須讀配方或重新執行 FT 偏好。來源變動仍完整重算，不能凍結料長；但不自動改縫中心或重跑 W 搜尋。

## 七、唯一的幾何定義

在完成面原框架內，每軸 X 的原材料尺寸為 P_X>0，縫寬 g≥0，T_X=P_X+g，f=floor(g/2)，h=g−f=ceil(g/2)。原週期中心：

```text
c_X(k) = a_X + k*T_X + P_X + f,     k ∈ Z
C_X(k) = seamOverrides[X,k].center  （鍵存在）
       = c_X(k)                    （鍵不存在）

Gap_X(k)  = [C_X(k)-f, C_X(k)+h)
Body_X(k) = [C_X(k-1)+h, C_X(k)-f)
```

每對相鄰中心必須 **C_X(k)−C_X(k−1)>g**。這同時確保正寬板本體、縫不交越及 signed k 順序；僅驗中心遞增還不夠。g=0 時仍要求正寬本體。定義未覆寫處回到原公式，不能以挪後可見陣列重新編號。

直排第 (i,j) 本體是 Body_u(i)×Body_v(j)。先與 R41 的 G_面材層求精確交集，再按既有 R42 切成完整分片、孔與確定序號。相鄰兩側都存在真分片才構成有效板縫；只移支撐、仍沿舊週期片邊計算 R43，是錯誤表示。

### 真板尺寸上限及計數

每個 (i,j) 的全部非空實際分片聯集記為 Q_ij。**對 Q_ij 的 bbox 驗兩軸尺寸 ≤ P_u、P_v**；不對 F 外的虛擬完整 Body 強制 ≤P。空 Q 不算板、不做材料尺寸判定。

這裡刻意驗同一 tile 的分片聯集，不只逐分片驗：PF2 既有契約以原板片為 wholeCount／cutCount 單位，分片另計。若兩個相距超過 P 的小分片各自可放進材料、卻仍合計一張原板，就已偷改用料／板片語意。[PF2 讀取與計數](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/panel-fill/PF2-NATIVE.md#L39-L48)。

`whole=true` 只在 Q_ij 是一個無孔矩形，且沿已明選 length／width 軸恰為 P_u×P_v 時成立；其餘非空 tile 為 cut。已退成 907 mm 的 body 即使沒有再被 F 裁掉，也不能叫整片。相同 signed tile 的分片不因形狀、面積或距離重新合併／配號。

這是保持既有每 tile 計數的收斂方式。若要改為每個分片可獨立消耗一張材料，就必須另外明改計數／來源語意；本稿不採那條擴張。

### signed k、反向與奇數縫

FT 從 min 側起鋪時 a=lo，依次第 j 條（j≥0）對應 k=j。從 max 側起鋪時 a=hi−P，依次第 j 條對應 **k=−j−1**；起鋪的完整板仍是第 0 片。由此可推得：

```text
min 側首縫：lo + P + floor(g/2)
max 側首縫：hi - P - ceil(g/2)
```

所以 D43 的原 signed 鍵與 FT01 的逆向 ceil 完全相容；不能把從起鋪端數的非負序號 j 當 signed k。floor 只在完成面框架取一次；結構側 s=−1 時，依 R41 映 v_d=s*v，不能再取一次反向下界，也不能翻 U/V/N 修掉差 1 mm。[D43](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/公理層.md#L851-L866)；[R42](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/公理層.md#L2362-L2378)；[FT01／FT02 框架說明](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/PROPOSAL.md#L55-L58)。

FT02 已明定首縫也可能退縮；因此「整片起鋪」是未觸發 FT02 時的基準，不得再用它否決已定首縫退縮。預覽要如實顯示第一片也被裁短，不能保留 whole 標記掩蓋例外。

## 八、定義、候選搜尋與依賴圖分離

### 8.1 K 只求已明示的中心

正式依賴方向保持：

```text
D3／D13／D14 → D41
D41／D26／D31 → D42（含直接中心 map）
D42 → 衍生承載面 → from-fill → D6 → D7
真板片＋D7足跡 → R43／FT 檢查結果
```

D42 不引用 project recipe、已生成 D7 的長度或碰撞結論，D7 不反向決定已保存的 C(k)。有限搜尋可以反覆構造不同候選，但每一個候選內的值圖必須是 DAG。結果的驗證可同時讀真板與角材，不把驗證關係註冊成相互求值引用。

### 8.2 W 的有限選擇不是核心循環

現有 oracle 的 seam_centers／g7_settle／expected_seam_positions 使用固定 8 輪；expected_seam_retreat 使用固定 4 輪並取 hit[0]。它們不是「已到穩定」的數學證明；碰到前一縫後 break 也不能當成滿足全部條件。[G7 迴圈](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/oracle/framing_oracle.py#L238-L277)；[獨立縫位檢查](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/oracle/framing_oracle.py#L1306-L1369)；[短牆階退縫](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/framing-template/oracle/framing_oracle.py#L1479-L1533)。

建議正式化為以下有限步驟（此為需呈閱的定義精化，不冒稱新增使用者原話）：

1. 固定本次明選來源、版本、w、X、板尺寸、起鋪方向；W 搜尋期間不改來源。
2. G7 的 d 為離起鋪端距離，門檻用整數式 **2d>2D−3w**。觸發時候選為 floor((2D−3w)/2)，不使用浮點 1.5。D 只來自本次外環牆在該位置的最近有效對牆距離；無對牆段時依原 outer bbox 預設。
3. 每次有效退縮嚴格減少 d。可取得的目標值都來自有限外環／孔邊／凹角座標與上述式子；收集、去重，依原位優先及退距由小到大排序。G7 定點求值只有在條件已成立時結束；新位置跨前縫、板本體非正或仍未滿足條件，記為該候選失敗，不能 break 後假成功。
4. 多個短牆階同時命中時，把每個已定幾何條件推出的候選列入同一有限集合，不以環陣列第一個 hit 決定唯一答案。每個候選按原 G7 及完整幾何再驗；候選及其失敗原因須可核對。超出公開資源容量回 CAPACITY，不以 4／8 輪後當前位置冒充定點。
5. P-182 的原位先完整構造；原位可行即選原位，包含依既有規則調支撐及補併料。原位不成立才依已定擋料集合、由近到遠完整構造並驗證下一個候選。每一候選先產 D42／真板，再產正式來源化 D7，最後驗全部核心、模板及宿主條件，包含本稿材料尺寸上限。
6. 第一個全數合法者是**依偏好確定的選中解**。可能存在多個物理解，這不構成錯誤；它不是「證明物理唯一」。無合法候選回完整逐候選原因。某候選內的 R6 多解／來源引用不唯一仍依原契約拒絕或要求明示，不准借 P-182 的排序暗選另一個幾何來源。
7. 所有候選均不得取正式 id、消耗記號或留下正式物件；只有明示確認的一個完整候選一次提交。core_limited 可以作診斷，但不能當可提交者。

候選來源有限、去重且 d 嚴格退縮，所以終止上界可由本次不同牆／擋料座標數計算，不必另設固定總退距上限。已採納「不另設累積總退距上限」不豁免板材上限、縫交越、碰撞、承接或引用合法性。[原位優先決策](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/決策佇列.md#L706-L726)；[累積退距已決回報](https://github.com/ZhiQiYang/geometry-axiom/issues/205#issuecomment-6336484777)。

## 九、縫中心覆寫的持久化與原生介面

**建議能力名** `panel-fill-seam-overrides/1`（本稿提案，非現有能力），依賴 panel-fill/1。只要定義帶非空 map 就宣告，未知能力的舊讀取端須整份拒絕，不能忽略 map 後載成週期板。

沿既有 `panel-fill-transaction/1`、expectedRevision、put-panel-fill 和完整候選確認；不另設第二個 preview owner。put 的 value 新增：

```json
"seamOverrides": [
  {"axis":"u","k":3,"center":3659},
  {"axis":"v","k":-2,"center":41}
]
```

這是欄位形狀示例，兩筆數字是否同時合法必須按該試排的實際來源求值，不能憑示例直接建模。

- axis 僅 u／v；k 為既有 D43 的精確 signed 整數，center 為 D1 範圍內整數 mm；未知欄位、重複 (axis,k)、非整數、型別不符拒絕。
- 首版只接受 pattern=straight。非空 map 與 stagger 同時出現回 UNSUPPORTED；無 map 的原交丁完全保持。
- 本稿建議公開資源上限為每試排 4096 筆；這是工程容量，不是總退距上限。實作 capability 必須回報，超量整筆拒絕，不截斷。原板列舉、頂點與縫線容量仍分別檢查。
- canonical 保存先 u 後 v、同軸按 signed k 遞增。定義讀回包含 map，場景沿既有 `panel-fill <id> definition-hex <canonical JSON hex>` 保存，不保存片段／搜尋 trace／真板 bbox。
- 省略欄位在舊場景表示空 map。對已帶 map 的既有試排做完整 put 時，請求必須明帶完整陣列；遺漏應拒絕為缺少現有定義，不得靜默清除。明帶 [] 才表示清除並回復週期來源，必重驗完整下游。
- **不可自動刪除「目前 center 恰等原 c(k)」的顯式項目。** 有項目表示固定直接中心，缺鍵表示跟隨週期；材料／gap／a 日後改變時兩者語意不同。W 初次生成可只輸出實際調整的鍵，之後重算不自動正規化掉定義。
- 定義 fingerprint 必包含排序後全部明示欄位；derived 的 body／stockSize／occupiedBounds／whole／片鍵與承接均從同一 World 求值。完整 dump→新 process load→讀回須保留 map 與相同結果。
- 沒有 FT generator 版本仍可重建正式 World，但執行器仍須支援通用 seam-overrides 能力。缺通用幾何能力與缺 project recipe 的 generator 是兩種不同錯誤。

### 有限而完整的列舉

不能只列出舊 bbox 內的週期索引後改中心，因為移動的本體可從舊查詢範圍外伸入 F。每軸候選索引至少是「原週期本體與有效面 bbox 有正長交集的所有 k」聯集「每個覆寫縫 k 所影響的本體 k、k+1」；再按實際 Body 求交並丟棄空者。兩軸做積後精確裁切。這個集合有限而完整：未受覆寫影響的本體恰等原週期，受影響者已全列入。容量先驗完整計畫，不抽樣、不只取前 1024 張。
