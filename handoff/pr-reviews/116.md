### 3.3.3 H-116-VIEW/1：必須補的只讀 bridge 與精確視角

**以下是完整介面提案，main 尚未有這些路由／欄位。** 現行 `pick` 僅輸出 scene 索引及 TimberFaceId，沒有 D3 面根拾取；現有 v3FilterOps 只按 style／view 過濾，DrawTarget 一般 ops 也沒有物件根。因此不能只加 contextmenu DOM 就聲稱上節交付。[bridge pick:260–281][bridge-pick]、[原生拾取:2363–2455][native-pick]、[分類過濾／replay:800–910][view-filter]

新增 `POST /view/read` → 原生 `view-read <server-generated-json-path>` 與 `POST /view/pick` → `view-pick <server-generated-json-path>`；沿既有受控 JSON 檔 bridge 模式，路徑由 server 產生，客戶端只送 JSON。兩者只讀，不取得寫入 token、不建立第二個 World；保留既有 render／pick 協定供原操作，不能改掉舊索引欄位含義。

read request schema 固定為 `workspace-view/1`：

```json
{
  "schema": "workspace-view/1",
  "expectedRevision": "123",
  "scope": {"kind": "project"},
  "presentation": {"mode": "three", "focus": null},
  "layers": ["face", "guide", "timber", "rc"],
  "hidden": [{"kind": "column", "id": 7}]
}
```

- expectedRevision 是既有原生 definition revision 的十進位字串；scope 另可為 `{"kind":"space","id":N}`，用於檢查當前空間工作區仍存在。現行 renderSpaceProjection 也是呼叫全場景 render，因此本版 space scope 保留該顯示範圍，不偷改成只畫該空間 members，更不改空間成員。presentation.mode 僅 three／focus；three 的 focus 必須 null，focus 模式的 focus 必須為 front／side／top／bottom。hidden 的 kind 封閉為 boundary／placement／guide／timber／column／beam，id 為 uint32（0 合法，仍須該型別的實際 root 存在）；有 D3 的面用 boundary 根，無 D3 的承載面才用 placement 根，同一已畫面不以兩種別名重複列為 root；無 D3 的承載面只能以 placement 根呈現，不能捏造 boundary。重複條目去重，未知種類／非法 id／不存在的 root／過期 revision 拒絕整個請求。[space projection:3742–3783][space-projection]
- 回覆 schema `workspace-view-result/1`，欄位為 `status`（READY／STALE／INVALID）、`revision`、`viewKey`、`layout`、`ops`。READY 的 layout.views 每項含 `viewId`、right、down、bounds、tx、ty，ops 每項沿原 DrawTarget 序列並帶 `owner:{kind,id}`；標題／框線等 view 級 ops 的 owner 為 null。viewKey 只綁定當前 revision、scope、presentation、layers、hidden 的讀取設定，非寫入能力；STALE／INVALID 不帶可操作 viewKey。原生同一次讀取產出 layout、owner 與 ops，JS 不解析「面 2」文字、style 色碼或 array index 反查身分。
- 顯示與拾取使用同一 viewKey／可見集合／原生畫家順序。面根的命中只用已繪出的原生輪廓與孔；孔內不命中面，退化成線時按同一拾取半徑測線，不用投影 bounding box 代替輪廓。參考線、角材六面、RC 保留原生命中演算法與後畫覆蓋順序。D3 面／placement 的新增命中插在其實際繪圖層，不能遮過原先畫在上面的角材／RC。這是呈現命中的補齊，不重定幾何。
- pick request schema 為 `workspace-view-pick/1`，欄位固定為 `expectedRevision`、`viewKey`、`viewId`、`point:{x,y}`、`radius`；point 與 radius 是該frame的整數mm，radius非負。先按目前CTM／view transform轉到該frame，再沿既有拾取量化：x/y用Math.round；主三視圖r沿Math.round(8/scale+.5)，既有局部投影拾取半徑12保持。本片不把這個拾取用量化當幾何新來源，也不把hit點自動寫進定義。依據為 [app.js:832–844](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L832-L844)、[app.js:8995–9000](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-web/app.js#L8995-L9000)。回覆 `workspace-view-pick-result/1`：`status`（HIT／NONE／STALE／INVALID）、`revision`、`viewKey`、`target`、`hoverOps`。HIT 的 target 必含 `root:{kind,id}`，另含 `placementId`、`boundaryId`、`memberFace`，不適用者 null；memberFace 僅 A0／A1／B0／B1／START／END。native 從實際 scene 物件回傳 id 與合法 host D3，不把索引直接送給 selectObject。NONE 的 target 為 null；STALE／INVALID 不可導航或開物件選單。
- right／down 軸固定：front = (+X,−Z)，side = (+Y,−Z)，bottom = (+X,+Y)，**top = (+X,−Y)**。前三項逐字沿 current_geometry 的既有 ViewFrame；top 是本片新增的原生只讀視角，觀者在 +Z。focus 模式以該單一 frame 的原生 bounds 排版並 fit；three 仍維持原前／側／仰的第三角配置。不能直接 CSS 翻轉仰視後沿用未翻轉拾取，也不把 top 寫回模型方位。[現有 frame][view-frames]
- JS 在 await 前捕捉 workspace／session／revision／presentationGeneration／openingGeneration，回覆全部相同才呈現；pan／zoom／切 frame 令較早螢幕點 pick 失效。右鍵使用該次事件的精確 pick，不以節流 hover 的舊點代替。未知 root 僅可顯示不可操作原因，不能 fallback 到第一個選中物件。



**能力與封閉輸入：**服務另明列 `workspace-view/1` 讀取能力及其支援的四個frame；只支援舊pick不等於支援此介面。request/response逐層只接受上列鍵，拒絕重複JSON key、未知schema/種類、NUL、非有限數、越界整數及超量，不截斷。單次request至多1MiB，hidden筆數不得超過服務宣告的本World可畫root容量；ops超過已宣告輸出容量回明確CAPACITY，無可操作viewKey，不回一張被截短但標READY的圖。viewKey隨原生revision/session或presentation設定退休，不能被當作來源pin或任何write token。正例XYZ=(100,200,300)在局部frame應得front=(100,−300)、side=(200,−300)、top=(100,−200)、bottom=(100,200)，再套layout；drawing與pick必用同一矩陣。

上述原生 read／pick 與前端 adapter 是 PR-c 的實作依賴，不可把「尚未有 boundary typed pick／單物件 owner metadata／top frame」留給接手者猜，也不能先記可驗收完成。它們不改 SSOT；任何日後新增幾何操作必須走原來的操作與候選，不掛在 viewKey 上提交。

## 5. A 的完整操作契約

### 5.1 共用資格、ownership 與群組守門

操作前讀取真正的 typed timber 定義與所有權，不以畫面上的數值、外觀或 id 猜分類。

本切片只支援同面、普通已放置 D7，且沒有本版未支援的群組約束。assembly-owned 必須服從 D34／I42 的所有權入口；#335 pair／成組則以群組約束列為 v1 不支援，不把它改稱 owner。任何 ownership 或群組資料不明者整筆停用。只有實際已有可用的原編輯入口才提供導向，不能虛構連結。多選混入不支援物件時整筆不可執行，不靜默濾掉它。

未來允許群組的部分成員修改時，所有明選 patch 先進同一候選，完整群組與外部依賴共同驗證；assembly-owned 另須取得其所有權契約允許。所選集合不足既有契約要求便整筆拒絕，不自動拆組、解除 ownership、補選或只修改成功者。

### 5.2 複製

只有同面單支符合資格的角材可用。取得截面型別來源、來源欄位映射、角色、方向與定位定義；不保存展開長度、幾何、正式 id、owner 或歷史。

工作階段剪貼資料綁專案、面與原生來源／history 世代。世界變更、Undo/Redo、切專案或重連即失效；純縮放／平移不使它失效。複製本身不改 World、dirty、history，不讀寫系統剪貼簿。

來源保留完整身分。例如原 A 引用某卡 field 2、B 引用 field 7，即使兩欄同值，也仍保存各自欄位身分；不改成裸數字或互換欄位。

### 5.3 貼上

在同面開啟現有角材建立表單，預填可重用的型別來源與角色，列來源名稱、完整引用與有效值；使用者明選合法新定位。

原生重算候選與完整影響後才可確認。新角材是新存在期，沒有原物件的正式 id、存在期記號或 owner。確認前不配正式身分、不改配號狀態。

來源或世代失效時，顯示具體原因並要求重新複製，不找最近線、不重新猜引用，不保留一個永遠等待的可用貼上按鈕。未修改的舊定位若會重疊，仍依原生規則拒絕，不能靠偏移一個像素避開。

### 5.4 重複

重開最後一筆成功建立普通角材的輸入配方，仍要求新的明選定位。它不是重放原始命令、原 id、舊 token 或上次結果；不重複刪除／修改動作。

成功配方綁當次專案、面、型別來源與新的正式基準；來源失效時停用。貼上與重複共用同一建立表單和候選 owner，保留同一組來源欄位身分。

### 5.5 多選批改

沿用已交付的選取集合。初版只批改既有可編輯的 A／B 型別來源、角色與方向；定位保持每支原引用。

每欄預設「保持各自原值」；混合值顯示「多種」，不可用第一支的值覆蓋全體。只有使用者明選要修改的欄位才形成 patch。若 A／B 有不同來源種類、版本或 fieldId，即使有效值相等仍顯示不同來源，不當成同值無差別。

**原生先將全部明選欄位 patch 套入同一隔離候選，之後才對最終候選完整求值／驗證。** 不能一支改完就驗並提交，再處理下一支；也不能因中間狀態暫不合法而拒絕其實合法的終態。原 placement order、未改欄位、來源與 D60 incarnation 均保持，不 delete/recreate、不重排、不以 id 排序改變放置次序。

預覽逐支列出新舊來源、有效值、角色及完整影響；任一最終違規全批拒絕，錯誤指名物件與原條號。成功一次提交與一筆 history；取消／拒絕零正式變更。整組重新定位、任意平移、跨面、混合型別、批刪及子圖複製不偽裝成本切片能力。

### 5.6 取消、no-op、晚回覆與保存

改選取、切面、關閉表單、切專案、Undo/Redo、來源改動均撤銷舊候選。關閉後的晚回覆不得重開、改新表單或提交；確認只對畫面所見同一集合與同一候選有效。

沒有選中任何修改欄位，或正規化後正式定義完全不變時是 no-op：不送變更提交，不新增 history、revision 或 dirty。有效數值相等但來源種類、版本、fieldId 或角色定義改變不是 no-op，仍須完整預覽與一次確認。

成功的實質變更一次 history；失敗、取消與 no-op 零正式變更。保存只包含已確認的一般角材定義與合法來源，工作階段剪貼資料、重複配方及未提交候選不進 .gcanvas；fresh profile 重開依原定義求值。

輸入框及中文組字中保留文字複製貼上與原快捷鍵；只有畫布焦點且沒有編輯輸入時才觸發幾何快捷鍵。不得攔截系統剪貼簿或拿 Enter 組字確認當幾何提交。
