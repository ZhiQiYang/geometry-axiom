## 要修的項目

- **B1｜`test_su/run_all.rb:35`:`@model.entities.empty?`**
  - 官方 API 文件的 `Sketchup::Entities` 沒有 `empty?`,Ruby 的 Enumerable 也沒有。照這樣寫,第一步就會丟 NoMethodError,接著被 rescue 接走寫出 exit_code=1,後面的 SketchUp 驗收一項都跑不到。
  - 改成 `@model.entities.length.zero?`。
  - 信心:依文件判斷,加上 Ruby 實測 Enumerable 沒有此方法;還沒在 SketchUp 實機確認。

- **M1｜`su/selection.rb:43、103、328`:座標沒有落到整數 mm,X 軸又可能取到短邊**
  - **重現 1**(以下模擬沿用 selection 的 `canonical_horizontal` / `snap_axes` / `TOL`,算法與 `flat()` 相同):12×8 m 的房間帶一個 30 mm 凹口,依序旋轉 3000 個角度,有 **867 個**被誤判成「非正交邊」而拒絕。同樣的房間不帶凹口時是 0 個。
    - 原因:X 軸取「最接近紅軸的邊」,平手時可能挑到很短的邊。短邊方向帶的 1e-6 mm 誤差,乘上 12 m 長邊,就超過 `TOL = 1e-4`。
  - **重現 2**:3664×3668 的房間旋轉 0.2° 後,包圍盒變成 3664.000001。
    - 多出一道挪過的縫(3623),面材從 8 片變 12 片,還多一條 39 mm 的窄條。
    - 400 個角度裡,有 73 個的結果跟沒旋轉的不同。
  - **修法方向**(依 D1「長度一律整數 mm」,不是新規則):
    1. X 軸改取外圈最長的那條邊。
    2. 投影之後,把座標四捨五入到整數 mm。
    3. 正交判定改用取整後的整數。
    4. 取整前的偏差如果超過 0.5 mm,照舊回報「非正交」。
  - **要有測試把關**:
    - 把上面兩個重現寫進 `test_selection_math.rb`:旋轉掃描要 0 誤拒,而且結果要和未旋轉時完全相同。
    - 加一個突變:拿掉取整,這兩個測試必須變紅,失敗訊息要指名 D1 整數 mm。
  - 模擬腳本在我這邊,摘要如上。

- **M2｜`su/selection.rb:138–168` 的障礙判定會誤報**
  1. 前一次產生的「下角材 平釘」群組,z 落在 2500～2539,會被當成樑。結果同一面換起鋪角重跑時,會被擋下並顯示「骨架碰到樑,降到 ≤ 2461」。
     → 修:排除本插件自己產生的群組(用屬性字典辨識)。
  2. 隱藏的實體、Tag 被關閉的實體,也被算成障礙。
     → 修:排除。
  3. 把四面牆或整棟建物包成一個群組時,它的包圍盒會蓋住整個房間。
