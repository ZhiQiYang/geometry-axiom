## 三、A 的完整行為與資料契約

### 1. 有限來源與目前設計的含義

第一版只接受同一目前專案及同一選定方案的普通 D7 已放置角材：

- live 表示來自同次原生讀取。
- 模型表示來自既有驗證成功的 ordinary-plan 紀錄之 `input.timbers`，每個 root 必須在保存來源 candidate 中存在、已放置，且 input／result 雙端核對成功。
- 全部納入表示都必須有完整 timber 與 placement 身分引用，對目前 World 為 `continuous`，而原生定義／有效值／來源內容一致。
- 缺少來源記號的舊模型、已刪除或重建來源、舊尺寸快照、assembly-owned、faces＋timbers、D36、未生成的 binding、任意 mesh，以及跨專案／跨方案都不能進本版集合。既有單一歷史快照料單仍照原契約使用；本流程不改寫、刪除或自動升級那筆模型。

「必須與現行來源一致」是本提案為**目前同一設計的表示歸併**加上的首版邊界；不是宣稱所有歷史快照都不能計量。當前模型版本仍由現有模型更新流程明示處理，本流程只讀。

### 2. 計量件與歸併

每個 `itemKey` 恰代表一件，沒有數量倍數。使用者可選多個表示作為其別名，並選其中一個作代表。代表只決定顯示與預設定位，不決定哪一份錯誤數值可以被忽略。

新列先各自列出；偵測到相同完整來源身分的多個表示時，整體維持需核對。使用者須明示歸併，或從本次範圍排除重複表示，才能 COMPLETE。**同一來源物件不可留在兩個已確認 item 假造數量；另一實際配置須有獨立原生實例。**

合併必須同時滿足：

- `projectScope` 與專案／方案 context 相符；
- typed timber key 及 incarnation 相同；
- typed placement key 及 incarnation 相同；
- 原生定義與有效值兩軸一致，且 A／B／L、材料末端、方向、面、定位、精確支承與具型別來源內容一致。

內容比對可以讀被引用來源的內容，**不擴充 K3 對閉包節點的存在期判定**。同值但不同來源不能靜默通過；同內容但不同記號也不能合併。任一項失敗，列出各表示的原因，不准挑一個代表掩蓋另一個失敗。K3 的模型根與閉包邊界見 [geometry-core/identity-trace/PROPOSAL.md:381–390](https://github.com/ZhiQiYang/geometry-axiom/blob/405f8c5e1a637a16cbe47470faf5ae1fa02b8676/geometry-core/identity-trace/PROPOSAL.md#L381-L390)。

### 3. 保存形狀

### 6. /2 的 bridge 與核對資料流（新增提案，不冒稱現有 API）

宿主先固定完整專案 context／revision／附件版本，從每個保存 model record 的同一 owner 取得 immutable bytes；模型仍走既有真 producer 驗證與 source-inspect 讀取。現行 World 只讀一次 references＋同修訂 source-inspect。這裡不能把去身分 candidate 的新記號當成保存來源記號：model 的根記號只取既有 sourceIdentity，內容由該模型原生 candidate 取得，再按 K3 核對 live。

供 /2 純求值器的 `VerifiedTakeoffInput/1` 須包含每個表示的 typed root、placement、同次讀取來源指紋、完整性、雙內容指紋、原生 A/B/L／材料 terminal／框架與實際端部來源（具型別 kind/id/face-selector，普通 full RC 也明列）。未提供端部來源不能用端點座標推測；先補唯讀 serializer，無完整證據回 incomplete，不讓舊 bridge 的「支撐身分未提供」靜默變成通過。新增欄位不得影響原定義內容雜湊，舊料單輸出以明確 serializer 保留。

宿主依所有 pins 及 immutable records 建立本次唯讀核對收據；只在本次 generation 有效，不存專案。不給 UI 接受 `verified:true` 的公用旁路。歸併編輯保存前驗整份附件；裁切與匯出重新取得上述資料，依 itemKey 形成唯一需求。UI 只送明選表示、item 歸併與代表，不送宣稱可信的長度、材料或身分。兩次讀取夾住 project／model／native pins，任一改動即拒，不使用部分先到的資料生成 CSV。
