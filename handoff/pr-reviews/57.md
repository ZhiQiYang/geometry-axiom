1. **板材來源的主格邊界是相鄰縫中心線。**D29 已定 REPEAT_PANEL 的 pitch＝panel＋gap、phase＝anchor＋panel＋floor(gap／2)，c(k)＝phase＋k×pitch。故若允許細分這種來源，D19 同一等分公式作用在縫中心線之間的完整主格，不能把 panel 本體當分母，也不能把 anchor 自動當 cell(0,0) 的左下角。這個幾何推論不等於現行 D19a 已經允許這個來源種類。

## 4. A 的定義、資料與求值契約

### 4.1 唯一幾何公式

來源兩軸必須存在、為新無限排法、沒有 D10b stagger。每軸允許 REPEAT 或 REPEAT_PANEL，分別取 native 的 step 或 panel＋gap 作完整 pitch。規則 divisions 各為 1…65，至少一軸大於 1，兩軸均要求 pitch % divisions＝0。n＝1 不產生該軸內線。

對已由 D29／D30 求出的父 cell C，沿用 D19：內線為 lo＋k×((hi−lo)／n)，k＝1…n−1，innerIndex＝k−1。只生成內線，不重複父邊；主 cell、頂點 key 及錨點不改成子 cell。所有座標和裁切由既有 K/W evaluator 求值，UI 只轉換畫面座標。

不增加新幾何欄位或 rule 型別。正式 rule DTO 保持 ruleKey／name／selector／divisions；selector 僅 all-cells 或單一 signed cell。ruleKey、nextRuleKey、耗盡、取消不配號、完整復原等，逐字沿用原契約。JSON 的 signed cell 仍是十進位字串，不過 JavaScript Number；父 cell 的 i＋1／j＋1 及實際輸出須能精確求值，溢位或 D1 超限明報。

### 4.2 範圍、引用與完整候選

既有同來源規則重疊、來源規則與手動子格的雙向衝突、正式引用鎖完全保留。已有 guide／角材使用時，不得改 divisions、selector 或刪除，即使內線序號仍存在；改名不換 key。上游 panel／gap／anchor／逐欄參數／整卡內容改動，仍須重驗該來源所有配置、套用、手動子格、全部有限引用與材料依賴。

來源 REPEAT ↔ REPEAT_PANEL 的明示切換可在 A 下保留既有 rules／highwater，但必須保留正式來源種類差異，並通過同一完整候選；不得讓 legacy 軸重宣告隱含清除 rules 或拆除 CardReference。若任何一個配置或引用失效，整筆拒絕，不替使用者改等分數、移動引用、刪掉規則或只保留成功的面。

查詢對 C∩F 裁切並扣孔，來源可零可見段；D19 手動子格的正面積前提不變。既有容量保持每來源 32 規則、每次最多 1024 cells／4096 segments；exact 過限拒絕並回所需數量，sample 取完整 cell，不抽掉同 cell 的內線，也不把抽樣索引重編為連續序號。單一 cell 自身超過 segment 預算仍拒絕。來源規則不逐格占 World 主／手動網格容量。

### 7.1 明示 /2，/1 舊義不改

`grid-subdivision-rules/2` 是本提案新增能力，完整包含 /1 的一層語意與本則無 stagger REPEAT_PANEL 擴充。新執行器支援清單同時列 /1、/2；不能只更新清單而讓任一核心、查詢、重放或 UI 路徑仍拒絕 A。

必需能力採以下精確規則：
