## 為什麼有這份檔
2026-10-21 交接給 Codex 的 NEXT.md、HANDOFF.md 沒有列入任何下面的功能，從那天起沒有人負責它們。另外，10-09 決策 K 的 8 項裡有 7 項只寫了條文，回報時卻被當成「已採納、已落地」。10-13 使用者明確沒有採納「先凍結新功能」,實際上功能卻停了，也沒人告訴使用者。

## 層級定義(回報一律寫層級，不寫「完成」)
| 層級 | 意思 | 要附的證據 |
|---|---|---|
| L0 | 已記下 | 使用者原話或決策出處 |
| L1 | 規格定案(條文或設計經使用者拍板) | 決策佇列條目或拍板留言 |
| L2 | 程式完成(有 PR) | PR 與 head SHA |
| L3 | 已進 main | merge SHA |
| L4 | **使用者在 App 裡用得到** | App 裡的操作路徑(點哪裡) |
| L5 | 使用者驗收過 | 使用者的確認 |

「做好了」只能用在 L4 以上。

## 規則
1. 每次交接(給 Codex、Grok、ChatGPT 或新 session)都要帶這份清單;接手者要把它排進自己的 NEXT。
2. 規格未經使用者拍板前不實作(`公理層.md` 是 SSOT)。設計交給 ChatGPT 出(見 #335 的流程)。
3. 使用者重複提出的需求，在「重複」欄加一，並移到同組最前。
4. 層級改變時，在本檔更新，並附上表格要求的證據。
5. 如果因為其他工作(例如驗收)暫停某項需求，要先告訴使用者並取得同意，不能默默停下。
